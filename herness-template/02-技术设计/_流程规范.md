# 研发流程

> 研发的完整工作流：技术方案设计 → coding → 单元测试 → 文档归档。

---

## 一、流程概览

```
迭代开始
  │
  ├─→ 1. 读取产品产物（需求分析、PRD、原型）
  ├─→ 2. 技术方案设计    → 02-技术设计/{端}/{类型}/
  ├─→ 3. Coding          → 源代码
  ├─→ 4. 单元测试        → 02-技术设计/{端}/单元测试/
  └─→ 5. 迭代文档归档    → 04-迭代管理/{周}/
```

---

## 二、研发 SOP

### 规则 0（硬门禁）：每次任务必读设计规范速查

> **在开始任何编码工作前，必须先读取 `05-共享上下文/设计规范速查.md`。**
>
> 该文件包含自动生成代码禁止手动编辑、API 设计规范、命名规范等强制性规则。不读 = 违规。

### 规则 1：coding 前必须完成技术方案设计

> 没有技术方案设计文档 = 不允许写代码。

技术方案设计必须包含：
- 数据库变更（如涉及）
- API 设计（接口路径、参数、返回值）
- 涉及的文件清单（新增 + 改造）
- 关键逻辑流程图或伪代码

### 规则 2：coding 后必须进行单元测试并形成文档

> 没有单元测试文档 = 不允许提 PR。

单元测试文档格式见 `examples/单元测试-示例.md`。

---

## 三、输出：整体文档（持续积累）

### 3.1 技术设计文档

按技术端和类型组织：

```
02-技术设计/
├── _流程规范.md              ← 你在这里
├── _index.md
├── 后端/
│   ├── _index.md
│   ├── 架构设计.md
│   ├── 接口设计.md
│   ├── 数据库设计.md
│   ├── 接口设计/             ← 按功能模块的详细 API
│   ├── 数据库设计/           ← 按功能模块的 SQL/Model
│   ├── 技术方案/             ← 按功能模块的整体方案
│   └── 单元测试/             ← 按功能模块的单元测试文档
└── 前端/
    ├── _index.md
    ├── 页面设计/             ← 按功能模块的页面设计
    └── 单元测试/
```

### 3.2 技术方案文档结构

```markdown
# {功能名称}-技术方案

## 1. 文档信息
- 关联迭代、关联 PRD、作者、日期

## 2. 方案概述
- 背景、目标、涉及范围

## 3. 数据库变更（如涉及）
- 新增表 / 变更表的 DDL、Model 定义

## 4. API 设计
- 接口路径、Method、请求/响应结构、错误码定义

## 5. 业务逻辑
- 核心 Flow 流程图、关键逻辑说明（含边界条件）

## 6. 涉及文件清单
- 新增文件、修改文件（含修改点说明）

## 7. 依赖与风险
```

### 3.3 单元测试文档

存放位置：`02-技术设计/{端}/单元测试/`

格式参见 `examples/单元测试-示例.md`。

---

## 四、输出：迭代文档（每周归档）

每周结束时，在迭代管理目录中记录研发产物链接（不是文档本身）：

```markdown
# 技术设计产物（YYYY-WXX）

## 后端
| 产物 | 文档链接 | 状态 |
|------|---------|------|

## 前端
| 产物 | 文档链接 | 状态 |
|------|---------|------|
```

---

## 五、研发门禁检查清单

### 编码前
- [ ] 已读取 PRD 和需求分析文档
- [ ] 技术方案设计文档已完成（数据库 + API + 文件清单）

### 编码后
- [ ] 所有 service/logic/handler 方法有对应单元测试
- [ ] 单元测试文档已编写
- [ ] 技术方案与实际代码一致（如有偏差已同步更新）

### 迭代结束
- [ ] 技术方案已归档到 02-技术设计/
- [ ] 单元测试文档已归档
- [ ] 迭代管理目录中已记录产物链接
- [ ] 域 _index.md 已更新
