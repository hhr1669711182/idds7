# AI 工作 SOP（标准作业程序）

> **核心规则**：本文件是 AI 工作的第一入口。每次任务必须先读取本文件，按规范执行，并留痕。
> 本目录为通用模板，可将整个目录复制到任意项目使用；落地时按需补充项目具体的目录结构、技术栈与规则。

---

## 一、工作启动流程（每次必做）

### 第 1 步：加载规范

```
读取 00-SOP.md              ← 你在这里
读取 README.md              ← 项目当前状态
```

### 第 2 步：理解项目状态

按顺序读取，快速建立上下文：

```
1. 04-迭代管理/_index.md               → 迭代总览表，找到当前周
2. 04-迭代管理/{当前周}/产物计划.md      → 本周计划产出
3. 04-迭代管理/{当前周}/周产物汇总.md    → 本周已产出物
4. 05-共享上下文/当前状态摘要.md         → 阻塞项、决策记录
5. 按需深入各域文档                      → 获取详细设计
```

### 第 3 步：判断任务阶段

| 任务类型 | 走哪个流程 | 关键产出 |
|---------|-----------|---------|
| 产品需求 | [01-产品设计/_流程规范.md](01-产品设计/_流程规范.md) | 需求分析、原型、PRD |
| 技术开发 | [02-技术设计/_流程规范.md](02-技术设计/_流程规范.md) | 技术方案、代码、单元测试 |
| 测试 | [03-测试/_流程规范.md](03-测试/_流程规范.md) | 测试策略、用例、报告 |
| PR 审查 | [06-PR审查/_流程规范.md](06-PR审查/_流程规范.md) | 审查意见、问题闭环 |

### 第 4 步：执行 & 留痕

按对应流程文档执行，完成后在下方 **[工作日志](#八工作日志)** 中追加记录。

## 二、核心行为规则

1. **先读后做**：禁止不读 SOP 直接开始写代码
2. **先设计后编码**：任何 coding 任务前，必须先完成技术方案设计文档。没有设计文档 = 不允许写代码
3. **编码后必须单元测试**：coding 完成后，必须编写单元测试并形成测试文档
4. **先查后写**：创建新文档前，先检查本目录下是否已有相关文档，优先更新已有文档
5. **引用源码**：编写技术文档时，必须引用实际代码路径和行号，禁止凭空想象
6. **保持同步**：实现过程中任何设计偏差，必须同步更新技术方案文档。文档与代码必须一致
7. **迭代闭环**：迭代结束时，产物必须从迭代管理目录流转到各域目录，不能只留在迭代文件夹中
8. **PR 必须审查**：每次 PR 提交必须在 PR 说明中追加 AI 审查请求，审查问题不修复的必须评论说明原因

## 三、文档的"双轨制"

项目文档分为两类，分别管理：

| 类型 | 含义 | 存放位置 | 示例 |
|------|------|---------|------|
| **整体文档** | 持续积累，按模块组织 | `01~03,05/` | 架构设计、接口设计、测试策略 |
| **迭代文档** | 每周产出，按周管理 | `04-迭代管理/{YYYY-WXX}/` | 产物计划、产物汇总 |

**流转规则**：

```
每周开始：在迭代文件夹中填写产物计划
  ↓
每周执行：产物写入对应域目录（01~03）
  ↓
每周结束：迭代文件夹中记录产物链接（非文档本身）
  ↓
归档：迭代文件夹移入 _archive/
```

## 四、迭代产物写入规范（迭代结束时执行）

### 规则

每个迭代结束时，必须将本次迭代的产物**写入对应的域文档**，而不是只留在迭代管理目录中。

### 写入目标

| 产物类型 | 写入位置 | 写入方式 |
|---------|---------|---------|
| 新增 PRD、原型、业务流程（未上线） | `01-产品设计/开发中/` | 创建或更新文档，在 `_index.md` 需求列表中追加条目 |
| PRD 上线归档 | `01-产品设计/已归档/` 对应业务模块子目录 | 从 `开发中/` 移入 `已归档/`，更新 `_index.md` 状态 |
| 新增技术设计（前端） | `02-技术设计/前端/` 对应子目录 | 创建或更新文档，在 `_index.md` 中追加引用 |
| 新增技术设计（后端） | `02-技术设计/后端/` 对应子目录 | 创建或更新文档，在 `_index.md` 中追加引用 |
| 新增测试用例/报告 | `03-测试/` 对应子目录 | 创建或更新文档，在 `_index.md` 中追加引用 |
| 关键决策 | `05-共享上下文/当前状态摘要.md` | 追加到"关键决策记录"表 |
| 新增术语 | `05-共享上下文/核心概念术语.md` | 追加术语定义 |
| 技术栈变更 | `05-共享上下文/技术栈速查.md` | 更新对应条目 |

| 状态 | 含义 |

## 六、质量门禁

每个阶段的产出必须满足对应门槛才能进入下一阶段：

```
产品设计 ──→ 研发 ──→ 测试 ──→ PR
   │           │         │         │
   ▼           ▼         ▼         ▼
 PRD完成    技术方案   测试用例   AI 审查
 需求评审   设计评审   执行通过   审查通过
```

| 阶段 | 门禁条件 |
|------|---------|
| 产品 → 研发 | PRD 已完成，需求分析文档已更新 |
| 研发 编码前 | 技术方案设计文档已完成 |
| 研发 编码后 | 单元测试已编写，测试文档已产出 |
| 研发 → 测试 | 技术方案 + 单元测试文档已归档 |
| 测试 → PR | 测试策略 + 用例 + 报告已完成并归档 |
| PR → 合入 | AI 审查通过，或未修复问题有评论说明 |
