# 产品设计流程

> 从需求到 PRD 的完整产出规范，分为迭代产物、全量文档两轨。产品文档只保留已归档、开发中两种状态。

---

## 一、流程概览

```
需求输入
  │
  ├─→ 需求调研                → 01-产品设计/开发中/
  ├─→ 需求分析（迭代产物）     → 04-迭代管理/{周}/产品设计产物.md（链接）
  ├─→ 高保真原型（迭代产物）   → 原型工具链接
  ├─→ PRD（未上线）           → 01-产品设计/开发中/
  └─→ PRD（已上线）           → 01-产品设计/已归档/
```

---

## 二、迭代产物（每周产出）

### 2.1 需求分析文档

**产出时机**：迭代开始时，在设计稿/开发前完成。

**文档结构**：

```markdown
# {功能名称}-需求分析

## 1. 背景与目标
- 业务背景、要解决的问题、目标用户

## 2. 功能范围
- 本期包含 / 本期不包含（明确边界）

## 3. 用户场景
- 场景1：...  /  场景2：...

## 4. 功能说明
- 功能点1  /  功能点2

## 5. 验收标准
- [ ] 标准1

## 6. 依赖与风险
```

**存放规则**：
- 编写位置：`01-产品设计/需求分析/`
- 迭代清单中记录链接

### 2.2 高保真原型

**产出时机**：与需求分析同步或紧随其后。

**要求**：必须覆盖所有交互状态（正常、空数据、错误、加载中）。

### 2.3 PRD（产品需求文档）

**产出时机**：需求分析 + 原型确认后。

**文档结构**：参见 `01-产品设计/需求文档模板.md`。

## 三、全量产品文档（持续积累）

### 3.1 两态管理

产品文档只保留两种状态：

| 状态 | 含义 | 目录 |
|------|------|------|
| **已归档** | 已上线的全量产品文档，上线后下达归档指令 | `01-产品设计/已归档/` |
| **开发中** | 未上线的产品文档（含待评审、进行中、调研） | `01-产品设计/开发中/` |

```
01-产品设计/
├── _index.md              ← 需求列表总索引
├── _流程规范.md            ← 你在这里
├── 需求文档模板.md
├── 已归档/                 ← 已上线 PRD（按业务模块归档）
│   ├── 模块A/
│   ├── 模块B/
│   └── ...
└── 开发中/                 ← 未上线 PRD（含待评审、进行中、调研）
```

产品上线后下达归档指令，将 PRD 从 `开发中/` 移入 `已归档/` 对应业务模块子目录，更新 `_index.md` 需求列表。

### 3.2 _index.md 需求列表格式

```markdown
| 需求名称 | 模块 | 状态 | 关联迭代 | PRD 链接 |
|---------|------|------|---------|---------|
| {需求名} | {模块} | 已完成 | {YYYY-WXX} | [PRD](已归档/{模块}/{需求名}PRD.md) |
```
