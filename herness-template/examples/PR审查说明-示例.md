# PR 审查说明 — 示例

> 本文档是 PR 提交说明的示例，演示如何在 PR 描述中附加 AI 审查请求。

---

## PR 提交说明示例

```markdown
## 变更概述

实现 {功能}：{一句话描述}，新增 {table} 表和相关 API，改造 {模块} 流程。

## 关联

- 关联迭代：{YYYY-WXX}
- 关联技术方案：[{功能}-技术方案.md](../02-技术设计/后端/技术方案/{功能}-技术方案.md)
- 关联需求：[{功能}PRD.md](../01-产品设计/开发中/{功能}PRD.md)

## 变更文件

### 新增
- `{路径}/model/{name}.go` — {说明}
- `{路径}/handler/{name}.go` — {说明}
- `{路径}/logic/{name}.go` — {说明}
- `{路径}/logic/{name}_test.go` — {N} 个单元测试

### 修改
- `{路径}/handler/{name}.go` — {修改说明}
- `{路径}/logic/{name}.go` — {修改说明}

## 测试情况

- 单元测试：已编写，{N} 个用例覆盖 {方法清单}
- 测试文档：[单元测试文档](单元测试-示例.md)

## AI 审查

@AI 检查本次PR，重点关注：
1. {并发风险点}
2. {失败是否影响主流程}
3. {是否有 N+1 查询问题}
```

---

## AI 审查回复示例

### 审查问题及处理

**问题 1：并发风险**
```
> AI: {Method} 中使用两步操作，并发场景下可能出现 {风险}。
> 建议使用行锁。

已修复：commit {hash} 中改为先锁定，再操作。
```

**问题 2：错误处理**
```
> AI: {method}() 的错误未处理，如果 {依赖} 不可用会导致请求失败。

不修复原因：当前设计预见到 {依赖} 不可用场景，内部已做容错 + 异步处理，
调用方不需要关心结果。详见 {文件}:{行号}。
```

**问题 3：N+1 查询**
```
> AI: 循环查询存在 N+1 问题。

已修复：改为批量查询，一次 SQL 取回所有数据。
```

---

## 问题闭环确认

| 问题 | 严重度 | 处理 | 状态 |
|------|--------|------|------|
| {并发风险} | 严重 | 加锁 | ✅ 已修复 |
| {错误处理} | 轻微 | 已有容错，不修复 | ✅ 已评论说明 |
| {N+1 查询} | 中等 | 批量查询 | ✅ 已修复 |
