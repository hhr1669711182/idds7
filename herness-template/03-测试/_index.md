## 测试用例组织

按功能模块组织，与产品需求和迭代关联：

```
测试用例/
├── 编写规范.md           # 测试用例编写规范（必读）
├── {模块名}-测试用例.md   # 各模块测试用例
└── ...
```

> **编写测试用例前，必须先阅读 [测试用例/编写规范.md](测试用例/编写规范.md)。**

## 测试分层

| 层级 | 说明 | 范围 |
|------|------|------|
| 单元测试 | 后端: {测试命令} / 前端: {测试框架} | 函数、组件 |
| 接口测试 | API 端到端测试 | 接口联调 |
| 功能测试 | 浏览器手工测试 | 页面交互、业务流程 |
| 集成测试 | 跨模块联动验证 | 上下游模块 |
| 回归测试 | 已有功能不受影响 | 全量回归 |

## 设计规范

- 每个功能模块对应一份测试策略 + 一份测试用例
- 测试策略关联对应的产品设计文档
- 测试用例覆盖正常流程 + 边界条件 + 异常场景
- 用例优先级标注：P0（核心流程）、P1（重要分支/边界）、P2（低频场景）
- 文档结构参见 `examples/`
