# 测试流程

> 测试的三层工作流：整体测试策略 → 迭代测试策略 → 测试用例 → 执行报告。

---

## 一、流程概览

```
迭代开始
  │
  ├─→ 1. 确认/更新整体测试策略     → 03-测试/整体测试策略.md
  ├─→ 2. 编写迭代测试策略          → 04-迭代管理/{周}/测试产物.md
  ├─→ 3. 编写测试用例              → 03-测试/测试用例/
  └─→ 4. 执行 + 迭代测试报告       → 03-测试/测试报告/
```

---

## 二、测试 SOP

### 规则 1：先策略后用例

> 先编写迭代测试策略和整体迭代策略，再编写具体测试用例。

策略回答"测什么、怎么测、多深"；用例回答"具体怎么操作、期望什么结果"。

### 规则 2：迭代报告留档并超链测试用例

> 每次迭代的测试报告必须留存，报告中引用具体的测试用例文档链接。

---

## 三、输出：整体文档（持续积累）

### 3.1 整体测试策略文档

**存放位置**：`03-测试/整体测试策略.md`

**内容要求**：
- 测试范围（哪些模块需要测试）
- 测试层级（单元测试 / 集成测试 / 端到端测试 的分工）
- 测试环境说明
- 覆盖率目标
- 自动化测试策略

### 3.2 按功能模块组织的测试用例

**存放位置**：`03-测试/测试用例/{模块名}-测试用例.md`

**编写前必读**：[测试用例编写规范](../测试用例/编写规范.md) — 定义标准格式、命名规范、优先级体系和质量要求。

文档结构参见 `examples/测试用例-示例.md`。

### 3.3 迭代测试报告

**存放位置**：`03-测试/测试报告/{YYYY-WXX}-测试报告.md`

**内容要求**：
- 测试摘要（用例数、通过/失败/阻塞数）
- 缺陷统计
- 风险评估
- 结论（是否建议发布）

---

## 四、输出：迭代文档（每周归档）

每周在迭代管理目录中记录测试产物链接：

```markdown
# 测试产物（YYYY-WXX）

## 测试策略
- [迭代测试策略-YYYY-WXX](../03-测试/测试报告/YYYY-WXX-测试报告.md)

## 测试用例
| 模块 | 用例文档 | 用例数 |
|------|---------|--------|

## 测试报告
- [YYYY-WXX-测试报告](../03-测试/测试报告/YYYY-WXX-测试报告.md)
```

---

## 五、测试门禁检查清单

- [ ] 整体测试策略已确认/更新
- [ ] 迭代测试策略已编写
- [ ] 测试用例已按模块编写完成
- [ ] 测试用例覆盖正常流程 + 边界条件 + 异常场景
- [ ] 测试已执行完毕
- [ ] 迭代测试报告已产出
- [ ] 报告中超链接了具体测试用例文档
- [ ] 迭代管理目录中已记录产物链接
