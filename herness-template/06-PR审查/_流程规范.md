# PR 代码审查流程

> 每次 PR 必须通过 AI 代码审查，问题闭环管理。

---

## 一、流程概览

```
开发者提交 PR
  │
  ├─→ 1. 在 PR 提交说明中追加：@AI 检查本次PR
  ├─→ 2. AI 自动审查代码
  ├─→ 3. 审查结果处理：
  │      ├─ 无问题 → 合入
  │      └─ 有问题 → 修复 OR 评论说明不修复原因
  └─→ 4. 问题闭环后合入
```

---

## 二、PR 提交规范

### 2.1 PR 描述模板

每次提交 PR 时，PR 描述中必须包含以下内容：

```markdown
## 变更概述
<简要描述本次变更内容和目的>

## 关联
- 关联迭代：YYYY-WXX
- 关联技术方案：<技术方案文档路径>
- 关联需求：<PRD 文档路径>

## 变更文件
- 新增：<文件列表>
- 修改：<文件列表>

## 测试情况
- 单元测试：<已编写/不适用>
- 测试文档：<单元测试文档路径>

## AI 审查
@AI 检查本次PR
```

### 2.2 审查请求格式

标准格式：`@AI 检查本次PR`

可附加审查重点：

```
@AI 检查本次PR，重点关注：
- API 错误处理是否完善
- 数据库查询是否有 N+1 问题
- 是否有安全漏洞（注入、越权）
```

---

## 三、AI 审查内容

| 维度 | 检查项 |
|------|--------|
| **正确性** | 逻辑是否正确，边界条件是否处理 |
| **安全性** | SQL 注入、XSS、权限校验、敏感信息泄露 |
| **性能** | N+1 查询、不必要的数据加载、缓存策略 |
| **代码规范** | 命名、错误处理、日志规范 |
| **设计一致性** | 实现与技术方案设计文档是否一致 |
| **测试覆盖** | 单元测试是否覆盖关键路径 |

---

## 四、问题处理

### 4.1 必须修复的问题

以下类型问题**必须修复**，不得以评论代替：
- 安全漏洞（注入、越权、敏感信息泄露）
- 数据一致性问题（缺少事务、并发冲突）
- 可能导致服务崩溃的 nil/空指针

### 4.2 可选择说明不修复的问题

以下类型问题**可以选择不修复**，但必须评论说明原因：
- 性能优化建议（当前数据量不构成瓶颈）
- 代码风格偏好（与现有代码风格保持一致）
- 重构建议（不在本期需求范围）

### 4.3 评论格式

```markdown
> AI 审查问题：XXX

不修复原因：<简要说明>
```

---

## 五、PR 审查检查清单

### 提交人
- [ ] PR 描述中包含变更概述、关联迭代、技术方案链接
- [ ] 已追加 `@AI 检查本次PR`
- [ ] 审查问题已全部处理（修复 or 评论说明）

### 审查人（AI）
- [ ] 已检查正确性、安全性、性能、规范、设计一致性、测试覆盖
- [ ] 问题已分类（必须修复 / 可选修复）
