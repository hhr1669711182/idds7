## 三、全流程业务测试（人工）

> 测试环境 **mock 已关闭**，全流程由**坐席系统 / 测试平台的真实消息**驱动（WS 网关 `message-client`）。本地场景编排引擎（`server/test-runner`，8 个场景）是开发侧工具，测试环境不可用——下表「观察点」列仍可直接对照检查地图表现。

### 3.1 标准全生命周期（对应开发侧 `fullCycle` 场景）

| 步 | 驱动动作（坐席/测试平台） | 地图侧应看到 |
|----|--------------------------|-------------|
| 1 | 来电接听（`received`） | 地图切到问询态 |
| 2 | 来电定位（`position`，带经纬度） | 定位上图（标记 + 视口适配到该点） |
| 3 | 地址画像（`address`） | 切到调派态，画像信息上屏 |
| 4 | 模拟派车（单消防站，1 辆出动车） | 消防站路线上图，调派路线预览面板出现，车辆沿路线行驶 |
| 5 | 车辆 GPS 轨迹（逐点推送） | 车辆逐点移动，跟踪态 |
| 6 | 警情状态流转（立案→调派→出动→到场） | 状态文案随消息变化 |
| 7 | 终态 `ARRIVED` | 历史轨迹面板自动打开（时间轴 / 倍速 / 统计 / 路线切换） |
| 8 | 归队 + 结案 + 来电结束 | 地图回归值守态，可接收下一通来电 |

### 3.2 专项场景（按需挑测）

| 场景 | 驱动 | 观察点 |
|------|------|--------|
| 洪涝（特灾轴） | 定位/警情/轨迹消息叠加特灾模式 | 围栏与图层按洪涝模式展示，门禁与调派态一致 |
| 值守 | 定位 + 画像 + 来电 | 值守态数据上屏，无调派误触发 |
| 弹窗态 | 轻量三消息（来电/定位/画像） | 弹窗信息正确，无多余图层 |
| 多标签联动 | 同源开两个标签页 | BroadcastChannel（`ids-map-screen-relay`）互相同步 / 选点接力正常，关闭一页后另一页不崩 |

### 3.3 门禁行为（重要，易误报缺陷）

- 地图有**阶段门禁**：消息到达时若所处阶段与消息不匹配（如调派态收到旧来电），消息会被**门禁丢弃**，地图无变化属**正确行为**，不是缺陷。
- 判断方法：对照驱动动作发生顺序（3.1 的 1→8 顺序）；乱序 / 跳跃推送导致的「没上图」不算缺陷，但应在缺陷单里注明「非门禁丢弃」。

## 四、手工测试要点

### 4.1 必测异常场景（对照兜底行为）

| 场景 | 怎么做 | 应看到 |
|------|--------|--------|
| 接口失败（500 / 业务 code 非 0） | 测试环境后端异常或弱网模拟 | `ElMessage.error` 提示（静默标记的接口不弹），不白屏 |
| 围栏 / 画像数据缺失 | 推送无围栏数据的区划 | `ElMessage.warning` 提示，面板正常可用 |
| WS 断线重连 | 断网 30s 后恢复 | 前端自动重连恢复，期间积压消息处理正常，无白屏 |
| 非白名单 origin 的 postMessage | 控制台手工 `postMessage` 伪造来源 | 直接忽略，无副作用 |
| 切走再回来 | 触发消息后切其他 tab / 路由再回 `#/map` | 状态正确恢复，过期旧消息不再上图 |

### 4.2 权限与状态机（当前无自动化，靠人工）

- **权限矩阵**：对照 `docs/source/04-角色与权限矩阵.md` 逐项操作，无权限操作应被拦截。
- **警情状态机**：对照 `docs/source/08-业务状态机定义.md`。7 态顺序：
  `CREATED → FORMAL_DISPATCHED → DISPATCHED → ARRIVED → OPERATION_COMPLETED → RETURNING → RETURNED`
  重点测**非法跳转**（如 CREATED 直接到 RETURNED）应被拒。

### 4.3 地图视觉（自动化不覆盖）

- 瓦片加载、图层叠加顺序、文字标注清晰度、主题切换后配色 —— 人工目视。
- 视觉改动验收需附截图：**浅色 + 深色两套主题都要看**。

## 五、缺陷提报规范

报缺陷时请包含（GIS 项目特有条目，少一条就打回补）：

1. **环境**：test 测试环境 + 浏览器 / 版本（注明「test 环境，数据中心北京」）
2. **复现步骤**：驱动消息的事件键序列（或坐席操作序列）+ 页面操作
3. **涉及消息时**：写明**事件键**（`docs/source/07-协议事件清单.md` 中的键名）与通道（WS / postMessage / BC）
4. **涉及坐标时**：写明**坐标系**（WGS84 / GCJ-02 / BD09）与坐标顺序（`[lng, lat]`）；坐标偏移 > 100m 直接标严重
5. **门禁类现象**：按 §3.3 先排除门禁丢弃，注明「非门禁丢弃」再报
6. **截图 / 录屏**：视觉与动画类缺陷必附

缺陷级别参考：
- **严重**：坐标偏移 > 100m（638m 事故红线）、消息门禁整体失效、应用起不来、主流程（3.1 全生命周期）走不通
- **一般**：单场景异常、面板显隐错误、提示文案缺失、断线重连异常
- **轻微**：视觉细节、控制台噪音、图标样式

## 六、常见问题

| 现象 | 处理 |
|------|------|
| 车辆 / 围栏位置与预期不符 | 先对数据中心：test 环境 = **北京**，数据按北京适配属正常 |
| 消息推送了但地图没反应 | ① 检查页面是否处于匹配阶段（§3.3 门禁）；② 检查 WS 是否连上（`ws://ids-test.ks.telewave.tech/message-client/ws`）；③ 再按 §五 报缺陷 |
| 图标不显示 | 在线图标模式依赖外网，断网 / 代理限制属环境问题 |
| 多标签页状态不同步 | 确认两标签同源同通道（`ids-map-screen-relay`）；异源 / 异通道不同步属预期 |
| 需要跑自动化（单测 / E2E） | 自动化由开发在代码仓库执行（`pnpm test` / `pnpm e2e`），测试组无需搭建环境；用例全貌见 `herness/03-测试/测试策略.md` |
