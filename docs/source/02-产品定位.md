## 1. 核心价值

| 价值点 | 说明 |
| --- | --- |
| **五层架构（Service→Protocol→Calc→Ctrl→Render）** | 严格分层、职责清晰、跨团队协同，IP 闭源保护与积木式复用并重 |
| **业务控制层 DTO 拼装** | 业务事件 → 通用控制层 DTO；业务规则与图形指令解耦 |
| **WGS84 强约束** | 协议层与控制层 WGS84 强一致，进入渲染层前由底座插件负责转换，避免多坐标系漂移 |
| **高频数据 Worker 化** | GPS ≥2fps、轨迹批处理、抽稀全部走 Web Worker + Transferable Objects，主线程稳态 ≥30fps |
| **5 个核心场景端到端 AC** | 值守/来电/问询/调派/跟踪五个核心场景的端到端 AC 是验收硬基线 |
| **3 个业务状态机** | 警情/车辆/调派方案三个状态机由业务控制层持有，业务流转可见可控 |
| **业务 ID 前缀隔离** | 临时图元按业务前缀（`call_`/`incident_`/`vehicle_`/`route_`）精准回收，跨场景不冲突 |
| **Auto-Fit 10%~15% Padding** | 视野切换自动保留 12% 留边，弹屏/围栏/路径一致体验 |
| **统一语言词典** | v1.0 起严格版本管理，跨产品线同构 |
| **协议层 DTO Schema** | 与 `src/controller/core/protocol/*.ts` 100% 一致，CI 强制校验 |

| 评审维度 | 量化指标 | 关键验收点 | 评判条 |
| --- | --- | --- | --- |
| 架构合规 | 严禁事项清单无违反 | 五层架构 / 坐标系 / 业务 ID 前缀 / Auto-Fit | ① 严禁事项清单 10 条全部通过 ② 业务控制层与通用控制层 DTO 严格分离 ③ 业务 ID 前缀全部对齐 ④ Auto-Fit Padding ≥ 0.10 |
| 场景 AC | 5 个核心场景 AC 全部通过 | 值守/来电/问询/调派/跟踪 | ① 端到端时延满足 SLA ② 视野 fit / 弹屏 / 围栏 / 路径结果正确 ③ 状态机转移符合预期 |
| 性能 SLA | 全部指标达标 | ≥30fps / ≤500ms / ≤1s / ≤2s / ≤200ms 等 | ① 关键计算函数有 vitest bench ② 端到端性能用 Playwright + Headless Chrome 验证 ③ 性能报告归档 |
| 测试覆盖 | 覆盖率 ≥ 80% | composable / store / controller / 纯函数 | ① 单元测试覆盖率 ≥ 80% ② 缺陷修复有失败测试 + 回归 ③ 状态机合法/非法转移全部有测试 |
| 文档完整 | 14 份 docs/source 全部通过评审 | 单一真相源、版本管理 | ① 协议层 DTO Schema 与代码 100% 一致 ② 统一语言词典 v1.0 覆盖全部术语 ③ 与 ids-command-center-client 同构对齐 |

## 3. 模块输入输出

### 3.1 输入

| 方向 | 来源 / 去向 | 数据描述 |
| --- | --- | --- |
| 输入 | 业务微服务（接处警/调度） → 本模块 | 警情、来电、调派、跟踪等业务事件（WebSocket） |
| 输入 | GPS 网关（车辆/单兵） → 本模块 | 车辆 GPS 高频更新（≥2fps） |
| 输入 | 主前端 Host → 本模块 | 页面跳转、警情定位、图元联动指令（postMessage） |
| 输入 | 排班系统 → 本模块 | 当值名单生效/失效事件（联动到警情状态） |
| 输入 | 配置中心 → 本模块 | 围栏配置、资源图层 ID、ETA_MAX、Padding 比例 |
| 输入 | 用户操作 → 本模块 | 缩放、平移、要素拾取、模式切换、确认/取消 |

### 3.2 输出

| 方向 | 来源 / 去向 | 数据描述 |
| --- | --- | --- |
| 输出 | 本模块 → 渲染层（OpenLayers/ThreeJS） | 图形指令（视野/几何/路径/动画） |
| 输出 | 本模块 → 主前端 Host | 视野状态、要素拾取、用户操作事件（postMessage） |
| 输出 | 本模块 → 班长席监控大屏 | 5 个核心场景实时快照、临时图元状态、性能采样 |
| 输出 | 本模块 → 运维系统 | 异常告警（GPS 失联、Worker 崩溃、WebSocket 断连） |

## 4. 模块职责

- **协议层**：`MessageEnvelope<T>` 解析与派发；业务/通用/IO 协议契约管理。
- **计算层**：空间计算（Turf）、坐标系转换、路径算路、轨迹抽稀；高频数据走 Worker。
- **业务控制层**：6 个 Controller（Alarm/Call/Config/Dispatch/Duty/Tracking）维护 3 个业务状态机，拼装通用控制层 DTO。
- **通用控制层**：4 个 Controller（Geometry/Kinematic/Spatial/View）执行图形指令，幂等操作。
- **IO 控制层**：2 个 Controller（Input/Output）桥接视图事件与外部系统。
- **渲染层**：OpenLayers / ThreeJS / amap 三大底座，资源图层 ID 严格命名。
- **基线维护**：WGS84 强约束、Auto-Fit 10-15% Padding、业务 ID 前缀、坐标系转换、5 个核心场景 AC、3 个业务状态机。

## 5. 本模块不做什么

- **不负责后端业务实现**（警情受理、派警、调度属于后端模块）。
- **不负责硬件维修与工单处置**（属于运维系统，本模块只推送故障）。
- **不负责排班表编辑与发布**（属于排班系统，本模块只读生效名单）。
- **不负责接警员完整档案**（属于资源调度模块，本模块只缓存最小画像）。
- **不负责 KPI 报表与统计归档**（属于归档统计系统）。
- **不负责权限决策**（属于权限管理模块，本模块只消费授权结果）。
- **不维护跨中心调配**（接警员只能登录其归属指挥中心的席位）。
- **不直接调用 OL/ThreeJS API**（业务控制层禁止，控制层切分是硬约束）。
- **不在渲染层进行空间计算**（除动画帧内简单插值）。
- **不绕过 store 直接修改图元**（必须通过 controller）。

#### 断言清单

1、GIS 前端的核心价值是"业务事件 → 地图呈现"的端到端链路质量与分层架构合规，不是单纯的地图展示组件。

2、五层架构基线是产品级硬约束；任何实现不得跨层调用、绕开 store 渲染、计算层持有 DOM/Map 引用。

3、模块必须实现 3 个业务状态机（警情/车辆/调派方案）并由业务控制层持有，业务流转可见可控。

4、5 个核心场景（值守/来电/问询/调派/跟踪）的 AC 是产品级硬基线；任何一档不达标禁止宣称完成。

5、所有临时图元按业务前缀隔离与回收；场景切换时通过 store `reset()` 重置临时状态。

6、协议层 DTO Schema（`docs/source/协议层DTO Schema.tsd`）必须与 `src/controller/core/protocol/*.ts` 100% 一致，CI 强制校验。

7、统一语言词典 v1.0 是术语唯一真相源；任何新增/调整必须发起评审。

8、本模块与主前端 Host 协作但职责清晰：Host 管 UI 与业务表单，GIS 管地图与五层架构。
