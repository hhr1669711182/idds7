## 0. 当前实际 Transport 与业务接线

本节描述当前源码。后文第 1～7 节保留历史业务概念模型，其中的事件名、ID 前缀、性能目标与 DTO 示例不等于已实现的 transport 契约。文档同步不改变事件键，也不表示 review 边界修复、自动化最终核验或人工验收完成。

### 0.1 实际信封与通道

```typescript
// src/types/message.ts；MessageEventKey/MessageSystem/MessageChannel 来自 const.message.type.ts
type MessageEnvelope<T> = {
  id: string;
  timestamp: number;
  channel: MessageChannel;
  system: MessageSystem;
  eventKey: MessageEventKey;
  data: T;
  targetSystem?: MessageSystem;
  meta?: MessageMetadata;
  v?: '1.0.0';
  isRemoveSameElement?: boolean;
};
```

实际是 `id/timestamp/eventKey/data/v`，不是历史的 `eventId/occurredAt/payload/version`。v 在类型中可选；store 的标准 Envelope 快路要求其值为 `'1.0.0'` 且有 eventKey/system/channel。接收入口使用传入的 channel/system；公共 ingest 保留历史 raw.eventKey/type 回退，WS 回调关闭该最后回退，不能把公共 ingest 的兼容范围视为 WS 支持范围。

| MESSAGE_CHANNEL | 值 | 当前接入 |
| --- | --- | --- |
| WS | `ws` | `register/initMessage.ts` → store.connectWebSocket → ingest |
| POST_MESSAGE | `postMessage` | store.bindParent，按 origin 白名单接收 |
| BROADCAST_CHANNEL | `broadcastChannel` | store.bindBroadcastChannel；选点/relay composables 归一后 ingest |
| LOCAL_STORAGE | `localStorage` | useUserStore 统一接收共享态；F10 mock bridge 将业务差异构造成信封后 ingest |
| HTTP | `http` | F13 profile sync 将 HTTP 补水构造成相同内部事件后 ingest；publish 返回 false |

LOCAL_STORAGE 是已存在的入站通道标识，不表示总线会扫描全部 localStorage。共享态由 `initUserStore` 初始读取与监听，再由 bridge 处理；HTTP 也不是新增的总线发请求 API。

当前 MESSAGE_SYSTEM：`host/map/three/dispatch/ids-seat-web`。`panel_25d/panel_3d` 不在当前常量中。

`MessageMetadata` 定义于 `src/types/message.ts`，含 `snapshotKind?: 'full' | 'delta'`、recordId/eventId/eventName/source、topics/notify、mock/initial、共享态 revision 和 generation/context 信息。meta.eventId 等源追踪字段不替代信封 id；快照种类也不放入 AddressUpdatedData 的业务字段。

interface CarLocationPoint {

  orgId?: string;

GPS 是批次，不是历史单点 `TrackingGpsUpdateData`；不要求 incidentId/layerId，不能向未定义图层派发通用更新。Runtime 合并每车最新 accepted GPS，attachTracking 会同步 hydrate，DispatchT1 必须先创建控制器再 attach，卸载解绑。

### 0.3 归一顺序与订阅

Registry 优先级：SEAT(50) → 地址机器人(100) → 位置(110) → GPS(120) → 接听(130) → 警情(140) → 画像地址(150) → T1(900)。统一 `normalizeBusinessFrames` 先按上述业务顺序检查 916 原生识别范围，整轮未命中才按同序做包装增强，增强不得覆盖原生结果。install.ts 为各业务 interceptor 共享同一 context 的归一结果；SEAT multi 也走该归一器，未命中再走扩展 dispatcher。位置/GPS 保留多结果及去重，answer/incident 仅首个匹配；不能将 multi 解读为每类都发全部帧。

T1 标记 fallback，只在前面无结果时接受根 eventType 对象或根 payload 单对象的 eventType/eventKey；事件值与 data 原样保留，不做常量名映射，不递归展开 T1 列表/深层包装。公共解包支持数组、多层 JSON 与 request/data/body/message/payload/userMsgBodyList，但不能把该能力等同于 T1 的接收边界，也不能让位置/GPS 抢走 T1 内的 data。标准 Envelope 先于整条拦截链。

`MESSAGE_SUBSCRIBE_TOPIC` 保留 SEAT、ALARM_CALL、ALARM_INCIDENT、GPS_MSG、DISASTER_PROFILE 拦截器匹配模板；线上 subscribe 报文统一为字符串 topic，两者不是同一份声明。当前 V2 WS 装配在 `register/initMessage.ts`：connect 鉴权后订阅 `user/<userId>/screen/map`、`ALARM_INCIDENT/STATE_CHANGED`、`ALARM_CALL/ANSWER_STATUS_CHANGED`、`GPS_MSG/car-location-broadcast-all`、`DISASTER_PROFILE/UPDATED`，有席位时再订阅 `seat/<seatKey>`。服务端自动订阅用户级收件箱 `user/<userId>`，前端不重复声明。

连接身份只由 token 决定（`userId` + `sessionState`），与席位无关：换席在同一连接上按 V2 §4.1 先 `unsubscribe seat/<旧>` 再 `subscribe seat/<新>`，不重建连接；换用户或换会话才释放旧连接。`subscribed` 回执逐 topic 记录（`pending`/`ok`/`denied`），登出或换会话清空，经 `initMessage()` 返回值的 `subscriptionStatus()` 查询，供联调排查静默拒订。

重连计数在鉴权通过后才清零。若 CONNECT 被拒（`result=denied` 或 5s 超时）后服务端关闭连接，`reconnectAttempts` 才能正常生效，避免「打开即关闭」导致无限重连。本系统由外部主控负责会话与登出，不消费挤下线通知；`clientId` 固定为 `ids-seat-web`。

以上 core 路径相对 `src/controller/`。SharedState/MapPhase 等类型源在 `core/protocol/SharedStateProtocol.ts`；业务读取 store，工具使用 `utils/seatSharedState.ts`。MapMode 原样保存 phase，不自行改成派生 dispatch。

`getSharedMapStage(rawState, MapMode)` 校验 v=1、有限 updatedAt 和 auth；auth=null 为 loggedOut。onDuty/popup/dispatchTrack 直接投影；inquiry + currentAlarm=null 才为 inquiry，inquiry + 有效 incidentId 为 dispatch；非法/缺失快照及裸 phase='dispatch' 不直接放行。会话身份变化推进 sessionEpoch，旧消息/异步结果不得跨会话恢复。

### 0.5 F10～F13 与引擎适配

F10 `composables/useMockCallLocationBridge.ts` 负责解析 seat-shared-state-mock、字段差异/命令去重、LOCAL_STORAGE ingest 与导航意图；Runtime 队列负责执行，仅 dispatch attachment 使用 MockMapPort.render/disasterSite/simulate/clear/dispatchVehicles，并按 session/generation 作废旧任务。

底座路径 `src/baseComponent/OpenlayersMap/`：businessMapPort.ts 返回 `{ port, dispose }` 并创建 AddressRobotRenderer 与 AreaFenceRenderer；AddressRobotRenderer 的 API 为 new(genericController)、addressRobotGisSearch、addressRobotClear、dispose，负责搜索 Feature/样式/面板语义及自身延迟/动画清理；AreaFenceRenderer 的 API 为 new(genericController)、areaFenceHighlight、areaFenceClear、dispose，负责行政区划围栏的定位动画、闪烁高亮与常驻描边（按 businessId 分图层）；VehicleRenderer.ts 承载车辆引擎，DispatchT1 使用新路径；AddressRobotUtils 保存样式/排序，SwipeControl.ts/.css 承载卷帘。业务 Controller 仅依赖 BusinessMapPort；旧 vehicleManager.ts 是兼容导出。

`src/Control/**` 和 `useMessageStore916.ts` 保留对照，messageStageGate.ts 仍在，不能写为已删除或所有旧 normalizer 无引用。完整人工验收后，再由用户另行确认是否清理。

## 8. 当前维护规则

- 事件键与 DTO 变更须同步 `src/const/const.message.type.ts`、`src/controller/core/protocol/**` 及本文件、`协议层DTO Schema.tsd`；信封类型在 `src/types/message.ts`。
- 当前 transport 版本通过 `v: '1.0.0'` 表达；历史 `version: '1.0'` 不是当前字段，不能宣称已有自动版本协商。
- 新事件须先有源码常量与实际契约；不得从历史概念表推导新增事件。历史拼写 `map.base.poiLoation` 保持原样。
- `.tsd` 是文档示例，不参与 TypeScript 构建；不能宣称 CI 已对它与全部源码做 100% schema 一致性校验。
