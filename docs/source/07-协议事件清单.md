## 1. 协议事件分类

| 类别 | 命名空间 | 方向 | 主要消费者 |
| --- | --- | --- | --- |
| 业务事件 | `MessageEnvelope<BusinessPayload>` | 业务 → 协议 → 业务控制层 | 6 个业务 Controller |
| 通用事件 | `MessageEnvelope<GenericPayload>` | 业务控制层 → 通用控制层 | 4 个通用 Controller |
| IO 事件 | `MessageEnvelope<IOPayload>` | 视图 ↔ IO 控制层 ↔ 外部 | InputController、OutputController、Host |

## 2. 统一信封 `MessageEnvelope<T>`

```typescript
interface MessageEnvelope<T> {
  eventId: string;                      // 事件唯一 ID（UUID v4）
  occurredAt: number;                   // 事件发生时间戳（毫秒）
  scene: 'duty' | 'incoming-call' | 'inquiry' | 'dispatch' | 'tracking';
  source: 'system' | 'user' | 'host';
  coordSys: 'WGS84';                    // 强约束
  payload: T;
  tenantId?: string;
}
```

## 8. 事件版本演进规则

- 任何事件 schema 变更必须先更新 `协议层DTO Schema.tsd`，再更新 `src/controller/core/protocol/*.ts`，最后更新 `07-协议事件清单.md`。
- 任何事件字段新增为可选字段；删除字段必须先废弃（标记 `@deprecated`）并保留 1 个版本。
- 事件命名遵循 `场景.动作.子动作` 模式（如 `alarm.profile.snapshot`）。
- 跨版本兼容由 `MessageEnvelope.version` 字段处理（本版本默认 v1.0）。
- CI 强制校验 `协议层DTO Schema.tsd` 与 `src/controller/core/protocol/*.ts` 100% 一致。

---

#### 断言清单

1、协议事件清单是协议契约的单一真相源；任何新增/调整必须先更新本文档与 `协议层DTO Schema.tsd`。

2、统一信封 `MessageEnvelope<T>` 是所有事件的容器；事件消费方必须校验 `coordSys === 'WGS84'`。

3、业务事件、通用事件、IO 事件严格分离；通用控制层只消费通用事件，IO 控制层只消费 IO 事件。

4、事件版本演进规则是协议兼容的硬约束；CI 强制校验。

5、跨中心访问必须在协议层校验 `tenantId`；不允许跨中心消费事件。
