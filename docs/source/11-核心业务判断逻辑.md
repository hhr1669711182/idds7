### 11-核心业务判断逻辑

> 版本: v1.0  
> 日期: 2026-07-24  
> 范围: GIS 前端核心业务判断与决策链

---

## 1. 核心业务规则总览

GIS 前端的所有核心判断均围绕 **业务控制层**（6 个业务控制器）的 `decision` 函数展开，严格遵循"五层架构 + 协议契约 + 业务状态机"原则。

所有写操作前必须通过 `protectInvariants` 不变量校验，违反率必须为 0%。

### 1.1 视野与坐标系判断规则（充分必要）

- 协议层 / 服务层强约束 **WGS84 坐标系**，进入渲染层前由底座插件负责转换。
- Auto-Fit 必须保留 10%~15% Padding（避免视野贴边）。
- 所有图元 ID 必须加 **业务前缀**（`alarm_` / `call_` / `route_` / `plan_` / `vehicle_` / `trail_`），确保 ID 隔离。

### 1.2 警情判断规则（充分必要）

- 警情状态机严格遵循 [08-业务状态机定义](./08-业务状态机定义.md) 的迁移表。
- 警情进入 `DISPATCHED` 必须绑定至少 1 辆可调派车辆。
- 警情 `CLOSED` 时联动调派计划 `COMPLETED`、车辆 `RETURNING`。
- 警情订阅按"席位 + 中心"双维度过滤，接警员仅可见本中心警情。

### 1.3 来电与问询判断规则（充分必要）

- 来电进入立即触发 `locateToCall`（zoom=18，500m 圈），同时启动 5s 倒计时。
- 同一时间最多弹屏 **3 路** 来电，第 4 路进入排队。
- 问询信息必须持久化到 `CallLocation.payload`，关闭弹窗二次确认。
- 来电与警情通过 `CallCtrl.relateToAlarm(callId, alarmId)` 建立绑定。

### 1.4 调派判断规则（充分必要）

- 调派四级围栏（1km/500m/200m/100m）联动下发，渲染层按 zoom 自动显示/隐藏。
- 算路耗时 ≤ 1s，失败降级为直线段并打点 `ROUTE_FALLBACK`。
- 可调派车辆必须在 `IN_GARAGE` 状态（车辆状态机），按"距离最近 + 状态最优"双因子排序。
- 调派路径 ID 前缀为 `route_`，调派计划 ID 前缀为 `plan_`。

### 1.5 跟踪判断规则（充分必要）

- 车辆 GPS 推送频率 ≥ 2fps，订阅通道进入 **Web Worker**。
- Web Worker 负责坐标转换、距离计算、围栏命中判断，结果通过 `Transferable Objects` 回主线程。
- 主线程按 ≥ 30fps 频率刷新渲染，状态机更新按"事件驱动"。
- 跟踪模式下 zoom ≥ 19，50m 微观视图，镜头跟随绑定车辆。
- 单中心最大同时跟踪车辆数 ≤ 50，超过进入"聚合渲染"。

### 1.6 业务不变量保护判断规则（protectInvariants）

**强制校验顺序**（任何业务操作前必须通过）：

1. 坐标系是否 WGS84 → 否则拒绝（阻断渲染并打点 `COORD_VIOLATION`）。
2. 图元 ID 是否加业务前缀 → 否则拒绝（打点 `ID_PREFIX_MISSING`）。
3. 状态机迁移是否在 08 定义的有向边内 → 否则拒绝（打点 `ILLEGAL_TRANSITION`）。
4. 业务焦点是否互斥（同时仅一个业务域拥有焦点） → 否则丢弃后到指令（打点 `FOCUS_CONFLICT`）。
5. 操作人权限是否满足角色权限矩阵（详见 [04-角色与权限矩阵](./04-角色与权限矩阵.md)） → 否则拒绝。

**不变量违反处理**：

- 拒绝操作 + 写入 `OperationLog`（操作人、原因、时间）。
- 异常处理不改变已有主流程状态，仅记录并通过 `MessageEnvelope<T>` 通知相关业务域。

## 2. 核心判断决策输出与持续协同

- 所有判断完成后，统一通过协议层发布 `MessageEnvelope<T>` 事件（`AlarmChanged` / `VehicleChanged` / `DispatchChanged` / `CallChanged` 等）。
- 通用控制层（GeometryCtrl / KinematicCtrl / SpatialCtrl / ViewCtrl）订阅并按业务参数执行。
- 异常场景（GPS 丢失、算路失败、围栏越界）优先保障数据一致性，操作完成后统一记录关键节点。
- 所有写操作前必须通过不变量校验，违反率必须为 0%。

## 3. 人工操作判断链

接警员 / 值班长通过 UI 触发业务动作时，统一走以下处理链：

```
人工操作 → 业务控制层 (AlarmCtrl/CallCtrl/InquiryCtrl/DispatchCtrl/DutyCtrl/TrackingCtrl)
    ↓
protectInvariants() 不变量保护
    ↓
decision() 业务判断
    ↓
stateMachine.transit() 状态机迁移
    ↓
protocolLayer.publish(MessageEnvelope<T>) 协议发布
    ↓
通用控制层 (GeometryCtrl/KinematicCtrl/SpatialCtrl/ViewCtrl) 执行
    ↓
渲染层 (OpenLayers/ThreeJS) 绘制
    ↓
OperationLog 留痕 + GIS_OPERATION 打点
```

**强制约束**：

- 任何业务动作必须经过完整链路，**禁止** UI 直接调用通用控制层。
- 通用控制层只接收 **通用控制层输入指令集（Generic Control Input DTOs）**，不感知业务参数。

## 4. 跨业务域判断规则

### 4.1 焦点互斥

- 同时只有一个业务域拥有"焦点控制权"（focus owner）。
- 焦点拥有者触发视野变化时，其他业务域的视野指令被丢弃。
- 焦点切换通过 `MessageEnvelope<FOCUS_CHANGE>` 广播。

### 4.2 资源互斥

- 同一图元不能被多个业务域同时占用。
- 抢占规则：先到先得；同帧内按业务优先级（**调派 > 跟踪 > 问询 > 来电 > 值守**）裁决。

### 4.3 退出与回收

- 业务域退出（关闭弹窗）必须发布 `DOMAIN_EXIT` 事件，由当前焦点拥有者主动释放。
- 强制退出（警情关闭）由业务控制层调用 `release(id)` 精准回收。

## 5. 性能边界判断

| 性能指标 | 阈值 | 超限响应 |
| -------- | ---- | -------- |
| 帧率 | ≥ 30fps（P95） | 自动降级为聚合渲染 |
| 来电弹屏延迟 | ≤ 500ms | 自动降低弹窗动画时长 |
| 调派算路 | ≤ 1s（P95） | 降级为直线段 |
| 跟踪车辆数 | ≤ 50/中心 | 超过进入聚合渲染 |
| 同时弹屏来电 | ≤ 3 路 | 超过进入排队 |

---

## 6. 异常判断与降级

详见 [12-异常处理流程](./12-异常处理流程.md)，本文件不重复。

核心异常类型：

| 异常类型 | 触发条件 | 降级策略 |
| -------- | -------- | -------- |
| 坐标系污染 | 协议层收到非 WGS84 坐标 | 阻断渲染并打点 `COORD_VIOLATION` |
| 非法状态迁移 | 违反 08 状态机迁移表 | 阻断并打点 `ILLEGAL_TRANSITION` |
| 算路失败 | 算路服务超时或返回错误 | 降级为直线段并打点 `ROUTE_FALLBACK` |
| GPS 丢失 | 车辆 GPS 信号丢失 > 30s | 标记 `GPS_LOST` 并保留最后位置 |
| 焦点冲突 | 同帧多个业务域争夺焦点 | 按优先级裁决并打点 `FOCUS_CONFLICT` |
| ID 缺失前缀 | 图元 ID 未加业务前缀 | 阻断发布并打点 `ID_PREFIX_MISSING` |

---

#### 断言清单

1. GIS 前端所有核心判断收敛在业务控制层 6 个控制器的 `decision` 函数，渲染层不允许出现业务判断。
2. 不变量校验（protectInvariants）按"坐标系 → ID 前缀 → 状态机迁移 → 焦点互斥 → 权限"强制顺序执行，违反率必须为 0%。
3. 跨业务域焦点互斥，资源互斥；同帧内按"调派 > 跟踪 > 问询 > 来电 > 值守"优先级裁决。
4. 性能边界触发自动降级：帧率 < 30fps → 聚合渲染、跟踪 > 50 车 → 聚合渲染、算路失败 → 直线段、同时来电 > 3 路 → 排队。
5. 异常处理不改变已有主流程状态，仅记录并通过 `MessageEnvelope<T>` 通知相关业务域。
