## 1. 用户角色定义

| 角色 | 说明 | 权限级别 | 主要职责场景 |
| --- | --- | --- | --- |
| 接警员 | 指挥中心一线接警操作人员 | 普通操作用户 | 自主选择场景、确认来电、问询研判、发起调派、跟踪车辆 |
| 调度员 | 指挥中心调派与协商人员 | 主管用户 | 调派协商、ETA 过滤、路径切换、推荐路径选择 |
| 值班长 / 班长 | 指挥中心当值主管（同时承担班长席监控职责） | 高级用户 | 人员召回、配置调整、通过班长席监控大屏实时监督全中心运行状态 |
| 系统管理员 | 系统配置与运维管理 | 管理人员 | 容量上限配置、图层 ID 配置、围栏配置、性能基线配置 |
| SRE / 运维 | 故障处置与系统维护 | 管理人员 | 接收告警、故障修复、性能调优、构建部署 |
| 主前端 Host | 接处警主前端（外部系统） | 系统 | 通过 postMessage 发送页面跳转、警情定位、图元联动 |

说明：所有角色操作均严格限制在本人归属指挥中心范围内；接警员不可对非归属中心进行操作，跨中心访问必须拒绝并记录关键节点操作记录。

## 6. 权限控制实现

### 6.1 权限控制位置

- **协议层**：协议事件分发前由 `MessageStore` 校验订阅者权限。
- **业务控制层**：每个方法执行前由 `protectInvariants()` 校验角色权限。
- **渲染层**：组件根据 `useCommonStore.currentRole` 控制 UI 显隐。
- **Pinia store**：每个 action 调用前由 RBAC 装饰器校验。

### 6.2 跨中心访问拒绝

所有非归属中心访问必须：
- 拒绝并记录关键节点操作记录。
- 推送告警至班长席监控大屏。
- 不向用户暴露任何非归属中心数据。

### 6.3 权限变更记录

- 所有权限变更（角色调整、订阅矩阵调整、配置变更）必须记录操作人、时间、原因。
- 操作记录保留期 ≥ 2 年，不可篡改。
- 重大权限变更需发起评审。

---

#### 断言清单

1、角色权限矩阵是 GIS 前端功能可见性的基线；任何 UI 显隐、数据过滤、协议订阅都必须按矩阵执行。

2、跨中心访问必须拒绝并记录关键节点操作记录；不向用户暴露任何非归属中心数据。

3、权限控制必须在协议层、业务控制层、渲染层、Pinia store 四处协同执行；任一处缺失即为不合规。

4、所有权限变更必须记录操作人、时间、原因；保留期 ≥ 2 年，不可篡改。

5、SRE 仅接收告警、修复故障、调优性能；不参与业务流转。
