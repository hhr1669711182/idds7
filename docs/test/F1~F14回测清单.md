### 0.3 localStorage 构造速查（可复制）

地图屏读取两个 key（同源，主屏也会写）。测试时**改 Value 后回车即生效**；要恢复正常，把值改回主屏写入的原始内容或刷新主屏让其重写。

**① 门禁 key：`seat-shared-state`**（控制阶段/上下文/登出）

基础结构：
```json
{
  "v": 1,
  "updatedAt": 1,
  "phase": "inquiry",
  "mode": "normal",
  "currentAlarm": { "incidentId": "test-incident-001" },
  "auth": { "accessToken": "test-token", "sessionId": "test-session" },
  "user": { "userId": "test-user" },
  "seat": { "seatNumber": "test-seat" }
}
```

| 想构造的场景 | 改哪个字段 | 对应测试项 |
|---|---|---|
| 登出（拒绝所有业务） | `auth` 改为 `null` | T06-12 |
| 未立案问询 | `phase`=`inquiry`，`currentAlarm`=`null` | T06-07/11 |
| 调派上下文（放行画像/警情） | `phase`=`inquiry`，`currentAlarm.incidentId` 为非空字符串 | T06-11/15/17 |
| 车辆跟踪阶段 | `phase`=`dispatchTrack` | F8 真值表 |
| 特灾模式 | `mode` 改为 `flood`（`phase` 保持 `inquiry`） | T06-25/29 |
| 坏快照（无效上下文） | `v` 改为 `2`，或存非法 JSON `{bad` | T06-12/27 |

> 注意：`phase` 是原始值，地图屏**不**把 `literal dispatch` 自动当调派；调派只认 `inquiry + 有效 incidentId`（见 §4 F8 真值表）。

**② 模拟 key：`seat-shared-state-mock`**（控制 F10 模拟来电/调派/特灾）

基础结构：
```json
{
  "v": 1,
  "updatedAt": 1,
  "callLocation": { "lng": 106.71, "lat": 26.57, "address": "测试模拟来电" }
}
```

| 想构造的场景 | 加/改哪个字段 | 对应测试项 |
|---|---|---|
| 模拟来电定位上图 | 加 `callLocation: {lng, lat, address}` | T06-26 |
| 模拟来电坐标更新一次 | `callLocation` 坐标改值，`updatedAt` +1 | T06-26 |
| 删除模拟来电（只清模拟，保留真实） | Application 里**删除** `seat-shared-state-mock` 这个 key | T06-26 |
| 特灾灾害点 | 加 `site`（非空对象） | T06-25/30 |
| 特灾模拟命令 | 加 `command: { "id": "cmd-1", ... }` | T06-28/30 |
| 坏 mock 数据（不清图） | 存非法 JSON `{bad` 或缺 `v`/`updatedAt` | T06-27 |

> 改完回车后看地图屏；模拟来电用固定 mock ID，与真实来电不冲突。

### 0.4 Console 核验关键词速查

执行每条人工用例后，在地图屏 Console 搜索对应关键词确认：

| 关键词 | 确认什么 |
|---|---|
| `subscribed` 且 `result=ok` | WS 订阅成功（被拒会是 `denied`） |
| `ANSWER_STATUS_CHANGED` | 来电接听状态到达 |
| `map.locate.call` | 来电定位事件到达 |
| `[gis-point-channel]` + `PICK_START` / `PICK_APPLIED` / `PICK_CANCEL` | 二次定位选点链路 |
| `STATE_CHANGED` + `CREATED` | 警情立案 |
| `DISASTER_PROFILE` / `UPDATED` | 画像/队站/槽位刷新 |
| `GPS_MSG` 或 `tracking.vehicle.gps.update` | 车辆 GPS 批次到达 |
| `vehicleTrack` | 历史轨迹触发 |
| `relay` / `ids-map-screen-relay` | 地图屏 relay 通道 |

> 找不到关键词不等于失败——先确认场景是否真的触发（阶段是否合法、消息是否发出）；阶段被拒的消息本就不会上图（见 F8 真值表）。

## 1. 状态标记与记录规则

| 标记 | 含义 | 用法 |
|---|---|---|
| ✅ 通过 | 实际结果与预期一致 | 填执行日期 |
| ❌ 不通过 | 结果与预期不符 | 记入 §8 缺陷汇总，标注是否阻塞 |
| ⏸ 阻塞 | 环境/依赖/权限缺失无法执行 | 写明原因，不打勾 |
| ❄️ 冻结登记 | F12/K01/K02 既有缺陷，仅验证迁位无新增差异 | 只登记现象，不宣称闭环 |

**记录规则**：
- 每条用例执行后必须填「结果」与「执行人/日期」；空白或只写「已检查」不视为通过。
- 自动化项复跑后退出码 0 且输出与预期一致才算通过；不能据「上次通过」推断本次通过。
- 冻结项（F12 / K01 / K02，见 §5）只验证「迁位无新增差异」，失败用例不得打勾。
- 发现契约（事件键/DTO/状态机）与 `docs/source/**` 不一致 → 记缺陷，不在本清单修改契约。
