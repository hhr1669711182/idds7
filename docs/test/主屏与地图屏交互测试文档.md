# 主屏 × 地图屏 · 交互测试文档

> 面向 QA 与前端联调。测试环境为真实环境（`ids-test.ks.telewave.tech`），非本地 mock。
> 主线：**主屏（受理席/调派席）做什么 → 地图屏该显示什么**。

---

## 一、功能简介

主屏与地图屏分属两个前端应用：

| 端 | 应用 | 说明 |
|----|------|------|
| 主屏 | ids-seat-web（受理席/调派席） | 业务操作入口：接警、立案、调派、派车、结案 |
| 地图屏 | ids-gis-web（本仓库，`/#/map`） | 地图渲染：定位、警情产物、车辆轨迹、回放面板 |

| 用例 | 主屏操作 | 地图屏预期显示 |
|------|----------|----------------|
| TC-01 登录/连接 | 主屏正常登录 | 地图屏打开后 WS 连接成功、自动订阅 `screen/map` |
| TC-02 来电接听 | 有电话打入、接听 | 地图屏进入 popup 态 |
| TC-03 二次定位（新增） | 主屏对该警情发起「重新定位」 | 地图屏进入选点模式，点击地图后新坐标回传主屏、警情 marker 移到新点 |
| TC-04 来电定位上图 | 主屏展示定位 | 定位 marker 上图、视野飞到该点 |
| TC-05 接警立案 | 主屏填写地址/立案 | 警情画像上图（地址槽位、辖区/队站资源），进入 dispatch 门禁 |
| TC-06 切换主管队站（新增） | 主屏修改该警情主管队站 | 主管队站图标/辖区面/周边资源/路径线按新队站重建，旧队站产物清除 |
| TC-07 调派派车 | 主屏下发调派、派车 | 候选队站/路线上图、车辆标记出现 |
| TC-08 车辆出动跟踪 | 车辆出动、GPS 广播 | 车辆沿真实路线移动、轨迹实时延伸 |
| TC-09 结案/终态 | 警情进入终态 | 警情产物清空、历史轨迹回放面板出现（引用已有历史轨迹回放测试文档.md） |
| TC-10 回归值守 | 结案后主屏回归 | 地图屏恢复值守底图、清除警情产物 |

两端通过两条通道交互：

```
主屏 ──WS 下行──▶ 地图屏（订阅 user/<userId>/screen/map）
       ├─ ALARM_CALL/ANSWER_STATUS_CHANGED   来电接听状态
       ├─ ALARM_INCIDENT/STATE_CHANGED      警情状态变更
       ├─ GPS_MSG/car-location-broadcast-all 车辆 GPS 广播
       └─ DISASTER_PROFILE/UPDATED          警情画像（地址/主管队站）

主屏 ──BroadcastChannel 'ids-map-screen-relay'──▶ 地图屏
       └─ PICK_START / PICK_APPLIED / PICK_CANCEL  二次定位选点

主屏 ──localStorage seat-shared-state（同 origin）──▶ 地图屏
       └─ phase / currentAlarm / mode  决定地图屏门禁 stage
          （popup / inquiry / dispatch / dispatchTrack / onDuty）
```

地图屏按 `stage` 在地图上渲染对应产物：`popup` 来电定位、`dispatch` 警情画像+队站+路径、`dispatchTrack` 车辆实时轨迹、`onDuty` 值守底图。

## 二、测试环境准备

| 项 | 值 |
|----|----|
| 主屏地址（受理席） | `http://ids-test.ks.telewave.tech/seat-web/acceptance/main-shell` |
| 副屏地址（辅助屏） | `http://ids-test.ks.telewave.tech/seat-web/acceptance/aux-shell` |
| 地图屏地址 | `http://ids-test.ks.telewave.tech/gis-web/#/map` |
| 连接身份 | 主屏登录后，地图屏同源打开，自动携带登录态并发起 WS 连接 |

> 三端同属 `ids-test.ks.telewave.tech`，**同源**：WS 下行、BroadcastChannel（二次定位）、localStorage（共享态 `seat-shared-state`）三条通道均正常工作。

**启动方式**：

1. 主屏登录（测试账号）：`http://ids-test.ks.telewave.tech/seat-web/acceptance/main-shell`。
2. 打开副屏：`http://ids-test.ks.telewave.tech/seat-web/acceptance/aux-shell`（切警情、调席操作在此进行）。
3. 打开地图屏：`http://ids-test.ks.telewave.tech/gis-web/#/map`。
3. 打开地图屏 DevTools → Console，用于核验日志；Network → WS 可看连接状态。

> 若地图屏未自动连接，检查 Console 是否有 WS 连接报错；连接成功后 Network 里应能看到 `/message-client/ws` 长连接。

## 三、测试用例

### TC-01 登录后地图屏自动连接

**等级**：P0

**主屏操作步骤**

1. 主屏正常登录。
2. 同源打开地图屏 `http://ids-test.ks.telewave.tech/gis-web/#/map`。

**地图屏预期显示**

1. 地图底图加载完成（值守态 `onDuty`）。
2. DevTools → Network 中 `/message-client/ws` 处于 `101 Switching Protocols`。
3. Console 无 WS 连接报错；订阅回执 `subscribed` 均为 `ok`（`screen/map`、`ALARM_INCIDENT/STATE_CHANGED`、`ALARM_CALL/ANSWER_STATUS_CHANGED`、`GPS_MSG/...`、`DISASTER_PROFILE/UPDATED`）。

**核验点**：Console 搜索 `subscribed` 应看到各 topic `result=ok`；若有 `denied`，记录被拒 topic。

---

### TC-02 来电接听

**等级**：P0

**主屏操作步骤**

1. 用测试电话打入。
2. 主屏显示来电，点击「接听」。

**地图屏预期显示**

1. 地图屏从 `onDuty` 进入 `inquiry` / `popup` 态（地图上出现来电粗定位点）。
2. 若该来电带定位，地图视野飞到来电大致位置；否则保持当前视野，等待定位上图。

**核验点**：Console 搜索 `ANSWER_STATUS_CHANGED` 应看到接听状态消息；`seat-shared-state` 的 `phase` 应更新为 `inquiry`。

---

### TC-03 来电定位上图

**等级**：P0

**主屏操作步骤**

1. 在 TC-02 基础上，主屏展示来电定位结果（后端推送定位坐标）。

**地图屏预期显示**

1. 地图出现来电定位 marker，视野自动飞到该坐标。
2. marker 位置与主屏展示的地址坐标一致（允许地图投影误差内）。

**核验点**：地图上 marker 落在预期坐标；Console 搜索 `map.locate.call` 应看到定位事件。

---

### TC-04 二次定位（人工校正坐标）

**等级**：P0

**场景**：来电定位坐标有偏差，主屏发起「重新定位」，由地图屏人工点选校正。

**主屏操作步骤**

1. 在 TC-03 基础上，主屏点击「重新定位 / 二次定位」按钮（携带 incidentId）。
2. 等待地图屏进入选点模式。
3. 在地图上点击正确目标位置。
4. 点击「确认」回传坐标给主屏。

**地图屏预期显示**

1. 地图屏收到选点请求后，光标变为选点状态，可点击。
2. 点击地图后，警情 marker 从原偏移位置移动到新点击位置。
3. 坐标回传主屏后，主屏地址坐标同步更新。

**核验点**：Console 搜索 `[gis-point-channel]` 应依次出现：
- `收到 PICK_START`（含 incidentId / ownerId）
- 地图点击后回传 `PICK_APPLIED`
- 若主屏取消，应出现 `PICK_CANCEL`，选点模式退出。

---

### TC-05 接警立案

**等级**：P0

**主屏操作步骤**

1. 在 TC-04 基础上，主屏填写警情地址、灾害类型等信息。
2. 点击「立案」（警情状态 `CREATED`）。

**地图屏预期显示**

1. 地图屏进入 `dispatch` 门禁态（`phase=inquiry` + `currentAlarm.incidentId` 有效）。
2. 警情画像上图：地址标注、命中辖区面、主管/支撑队站图标、周边资源。
3. 视野聚焦到警情点与队站。

**核验点**：
- Console 搜索 `CREATED` / `STATE_CHANGED` 应看到立案状态。
- `seat-shared-state.currentAlarm.incidentId` 与主屏一致（同源可查）。
- 地图上出现警情 marker + 队站图标 + 辖区面。

---

### TC-05B 副屏切换警情上图

**等级**：P1

**场景**：多警情并存时，在副屏切换当前操作的警情 ID，地图屏跟随切换上图。

**前提**：
- 当前存在 ≥2 条有效警情。
- **待切换的目标警情必须已有位置坐标**——无位置的警情不会触发上图。

**副屏操作步骤**：

1. 在副屏（`aux-shell`）警情列表中，从当前警情 A 切换到警情 B。
2. 等待 2~3 秒，观察地图屏。

**地图屏预期显示**：

1. 警情 A 的产物（marker / 辖区面 / 队站图标 / 路线）被清除。
2. 警情 B 有位置：产物上图，视野跳到 B 的坐标。
3. 警情 B 无位置：地图屏**不**切换上图，保持原状（不出现半成品 marker / 错误定位），Console 无报错。

**核验点**：
- Console 搜索 `STATE_CHANGED` / `DISASTER_PROFILE/UPDATED` 应看到切换后警情 B 的消息。
- 地图上旧警情产物消失、新警情产物出现；切换无位置警情时无残留 marker。

---

### TC-06 切换主管队站

**等级**：P1

**场景**：立案后发现主管队站选错，主屏修改主管队站，地图屏按新队站重建产物。

**主屏操作步骤**

1. 在 TC-05 基础上，主屏修改该警情的「主管队站」为另一队站并保存。

**地图屏预期显示**

1. 原主管队站图标 / 辖区面 / 周边资源 / 路径规划线被清除。
2. 按新主管队站重新上图：新主管站 `zhu.png` 图标、对应辖区面、新队站周边支撑资源、新路径规划线。
3. 坐标命中的辖区被消息指定的主管队站强制覆盖（即使坐标落在别的辖区）。

**核验点**：
- Console 搜索 `DISASTER_PROFILE/UPDATED` 应看到画像刷新（`m_org_id` 为新队站 ID）。
- 地图上旧队站产物消失、新队站产物出现；路径线从新队站指向警情点。

---

### TC-07 调派派车

**等级**：P0

**主屏操作步骤**

1. 在 TC-06 基础上，主屏下发调派指令、选择出动车辆。
2. 警情状态推进到 `DISPATCHED`（出动）。

**地图屏预期显示**

1. 候选队站 / 候选路线上图（DispatchRoutePreview 面板可切候选）。
2. 出动车辆标记出现，车辆按选中路线行驶动画（本地环境）或等待真实 GPS（测试环境）。
3. 警情面板显示调派信息。

**核验点**：
- Console 搜索 `DISPATCHED` / `STATE_CHANGED` 应看到出动状态。
- 地图上出现车辆 marker + 路线规划线。

---

### TC-08 车辆出动跟踪

**等级**：P0

**前置说明**：依赖测试环境有真实车辆上线并广播 GPS。

**主屏操作步骤**

1. 在 TC-07 基础上，出动车辆实际行驶。
2. 主屏保持调席/跟踪态。

**地图屏预期显示**

1. 车辆 marker 沿真实 GPS 轨迹连续移动（不是本地 mock 直线）。
2. 已行驶轨迹线实时延伸。
3. 多车时每车独立移动，车牌 / 车辆类型标识正确。

**核验点**：
- Console 搜索 `tracking.vehicle.gps.update` 或 `GPS_MSG` 应看到批次 GPS 消息（`{ datas: [...] }`）。
- 车辆位置与后端 GPS 一致；地图无卡顿。

---

### TC-09 结案 / 终态触发历史轨迹回放

**等级**：P0

**主屏操作步骤**

1. 警情推进到终态（`ARRIVED` / `OPERATION_COMPLETED` / `RETURNED` / `CLOSED` / `POST_ACTION_REVIEWED` 任一）。

**地图屏预期显示**

1. 原有警情产物（队站 / 资源 / 路径规划线）被清空。
2. 地图出现出动车辆历史轨迹：完整线 + 已走灰线 + 车辆图标 + 方向箭头。
3. 底部弹出「车辆历史轨迹回放」面板（时间轴 + 倍速 + 路线切换 + 轨迹统计）。

**核验点**：
- Console 搜索 `vehicleTrack` 应看到终态触发、查询车辆 / 轨迹、渲染组数日志。
- 详细回放面板功能（播放 / 倍速 / 时间轴 / 多路线切换 / 统计）见 [历史轨迹回放测试文档.md](./历史轨迹回放测试文档.md)，不在此重复。

---

### TC-10 回归值守

**等级**：P1

**主屏操作步骤**

1. 结案后，主屏结束当前警情 / 回归值守。

**地图屏预期显示**

1. 地图屏回到 `onDuty` 值守态。
2. 所有警情产物（marker / 队站 / 路线 / 轨迹 / 回放面板）清除。
3. 底图恢复到默认值守视野。

**核验点**：
- `seat-shared-state.phase` 回到 `onDuty`，`currentAlarm=null`。
- 地图上无残留警情 marker / 路线 / 面板；Console 搜索对应事件无新报错。

## 四、交互核验速查表

| 主屏/副屏动作 | 地图屏 stage | 地图屏应出现 | 对应消息 / 通道 |
|---------|------------|-------------|---------------|
| 登录 | `onDuty` | 值守底图 | WS 连接 + 订阅回执 |
| 接听 | `inquiry` / `popup` | 来电粗定位 | `ALARM_CALL/ANSWER_STATUS_CHANGED` |
| 定位上图 | `popup` | 定位 marker | `map.locate.call` |
| 二次定位 | `dispatch`（选点中） | 选点模式、marker 移动 | BC `PICK_START` / `PICK_APPLIED` |
| 立案 | `dispatch` | 警情画像 + 队站 + 辖区 | `ALARM_INCIDENT/STATE_CHANGED`（CREATED） |
| 副屏切换警情 | `dispatch` | 旧警情产物清空、新警情上图（需有位置） | `ALARM_INCIDENT/STATE_CHANGED` / `DISASTER_PROFILE/UPDATED` |
| 切换主管队站 | `dispatch` | 主管站 / 辖区 / 路径重建 | `DISASTER_PROFILE/UPDATED` |
| 调派派车 | `dispatch` | 候选路线 + 车辆 | `ALARM_INCIDENT/STATE_CHANGED`（DISPATCHED） |
| 车辆行驶 | `dispatchTrack` | 车辆移动 + 轨迹延伸 | `GPS_MSG/car-location-broadcast-all` |
| 终态结案 | 终态 | 旧产物清空 + 历史轨迹回放 | `ALARM_INCIDENT/STATE_CHANGED`（终态） |
| 回归值守 | `onDuty` | 底图、产物全清 | `seat-shared-state.phase=onDuty` |

## 五、异常兜底验证

| 场景 | 预期行为 |
|------|---------|
| 主屏未登录 / 地图屏直接打开 | WS 连接被拒或无订阅回执，地图屏不渲染业务产物 |
| 主屏发起二次定位但地图屏未响应 | Console 无 `PICK_START` 日志；检查两端是否同 origin（BC 通道要求同源） |
| 警情终态但画像消息晚到 | 终态警情直接拒绝画像上图（reason=`terminal`），不重复渲染旧产物 |
| 车辆 GPS 无广播源 | TC-08 车辆不动 / 不出现，Console 无 `tracking.vehicle.gps.update`；属正常，非地图屏故障 |
| 主屏切换主管队站消息丢失 | 地图屏仍显示旧队站产物；以最新 `DISASTER_PROFILE/UPDATED` 为准，不自动回滚 |
| 副屏切换到无位置的警情 | 地图屏不切换上图、不出现半成品 marker，保持当前警情（TC-05B 边界） |
| 结案后地图屏 F5 刷新 | 终态标记持久化（sessionStorage），刷新后直接回放轨迹，不恢复警情上图（详见历史轨迹回放文档 TC-TRK-06） |
