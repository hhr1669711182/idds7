# PR 代码审查流程

> 每次 MR 必须通过 AI 代码审查，问题闭环管理。本项目使用 **GitLab Merge Request**。

---

## 一、流程概览

```
开发者提交 MR
  │
  ├─→ 1. MR 描述中追加：@AI 检查本次MR
  ├─→ 2. AI 按维度审查
  ├─→ 3. 结果处理：
  │      ├─ 无问题 → 合入
  │      └─ 有问题 → 修复 OR 评论说明不修复原因
  └─→ 4. 问题闭环后合入
```

---

## 二、MR 描述模板

```markdown
## 变更概述
<简要描述本次变更内容和目的>

## 关联
- 关联迭代：YYYY-WXX
- 关联技术方案：herness/02-技术设计/前端/** 或路径
- 关联需求：herness/01-产品设计/** 或 docs/source/** 路径

## 变更文件
- 新增：<文件列表>
- 修改：<文件列表（含修改点）>

## 分层落点
| 改动点 | 层 | 文件 |
|--------|----|------|

## 测试情况
- 类型门禁：pnpm lint（无新增报错 / 新增报错说明）
- 手工验证：<验证路径与结果>

## 契约同步
- 事件键 / DTO / 接口：（是 → 列出同步的文件 / 否）

## AI 审查
@AI 检查本次MR
```

**审查请求**：`@AI 检查本次MR`，可附重点：

```
@AI 检查本次MR，重点关注：
- 消息事件键与拦截器是否同步
- 是否存在越层调用
- 订阅是否在卸载时取消
```

## 三、AI 审查维度（本项目定制）

| 维度 | 检查项 | 依据 |
|------|--------|------|
| **分层合规** | 是否越层；通用控制层是否混入业务；业务控制器是否直接 import 引擎 | `05-共享上下文/设计规范速查.md`「分层铁律」 |
| **契约一致** | 事件键/DTO 是否与 `docs/source/07-协议事件清单.md`、`协议层DTO Schema.tsd` 一致 | 消息协议速查 |
| **正确性** | 逻辑正确、边界处理、空值防护 | — |
| **消息链路** | 订阅是否取消；拦截器是否注册；发布的事件键与监听是否配对 | 消息协议速查 |
| **类型安全** | 是否有跨层 `any`；`pnpm lint` 是否引入**新增**报错 | `tsconfig` strict |
| **安全性** | XSS、越权、敏感信息泄露、origin 白名单 | `bindParent` acceptOrigins |
| **性能** | 高频数据是否走 Worker；图层是否重复创建；订阅是否泄漏 | — |
| **坐标与空间** | WGS84 顺序、缓冲区/AOI 正确性 | 设计规范速查 |
| **禁改文件** | 是否手改自动生成文件 / 构建产物 | 设计规范速查「禁改文件」 |
| **测试覆盖** | 关键路径与异常路径是否验证；`pnpm lint` 结果 | — |
| **文档同步** | 方案与代码是否一致；契约是否回写 | `02-技术设计/_流程规范.md` |

## 四、问题分类处理

### 4.1 必须修复（不得以评论代替）
- 分层越层（违反架构铁律）
- 契约不一致（事件键/DTO 未同步）
- 安全漏洞（注入、越权、XSS、未校验 origin）
- 数据一致性问题、崩溃风险（未捕获的空值）
- 手改自动生成文件 / 构建产物
- 订阅未取消导致的泄漏

### 4.2 可评论说明不修复
- 性能优化建议（当前数据量不构成瓶颈）
- 代码风格偏好（与现有风格一致即可）
- 重构建议（不在本期范围）

### 4.3 评论格式

```markdown
> AI 审查问题：XXX

不修复原因：<简要说明>
```
