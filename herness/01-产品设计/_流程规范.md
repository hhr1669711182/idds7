# 产品设计流程

> 需求从澄清到定稿的标准动作。本项目是前端工程，产品设计聚焦业务语义，技术方案在 [02-技术设计](../02-技术设计/_流程规范.md)。

---

## 一、流程概览

```
需求提出
  │
  ├─→ 1. 读业务上下文     → 05-共享上下文/核心概念术语.md + docs/source/**
  ├─→ 2. 需求澄清         → 明确目标、角色、边界、异常
  ├─→ 3. 交互/流程设计    → 流程图、页面流转、状态变化
  ├─→ 4. 产出 PRD/需求文档 → 01-产品设计/需求文档模板.md
  └─→ 5. 交接研发         → 进入 02-技术设计
```

---

## 二、澄清清单（必须逐项回答）

- [ ] **目标**：要解决什么问题？成功指标是什么？
- [ ] **角色**：谁使用？（接警员 / 调度员 / 值班员 / 管理员）
- [ ] **入口**：从哪个页面/消息进入？出口是什么？
- [ ] **主流程**：正常路径的每一步与状态
- [ ] **异常流程**：失败、超时、无数据、无权限如何处理
- [ ] **数据来源**：接口（`src/service/methods/**`）还是消息（WS/postMessage）？
- [ ] **坐标系与空间**：是否涉及坐标、缓冲区、AOI、路径？
- [ ] **权限**：对应 `docs/source/04-角色与权限矩阵.md` 的哪一档？
- [ ] **验收**：怎么算做完？（可观察、可测）

---

## 三、需求文档结构（见 需求文档模板.md）

1. 文档信息（迭代、作者、日期）
2. 背景与目标
3. 角色与场景
4. 功能需求（主流程 + 分支）
5. 业务规则（校验、默认值、边界）
6. 异常与提示（文案、兜底）
7. 验收标准
8. 待确认项

---

## 四、交接研发的门禁

进入 [02-技术设计](../02-技术设计/_流程规范.md) 前：

- [ ] 目标与验收标准明确
- [ ] 主流程与异常流程已梳理
- [ ] 数据来源明确（接口 or 消息事件键）
- [ ] 涉及的业务术语已在 `05-共享上下文/核心概念术语.md` 登记
- [ ] 权限要求已确认
