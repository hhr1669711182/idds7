## 一、测试目标

### 守什么（必须自动化或人工把关）

| 目标 | 守法 |
|------|------|
| 类型门禁 | `pnpm lint`（vue-tsc，非 ESLint）零新增报错；`pnpm lint:baseline` 对比 |
| 协议契约 | 消息事件键 / DTO 与 `docs/source/07-协议事件清单.md`、`协议层DTO Schema.tsd` 一致 |
| 坐标正确性 | WGS84 对外统一；GCJ-02 只在入站/出站转换函数；百度 y = -(OL y) - 1 |
| 分层不越界 | `core/generic/**` 零业务；`core/business/**` 禁 import ol/three；跨层 DTO 用 protocol |
| 业务状态机 | 警情 7 态（`docs/source/08-业务状态机定义.md`）流转合法；MapMode 阶段门禁 |
| 应用能起 | 路由进得去、关键 DOM 在位、无未捕获 JS 异常 |
| 业务全流程 | 警情 → 定位 → 画像 → 派车 → 轨迹 → 结案，可复现 |

### 不守什么（明确不纳入自动化断言）

| 不守 | 理由 | 兜底 |
|------|------|------|
| 像素与瓦片渲染 | jsdom 无布局；CI 无外网 / 无高德 key 会 401 | 人工目视 |
| 真实网关 / GeoServer | 远程真外部，注入 port 后测试给 mock adapter | `@alova/mock` + `server/mock-ws.js` |
| 真实 WS 鉴权 / 订阅回执 | 线上鉴权走宿主系统 | 回归报告标注「未覆盖」 |
| F12 选点 / ACK V1.0 既有缺陷 | 用户要求冻结等价迁位 | 见回归报告「冻结」项 |
| 3D 模型 glTF 贴图相对 uri | 必须整组留在 `public/`，自动化不校验 | 构建产物抽查 |

## 二、测试环境与工具链

### 2.1 运行时

| 项 | 值 |
|----|----|
| 操作系统 | Windows（开发基线）；CI 可用 Linux/macOS |
| Node / pnpm | Node ≥ 20（pnpm ≥ 10）；实测 Node 25.2.1 + pnpm 10.33.0 |
| 框架 | Vue 3.5 + TypeScript 6 + Vite 8 + Pinia 3 |
| 图形引擎 | OpenLayers 10（主）+ Three 0.169 + Cesium 1.143（仅库模式按需） |
| 形态 | 应用（`pnpm dev`）+ 库（`pnpm build:lib`，入口 `src/lib/index.ts`）双轨 |

### 2.2 单元 / 组件（Vitest）

| 项 | 值 |
|----|----|
| runner | Vitest 5（`vitest run`） |
| 环境 | jsdom + `tests/harness/setup.ts` 全局 setup（ResizeObserver / matchMedia / mock 清理） |
| 断言框架 | Vitest 内置 `expect` + `@vue/test-utils` mount |
| 覆盖率 | `@vitest/coverage-v8`，白名单见 §3.4 |
| 并发 | 默认并行；`--maxWorkers=4` 用于 Windows 重组件场景 |
| 不挂插件 | 不挂 Cesium / SVG 图标 / UnoCSS；Element Plus 由 resolver 真实解析 |

### 2.3 E2E（Playwright）

| 项 | 值 |
|----|----|
| runner | Playwright（独立 `@playwright/test`） |
| 浏览器 | 默认系统 Chrome（`channel: 'chrome'`），`PW_USE_SYSTEM_CHROME=0` 回落自带 |
| 视口 | 1440×900；`locale: zh-CN`、`timezoneId: Asia/Shanghai` |
| 并发 | **单 worker 串行**（地图吃内存，并行抢 GPU/端口） |
| 超时 | 单测 90s；expect 15s |
| 重试 | 本地 1 次；CI 0（`retries: process.env.CI ? 0 : 1`） |
| 报告 | 本地 list；CI 追加 HTML 到 `tests/__artifacts__/e2e/report` |
| 失败产物 | `trace: retain-on-failure` + `screenshot: only-on-failure`，落 `tests/__artifacts__/e2e/results` |
| webServer | `pnpm dev`（8888），本地 `reuseExistingServer` 复用已开的 dev，CI 强制拉起 |

### 2.4 Mock 与本地测试台

| 项 | 说明 |
|----|----|
| `pnpm mock:server` | 启动 `server/index.js` 本地 HTTP mock 网关 |
| `pnpm mock:ws` | 启动 `server/mock-ws.js`（:18080）：WS mock + `/test-ui/` 测试台 + `/api/test/*` |
| `pnpm dev:local:test` / `pnpm dev:test` | `node scripts/dev-with-mock-ws.mjs [test]`，dev 与 mock WS 同时拉起 |
| `/test-ui/` | 测试台前端页面（`server/test-ui/`），轮询增量写 `seat-shared-state`（phase / mode / currentAlarm）到 localStorage，GIS 页 storage 事件 → `useUserStore.applySharedState` → `useLayersStore` + `messageStagePolicy` 门禁热更新 |
| BFF mock 拦截 | `mock-ws.js` 的 `handleBffMock` 拦截 `queryIncidentTurnoutVehicles`、`queryCarHistoryTrack` 等，返回按 carId 的 `carPoints` 带 `gpsTime` |

### 2.5 场景编排引擎（全流程）

| 项 | 说明 |
|----|------|
| 入口 | `node server/test-runner/cli.js [mode] [--full] [--target user/session] [--url ws://…]`，对应 `pnpm test:scenario` / `pnpm test:scenario:full` / `pnpm test:scenario:cycle` |
| 控制通道 | `WsControl` 走 `:18080/mock-control` WS（与 test-harness 进程内同一套引擎） |
| 步骤契约 | `_base.js` 导出 `step` / `pushCallReceived` / `pushPosition` / `pushAddress` / `pushCallEnded` / `carSequence` / `incidentFlow` / `mockVehicles`；每步含 `tag`（core/extra）、`kind`（引擎据 kind 推导门禁 stage）、`afterMs`（观察窗） |
| 门禁推导 | 引擎按 kind 自动推导前端门禁所需 `MapMode.stage`（received→inquiry / position→popup / address·incident→dispatch / car→dispatchTrack），反推可写 `stored-state`（phase + currentAlarm），**不可直接写 phase='dispatch'**（须 phase='inquiry' + currentAlarm.incidentId 推导），否则 `getSharedMapStage` 返回 null，之后所有消息被门禁丢弃 |
| 报告 | 每步 PASS/FAIL + 耗时 + `gateWarn`；全量结果落 `server/test-runner/reports/`；退出码 0 = 全部通过 |

### 2.6 环境与 CI 差异

| 维度 | 本地 | CI |
|------|------|------|
| 测试环境 | `.env.local`（`VITE_AMAP_ADMCODE`/`CITY` 可配，test 暂用北京，切贵州改 `.env.test`） | 显式 `build:test` / `build:uat` / `build:prod` |
| E2E 浏览器 | 系统 Chrome | 自带 Chromium（`PW_USE_SYSTEM_CHROME=0`） |
| E2E 重试 | 1 次 | 0 次 |
| 门禁 | 全部**不阻塞提交**（与 lint 基线策略一致），`husky pre-commit` 只做提示 | 在 CI 显式执行 `pnpm test` / `pnpm e2e`，用退出码拦截 |
| 类型门禁 | `pnpm lint:baseline` 对比「无新增报错」 | 同本地 |

### 4.1 常见异常场景清单（复用 `编写规范.md` §三，配 GIS 关注点）

| 场景 | 预期兜底 | 自动化位置 |
|------|---------|-----------|
| alova 401 | 生产跳登录页；dev 不处理 | `error.spec` + 手工 dev 验证 |
| alova 业务失败（success=false） | 抛 `AppError`；默认 `ElMessage.error`；`meta.silent` 可静默 | `error.spec` |
| 响应空 / 非法 JSON | 抛 `AppError(INVALID_RESPONSE)` | `error.spec` + `messageNormalizationErrors.spec` |
| WS 断线 | `WebSocketClient` 自动重连；`wsError` 记录 | `webSocketClientV2.spec` |
| `postMessage` 非白名单 origin | 直接忽略 | `messageStore.spec` |
| 消息未命中拦截器与 Legacy | 静默丢弃（不抛错） | `unwrap.spec` |
| 拦截器 transform 抛异常 | 记录并跳过，不影响其他拦截器 | `messageNormalizationErrors.spec` |
| 组件卸载 | 已订阅的消息必须取消订阅 | `messageStore.spec` + 组件测试 |
| 坏 DTO 逐帧容错 | 不阻断兄弟帧；Error 日志保留 name/message/stack | `messageNormalizationErrors.spec`（回归报告 D04） |

### 4.2 状态迁移与权限的契约源

- 状态机：`docs/source/08-业务状态机定义.md`（警情 7 态：`CREATED → FORMAL_DISPATCHED → DISPATCHED → ARRIVED → OPERATION_COMPLETED → RETURNING → RETURNED`；核心 5 态省略 `OPERATION_COMPLETED`）
- 门禁 stage：`MapMode`（`popup` / `inquiry` / `dispatchTrack` / `onDuty` / `dispatch`）由 `getSharedMapStage` 投影；`inquiry` + 有效 `incidentId` 推导出 `dispatch`，**不要求外部显式写 `phase='dispatch'`**
- 权限矩阵：`docs/source/04-角色与权限矩阵.md`（当前**零自动化**，仅手工）

## 七、GIS 专用契约测试（复用 `tests/harness/README.md` §三，此处只列「测法」）

| 契约 | 测法 |
|------|------|
| **坐标系** | GCJ-02 边界**只能**出现在入站 / 出站转换函数（`amapGcj02ToWgs84` / `parseAmapLocation` 入站，`toAmapGjc02` / `toAmapLngLatString` 出站）；业务层 / store / DTO 统一 WGS84；**禁止** DTO 同时出现 `lng` 与 `wgs84Lng` 冗余字段。断言用**往返误差**而非绝对值：正常路径 `< 1e-5°`（≈ 1m，国测局简化算法固有精度）；`> 1e-3°`（≈ 100m）= 缺陷立即失败。百度投影（BD09 墨卡托）只允许经 `baseComponent/tools/baidu.ts` 工厂获取；断言瓦片 `y` 时注意 **百度 y = -(OL y) - 1**。 |
| **消息协议** | 测试中出现的事件键必须存在于 `const.message.type.ts` 的 `MESSAGE_EVENT_KEY`；收发必经 `useMessageStore().publish/subscribe`，测试里**禁止** `new WebSocket()` 或裸 `window.addEventListener('message')`。改事件键 / DTO 须同步 `docs/source/07-协议事件清单.md` 与 `协议层DTO Schema.tsd`，并在用例「回归关联」注明。 |
| **分层** | `core/generic/**` 零业务（不得出现 alarm / call / dispatch 等业务名词与地图类型）；`core/business/**` 禁 `import 'ol/...'` / `import 'three'`；跨层传参用 `controller/core/protocol/**` 的 interface，**禁止 `any`**。测试同样受约束：跨层 DTO 断言走 protocol interface，用例里不得出现 `as any` 绕过类型。 |
| **引擎隔离** | **不 mock OpenLayers / Three / Cesium 内部**——它们属「真外部 / 引擎」，断言**业务可观察结果**（图层是否加上、坐标是否落对），而非引擎内部状态。`useCurrentMap()` 在组件测试里返回空对象，`isOlMap` 为假后相关分支直接 return；网络请求失败（瓦片 401 / 地理编码超时）不计入失败，只拦未捕获 JS 运行时异常。 |

## 十、执行手册

### 10.1 本地全量跑通（开发 / 提 MR 前）

```bash
# 1. 类型门禁（零新增报错；基线当前 0 项）
pnpm lint
pnpm lint:baseline

# 2. 单元 + 组件
pnpm test
# 重组件场景（Windows 并发不足）：
pnpm test --maxWorkers=4

# 3. 覆盖率（产物落 tests/__artifacts__/coverage）
pnpm test:coverage

# 4. E2E 冒烟（独立拉起 dev server，:8888；本地 reuseExistingServer 可复用已开的 dev）
pnpm e2e

# 5. 全流程场景（先起 mock 服务 + dev:test）
pnpm mock:ws              # :18080 mock WS + /test-ui/
pnpm dev:test             # dev + mock WS（test 环境，北京数据中心）
pnpm test:scenario dispatch --full
pnpm test:scenario:cycle  # 等价 fullCycle --full

# 6. 构建（应用 + 库双形态）
pnpm build
pnpm build:lib

# 7. herness 文档体量自检
pnpm harness:check
```

### 10.2 CI 卡门禁（显式退出码拦截）

```yaml
# 示例（.github/workflows 或等价）
steps:
  - run: pnpm install --frozen-lockfile
  - run: pnpm lint && pnpm lint:baseline
  - run: pnpm test
  - run: pnpm test:coverage
  - run: pnpm e2e            # 需 CI 预装 Chromium（PW_USE_SYSTEM_CHROME=0）
  - run: pnpm build && pnpm build:lib
  - run: pnpm harness:check
```

### 10.3 失败排查

| 现象 | 排查路径 |
|------|---------|
| Vitest 用例失败 | 看终端 trace；重跑 `pnpm test:ui` 交互式定位；查 `tests/harness/setup.ts` 全局 mock 是否被覆盖 |
| E2E 冒烟失败（本地） | `pnpm e2e` 自动拉 dev server；冷启动 Vite 转换超时 → `smoke.spec` 内 `gotoWithWarmup` 已做刷新兜底；看 `tests/__artifacts__/e2e/results` 的 trace + screenshot |
| E2E 冒烟失败（CI） | `PW_USE_SYSTEM_CHROME=0` 用自带 Chromium；`retries: 0` 不掩盖不稳定；看 HTML 报告 `tests/__artifacts__/e2e/report` |
| 场景引擎 `gateWarn` | 查 `server/test-runner/reports/` 最近 run 的 `stateLog` + `stateSequence`；对照 `_base.js` 步骤契约（kind → stage 推导表）；确认 `test-ui` 是否增量写了正确的 `seat-shared-state` |
| 类型门禁新增报错 | `pnpm lint:baseline` 输出新增项；**必须当场修**（零基线策略，不再攒基线）；空值类（TS18047/2532/2531）必须真修，禁止 `as any` |
| 坐标断言失败 | 对照 §七 GIS 契约：往返误差 `< 1e-5°` 正常；`> 1e-3°` = 缺陷；百度 y 记得取反 |

### 10.4 测试资产位置

| 资产 | 位置 |
|------|------|
| 测试代码 | `tests/{unit,components,e2e,harness,fixtures}/**` |
| 覆盖率报告 | `tests/__artifacts__/coverage/` |
| E2E trace / 截图 / HTML 报告 | `tests/__artifacts__/e2e/` |
| 场景引擎报告 | `server/test-runner/reports/` |
| 回归报告 | `herness/03-测试/测试报告/`（如 `Control走线迁移-P1自动化回归报告.md`） |

> `tests/__artifacts__/**` 已 gitignore（可重新生成，不入库）。`src/**` 内禁止测试文件（`vue-tsc` 的 `include` 只覆盖 `src/**/*.ts`，测试天然不污染类型门禁基线）。
