# 测试用例编写规范

## 一、用例结构

每条用例包含：

| 字段 | 说明 |
|------|------|
| 用例编号 | TC-{模块}-{序号} |
| 用例标题 | 场景 + 预期 |
| 关联需求/方案 | 文档路径 |
| 前置条件 | 页面状态、数据、登录态、开关 |
| 操作步骤 | 可复现的步骤 |
| 预期结果 | 可观察的具体表现 |
| 实际结果 | 执行后填写 |
| 结论 | 通过 / 不通过 / 阻塞 |

---

## 二、必须覆盖的用例类型

| 类型 | 示例 |
|------|------|
| **正常路径** | 来电定位正常落点并适配视口 |
| **边界** | 坐标为 0/极值；缓冲区半径为 0；列表为空 |
| **异常** | 接口 500 / 业务 code 非 0；WS 断线；数据为 null |
| **权限** | 无权限操作被拦截（对照 `docs/source/04-角色与权限矩阵.md`） |
| **状态迁移** | 警情/车辆状态流转合法与非法（对照 `docs/source/08-业务状态机定义.md`） |
| **空间计算** | 缓冲区、AOI、ES 查询结果的正确性 |
| **消息链路** | 订阅生效、取消后不再回调、拦截器归一正确 |
| **回归** | 改动公共层（store/controller/const）后的既有功能 |

---

## 三、本项目常见异常场景清单

| 场景 | 预期兜底 |
|------|---------|
| alova 401 | 生产跳登录页；dev 不处理 |
| alova 业务失败（success=false） | 抛 `AppError`；默认 `ElMessage.error`；可 `meta.silent` 静默 |
| 响应空 / 非法 JSON | 抛 `AppError(INVALID_RESPONSE)` |
| WS 断线 | `WebSocketClient` 自动重连；`wsError` 记录 |
| postMessage 非白名单 origin | 直接忽略 |
| 消息未命中拦截器与 Legacy | 静默丢弃（不抛错） |
| 拦截器 transform 抛异常 | 记录并跳过，不影响其他拦截器 |
| 组件卸载 | 已订阅的消息必须取消订阅 |

---

## 四、编写规范

- 用例必须**可复现**：前置条件与步骤写清，不写"正常情况下"
- 预期结果**可观察**：具体到界面表现或数据，不写"功能正常"
- 覆盖**异常**：每个用例至少考虑一条异常分支
- 涉及消息的用例标明**事件键**与**通道**
- 涉及坐标的用例标明**坐标系**与**坐标顺序**
- 发现缺陷 → 记录并跟踪，修复后回归
