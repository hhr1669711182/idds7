# 代码注释规范

> **适用范围**：约束**新产生 / 本次改动**的编码文件（`src/**` 下的 `.ts` / `.tsx` / `.vue`）。
> **存量不追溯**：已在库的历史注释、模板文件头、注释掉的代码块一律**保持现状，不清理、不改写**；存量治理另立专项、分批单独 MR，不夹带在业务需求里。
> **冲突裁决**：与本规范冲突的旧条款（如「新增文件头保留 `@Author` 模板」）以本规范为准。

---

## 一、核心判定

一条注释该不该存在，只回答一个问题：

> **下一个人改这段代码时，不知道就会踩坑吗？**

| 答案 | 动作 |
|------|------|
| 不知道会踩坑 | 留注释，把坑写清楚（写「为什么」、风险在哪） |
| 看了代码就懂 | **不写**。非必要不注释 |

**分级要求**

| 文件类型 | 目录 | 注释要求 |
|------|------|---------|
| **业务代码文件** | `views/` `components/` `baseComponent/` `assets/` | **非必要不注释**，只留「会踩坑」的必要说明 |
| **公共文件** | `utils/` `controller/` `store/` `composables/` `apis/` `config/` `const/` `interceptor/` `service/` | **必须规范注释**，导出符号一律有 JSDoc |

## 二、三层分工：代码放不下的，搬到 herness

| 内容 | 正确归属 | 代码里留什么 |
|------|---------|-------------|
| 设计背景、方案对比、完整流程 | `herness/02-技术设计/` | 一行 `// 方案见 herness/02-技术设计/xxx.md` |
| 跨模块契约、术语定义 | `herness/05-共享上下文/` | 一行链接 |
| **为什么这么写、坑在哪** | **代码内**（本规范范围） | 1–3 行，写完整 |
| 已完成事项、「改过这里」的流水账 | `herness/09-工作日志/` | **无** |

## 三、长度硬上限

| 类型 | 建议 | 硬上限 | 超限动作 |
|------|------|--------|---------|
| 行尾注释 | 1 句 / 30 中文字 | 1 句 | 提到上一行独立注释 |
| 独立注释行 | 1–2 行 | 3 行 | 搬到 `herness/02-技术设计/` |
| JSDoc 块注释 `/** */` | 3–5 行 | **10 行** | 搬到 `herness/02-技术设计/` |
| 同位置连续注释块 | — | **15 行** | 搬到 `herness/02-技术设计/` |
| 文件头 | 0 行 | **最多 1 行** `// 用途：xxx` | 删除模板头 |
| 注释掉的旧代码 | 0 行 | 0 行 | git 有历史，直接删 |

## 四、公共文件的注释义务

改动或新增公共文件时，下列对象必须满足：

| 对象 | 要求 |
|------|------|
| `export` 的函数 / 类 / 常量 / 类型 | 必须有 JSDoc：用途一句话；`@param` 仅在入参非显然时写；返回值有特殊约定（坐标系、单位、是否原地修改）才写 `@returns` |
| 文件顶部 | 最多 1 行 `// 用途：xxx。` 已登记的公共工具再补 `见 herness/05-共享上下文/公共工具速查.md` |
| `export type` / `interface` 成员 | 非显然字段加行内注释（坐标系、单位、取值范围、可空语义） |
| 危险逻辑 | 坐标转换、协议收发、生命周期销毁、图层渲染顺序 —— 就近必须注释 |
| 判空 / 收窄 / 兜底 | **不写注释**，一律走 `@/utils` 公共工具，调用处无需解释 |

JSDoc 模板（按需裁剪，不要凑行数）：

```ts
/** 经纬度按 EPSG:4326 处理，返回值不可原地复用（内部会二次纠偏） */
export function wgs84ToGcj02([lng, lat]: LngLat): LngLat

/** 图层编号固定 999：业务依赖「主管队站」始终压在「支撑队站」之上 */
const LEAD_STATION_Z_INDEX = 999
```

## 五、TODO 规范

格式（**三要素缺一即违规，不许进代码**）：

```ts
// TODO(huanghuanrong, 2026-12-01, GIS-1234): 原因 —— 待做什么 —— 何时删
```

| 规则 | 说明 |
|------|------|
| 必须有责任人 | 取 `git config user.name` |
| 必须有清理条件 | 到期未处理就删注释与对应代码 |
| 必须有问题号 | 无 issue 编号说明还没立项，改提 issue 或写进 `herness/04-迭代管理/` |
| 到期处理 | 删除注释和代码，**不留「暂时」「临时」「兼容旧」「先取第一个」等模糊表述** |

## 六、禁止清单（自查直接对照）

- ❌ 注释掉的旧代码 —— git 有历史，需要时 `git log` 查
- ❌ 复述函数名 / 变量名（`// 遍历数组` 紧挨着 `forEach`）
- ❌ 已完成事项清单、版本变迁说明、「改过这里」的日志
- ❌ 与代码不同步的历史说明（代码改了注释没改）
- ❌ 排查过程、聊天记录、调试日志
- ❌ `@Author` / `@Date` / `@LastEditTime` / `@LastEditors` / `@FilePath` 模板头（新增文件不写；存量保持现状）
- ❌ 大段技术方案塞进 JSDoc
- ❌ 与 `herness/**` 已有文档重复的说明
- ❌ `catch {}` 空块不说明原因

## 七、必须写注释的场景

| 场景 | 写什么 | 示例 |
|------|--------|------|
| 坐标系 / 精度陷阱 | 坐标系名 + 为何不能改 | `// 业务层统一 WGS84；GCJ-02 转换只允许在高德模块内做，跨层纠偏会造成百米级偏移` |
| 消息协议契约 | 事件方向 + 唯一出口 | `// 发消息统一走 @/controller/publish，收消息走 useMessageStore().subscribe` |
| 生命周期 / 销毁顺序 | 为何是这个顺序 | `// 先 stop 交互再销毁图层，否则 Draw 会残留交互态` |
| 图层 z-index / 渲染顺序 | 数值依据 | `// 主管队站固定 999，遮挡顺序有业务依赖，见 herness/05-共享上下文/公共工具速查.md` |
| 性能取舍 / 降级策略 | 为什么可以接受误差 | `// 高频轨迹节流到 10Hz，地图端按插值补点；全量推送会打满 WS 带宽` |
| 反直觉的兼容逻辑 | 为什么不能「顺手优化」 | `// 接口仍返回 GCJ-02，此处不做转换，否则与历史图层偏移 300m+` |

## 十、未使用声明的处置规则（TS6133）

> 类型门禁已于 2026-10-22 归零（`lint-baseline.json` = 0 项），**新代码不得再产生 TS6133**。
> 存量死代码的处置**不是「删了了事」**，按下面四类走。

### 10.1 先分清来源

`vue-tsc` 不认注释掉的模板引用，报错常来自三处：

| 来源 | 表现 | 判断方法 |
|------|------|---------|
| HTML 注释里的模板引用 | 变量/方法只被 `<!-- -->` 包裹的模板用 | 在模板里搜变量名，看是否落在注释块内 |
| JS 块注释禁用的功能 | `/* ... */` 整段功能被关掉 | 看变量是否只被块注释代码引用 |
| 只写不读的私有字段 | 字段被赋值但从未被读取 | 搜字段名，除赋值外无读取处 |

### 10.2 四类处置动作

| 类 | 场景 | 动作 |
|----|------|------|
| **A** | 模板 / 功能已注释，声明保留备用 | 保留声明 + `// @ts-expect-error TS6133: 引用处已注释，保留备用`；**对应 import 逐项注释掉，不删除** |
| **B** | 公共文件的备用函数（如 `baseSource.ts` 的备选底图源） | **整个函数块注释掉**（含 JSDoc），保留可恢复性 |
| **C** | 纯死代码（无引用、无注释、无公共价值） | 连带 import 一并注释掉，不直接删 |
| **D** | 只写不读的私有字段 | **必须用 `@ts-expect-error` 豁免，不能注释掉** —— 注释掉仍在被方法引用的字段会立刻引入 TS2339 |

### 10.3 三条硬约束

1. **注释掉的东西不能在另一处被引用**。注释前先全局搜该标识符，确认除被注释的代码外无其他引用。
2. **公共文件（`utils/`、`baseComponent/`、`store/` 等）的未使用导出函数不删**，先按 B 类整体注释掉备用。
3. **`@ts-expect-error` 只用于「已知且已说明」的豁免**，必须紧跟一行原因注释：

```ts
// @ts-expect-error TS6133: 模板功能已注释，变量保留备用
const canStart = computed(() => !!endCoord.value && !isPlanning.value)
```

### 10.4 已验证的 TypeScript 行为

| 写法 | 对未使用的**局部变量** | 对未使用的**函数参数** |
|------|---------------------|---------------------|
| `_` 前缀 | ❌ 无效，仍报 TS6133 | ✅ 有效（TS 对参数有特殊规则） |
| `// @ts-expect-error` | ✅ 有效 | ❌ 无效 |
| `void foo` 消费 | ✅ 有效 | ✅ 有效（保留原名，对外签名不变） |

> 公共导出函数要保留原参数名（如 `createBuildingByFloors(totalFloors, buildHeight)`），
> 用 `void buildHeight` 消费，不要改成 `_buildHeight` —— 会破坏调用方的具名传参可读性。

### 10.5 类型错误的修法优先级

| 类别 | 修法 | 禁止 |
|------|------|------|
| 空值类（TS18047 / TS2532 / TS2531） | **真修**：显式类型标注 + 可选链 + 提前 return 收窄 | ❌ 用 `any` 或 `!` 掩盖 |
| 属性不存在（TS2339） | `instanceof` 收窄 / 类型断言 | ❌ 盲目 `any` |
| 隐式 any（TS7006） | 显式标注参数类型 | ❌ 留空 |
| 参数类型不符（TS2345） | 放宽回调签名以匹配库的真实类型 | ❌ 改调用方迁就库 |

> 真实 API 差异（如 OL10 的 `StyleLike` 只在 `ol/style/Style.js` 导出、不在 `ol/style` 桶导出）
> 必须**改导入路径**，不要用 `any` 绕过。
