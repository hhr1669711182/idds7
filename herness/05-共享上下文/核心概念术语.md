# 核心概念术语

> 业务与系统术语对照表。理解需求文档、`docs/source/**` 与代码注释时查阅。
> 新增业务概念时追加本表（术语 → 代码符号 → 位置 → **禁用词**）。

---

## 零、怎么用这张表

### 0.1 只收「本项目特有的概念」

通用编程概念（超时、错误类型、工具函数模式）**不进**这张表，
即使项目里用得很多。加之前先问：这是**本领域特有的概念**，还是通用编程概念？只有前者才收。

### 0.2 禁用词列（`Avoid`）

同一概念常有多个叫法，用词分裂是多人协作最常见的隐性成本。
发现团队里存在第二种叫法时，写进「禁用词」列并统一。

| 概念 | 禁用词 | 为什么 |
|------|--------|--------|
| 警情 | 事件、Event | `Event` 在本项目指消息事件（`MESSAGE_EVENT_KEY`），混用会让「警情事件」与「消息事件」撞名 |
| 接缝 | 边界、boundary | boundary 在本项目已指「分层边界」，seam 特指「可替换行为的位置」 |
| 深度 | 复杂度 | 复杂度高≠深；深指的是「单位接口承载的行为量」 |
| 宿主系统 | 上游、下游 | 上下游指消息流向，与「承载本 GIS 的主系统」不是一回事 |
| 席位 | 坐席 | 团队口语与代码 `seatNumber` 不一致，统一用「席位」 |

### 0.3 定义写法

- **一句话说清是什么**，不是它做什么
- 有多个叫法时**选定一个**，其余进禁用词列
- 与代码符号对应时写出**真实路径与符号名**，不臆造
