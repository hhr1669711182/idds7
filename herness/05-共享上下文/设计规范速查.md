## 一、分层铁律（来自 src/controller 实际结构）

```
views/components  ──只读 store / 只调 controller 公开方法──▶ 禁止直接 new OlMap / 操作 renderer
        ▼
store（Pinia）    ──业务状态 + 消息中枢──▶ 唯一消息总线是 useMessageStore
        ▼
controller/core/generic    通用图形控制：view / geometry / spatial / kinematic
controller/core/business   业务控制：config / alarm / duty / call / dispatch / tracking / addressRobot
controller/core/io         输入输出控制
controller/core/protocol   协议 DTO 定义（Generic / Business / IO）
controller/publish         对外消息发送门面（controller/map、controller/three 已废弃）
        ▼
plugins/mapPlugins（MapCore + 插件）  ──渲染底座──▶
        ▼
OpenLayers / Three / Cesium
```

| # | 规则 | 违反示例 | 正确做法 |
|---|------|---------|---------|
| 1 | 通用控制层零业务 | `core/generic/**` 里出现 `alarm`/`call`/`dispatch` 判断 | 业务判断放 `core/business/**` |
| 2 | 业务控制层不碰引擎 | `core/business/**` 里 `import OlMap from 'ol/Map'` | 只用注入的 `genericController` |
| 3 | DTO 用 protocol 类型 | 控制器方法写成 `foo(data: any)` 并用 `any` 承接跨层数据 | 入参用 `protocol/GenericProtocol.ts` / `BusinessProtocol.ts` 的 interface |
| 4 | 消息收发唯一出口 | 裸 `new WebSocket(...)`、`window.addEventListener('message')`，或业务代码裸调 `store.publish` | 发送走 `@/controller/publish` 的 `publishXxx`；接收走 `useMessageStore().subscribe` |
| 5 | 新控制器登记 | 新建 `XxxController.ts` 不导出 | 在所属 `index.ts` `export *`，并回写项目结构速查 |
| 6 | 视图不越层 | view 里直接 `map.addLayer(...)` / `new OlMap()` | 经 controller 或 plugins/mapPlugins |

## 四、编码约定

| 约定 | 规则 |
|------|------|
| 语言特性 | TS `strict`，禁止 `any` 作为跨层 DTO；确需 `any` 用 `unknown` + 收窄或 `Record<string, unknown>` |
| 未用变量 | `noUnusedLocals` / `noUnusedParameters` 开启，**不留无用变量**（会直接报错） |
| 常量 | 用 `as const`；集中放 `src/const/**`，不散落在组件里 |
| 环境变量 | 只经 `src/config/env.ts` 的 `appEnv` 读，不直接 `import.meta.env`（除 env.ts 内部） |
| 类型定义 | 跨层 DTO 放 `controller/core/protocol/`；组件 prop 类型可放同目录 `types.ts` |
| 命名 | Store：`useXxxStore`；方法：`xxxMethod` 或语义化动词；常量：大写下划线对象 |
| 注释 | 中文注释优先；解释"为什么"而非"做了什么"；细则见「四·之一」 |
| 引用路径 | 用 `@/` 别名指向 `src/`（vite 与 tsconfig 均已配） |

## 四·之一、存量兼容与新增代码规范（🟡 新增 · 2026-10-16 定版）

> **总原则：存量不改，新增从新。** 本项目格式化与检查工具**当前均未接入**（见本节第 5 条），
> 条款靠人工遵守；工具一旦接入即自动变成机检项。
> **禁止**借「规范化」名义对存量文件做全量格式化、注释重写或重构——会产生大量无关 diff。

### 1. 代码格式

| 对象 | 规则 |
|------|------|
| **存量文件** | 保持现状。改动时**跟随所在文件既有风格**（该文件用分号就带分号、用双引号就沿用双引号），不做顺手格式化 |
| **新增文件** | 统一按 `.prettierrc.json` 基线：单引号、无分号、2 空格缩进、行宽 120、`trailingComma: all`、箭头函数带括号 |
| 新增文件头注释 | 允许且建议保留 `@Author` / `@Date` / `@Description` / `@FilePath` 头注释块（与历史文件一致）；**已有文件的既有头注释不得删除或改写** |
| 存量头注释 | 历史 `@Author` / `@Date` 块**保持现状，不清理、不改写、不删除**；需要时可在其下**追加**新的说明块 |
| 行尾/缩进 | 跟随 `.editorconfig`（当前为注释态，启用后生效）；Windows 本地 `core.autocrlf=true`，行尾由 git 处理，**不要手工改行尾** |
| 格式化范围 | 单次改动只格式化**本次触及的行**，不整文件重排 |

### 2. 注释规范

| 规则 | 反例 | 正确做法 |
|------|------|--------|
| 只写「为什么」，不复述代码 | `// 给 headers 赋值` | `// 无有效 token 时不写凭证头，避免 401 噪声` |
| 注释掉的代码块：存量保留，新增不写 | `// if (token) { headers[...] = ... }` | 存量注释代码**保持现状**（不强制清理）；新写代码不得留注释掉的代码块，git 已保存历史，需要时用 git 查（src 下现存 29 处） |
| 公开导出必须有 JSDoc | 无注释的 `export const` | `/** 用途一句话；@param/返回值有特殊约定才写 */` |
| 内部私有函数可无注释 | 每个小函数都加注释 | 只在「逻辑反直觉」「有前置约束」时注释 |
| 注释不承诺未验证的事 | `// 修复了 XX bug` | 写清约束或引用 issue/文档，不写无法验证的结论 |

### 3. 数据校验与判空收口

**判空、类型收窄、默认值兜底一律走公共工具，禁止在业务里重复手写。**

```ts
// ✗ 每个文件各写一遍
typeof v === 'string' && v.trim() ? v : null
if (x !== null && typeof x === 'object' && !Array.isArray(x)) { ... }
try { return JSON.parse(raw) } catch { return null }

// ✓ 统一从 @/utils 收口
isObject(v) / isNonEmptyString(v) / safeJsonParse(raw, fallback)
```

| 需求 | 落位 |
|------|------|
| 类型守卫（`isObject` / `isNonEmptyString` / `isFiniteNumber` / 数组判空） | `src/utils/guards.ts`（**待建**，见状态摘要登记项） |
| JSON 安全解析 | 同上的 `safeJsonParse` |
| 数值/字符串兜底转换 | 同上；避免散落 `Number(x ?? 0)`、`x ?? ''`（src 下 `Number(` 149 处、`?? ''` 122 处） |
| 业务语义投影 | `src/utils/seatSharedState.ts` 等业务专属纯函数，**不放 guards** |

> **落位边界**：`utils/guards.ts` 只放**无业务语义**的通用收窄；
> 带业务含义的判断（如「有效 dispatch = inquiry + 有效 incidentId」）仍属业务专属纯函数，不许塞进 guards。

### 4. 已有 hooks / 工具函数的改动约束

| 规则 | 说明 |
|------|------|
| **补充式修改优先** | 新增能力用新增参数/新增导出实现，不改已有签名语义、不重排已有代码 |
| **不动存量注释与格式** | 已实现的 hooks/工具，注释措辞、代码顺序、格式保持原样；确需修正文案时单独 MR 说明 |
| **不夹带重构** | 修 bug 的 diff 里不许出现「顺手重命名 / 顺手抽象 / 顺手升级依赖」 |
| **公共工具演进走回写** | 签名或语义变化时同步 `公共工具速查.md`；破坏性变更需在技术方案里列迁移清单 |
| **快照型工具保持纯函数** | `utils/` 下接收快照做转换的工具保持**零 store 依赖**；需要读 store 的订阅器另立文件（如 `utils/sharedStateWatch.ts`），避免 utils ↔ store 循环引用 |

### 5. 工具现状（⚠️ 当前均不执行）

| 文件 | 内容 | 现状 |
|------|------|------|
| `.prettierrc.json` | 代码格式基线（单引号 / 无分号 / 2 空格 / 120 列） | 备用，**未安装 prettier，不执行** |
| `.eslintrc.json` | `no-console` / `no-debugger` / `eqeqeq` / `prefer-const` / `no-var` | 备用，**未安装 eslint，不执行**；ESLint 9+ 需迁移 flat config |
| `.editorconfig` | 行尾 / 缩进 / 末行换行 | **全部注释掉，不生效**（编辑器会自动读取，未注释会立即影响新建文件） |

`pnpm lint` 仍是 `vue-tsc --noEmit`（**类型门禁，不检查格式**）。启用上述工具需单独技术方案 + 装包，届时删除本节的「不生效」说明。

## 四·之二、通用工程限制（🟡 新增 · 2026-10-16 定版）

| # | 规则 | 理由 / 实测依据 |
|---|------|----------------|
| A | **无死代码** | 不留注释掉的代码块（存量 29 处保留不清理）、不留裸 `console.log`（存量 49 处保留）。git 已保存历史，注释代码只是噪音。**历史遗留不强制清理，但新写代码不得引入** |
| B | **无静默吞异常** | 新写的 `catch {}` 空块必须注释说明为何可忽略；可预期失败走返回值 / `null` / `AppError`，不可预期走 `createLogger(ns).error`。新写代码禁止裸 `console.*`（存量 `console.log` 49 处、`warn/error` 97 处不追溯） |
| C | **改逻辑必改测试** | 行为变更需有对应用例并跑 `pnpm test`；新增共享工具必须补单测。回归类修改建议留红→绿证据（回退实现看用例失败） |
| D | **diff 自审（禁止夹带）** | 单次改动不夹带无关重构、不顺手格式化、不顺手改存量注释措辞、不升级无关依赖。发现历史问题**登记到 `当前状态摘要.md`**，不在本次 diff 里顺手修 |
| E | **新增依赖需授权** | 新增 npm 包必须在技术方案说明用途 / 体积 / 替代方案，并获确认；优先复用现有依赖 |
| F | **`any` 预算制（只减不增）** | 沿用 lint 基线思路：跨层 DTO 禁用 `any`（必须用 `controller/core/protocol/**` interface）；存量 `any`（src 下约 271 处）**不强制清理**，但新写代码不得引入 |
| G | **公共工具去重登记** | 新增通用收窄 / 转换工具前先 `rg` 搜是否已有同类实现；确需新建时在 `当前状态摘要.md` 登记（待收敛项），并在方案里写明与现有工具的关系 |

### 环境配置（env）中转规则

**所有配置值一律经 `src/config/env.ts` 的 `appEnv` 中转分发，业务代码不直接读 `import.meta.env`。**

| 类别 | 落位 | 规则 |
|------|------|------|
| 服务地址 / 开关 / clientId | `appEnv.xxx`（`VITE_` 前缀） | 现有 20+ 项已收口，新增沿用；未配置时给安全兜底，不写死 |
| **各类配置值（含调试凭证）** | 对应环境的 `.env.*` → `appEnv` 读取 | 一律走 env 配置，**不写进源码**。原先硬编码在 `alova.ts` 的 token 类配置已迁至 env 读取 |

> **敏感判断 = 人工决定，是否删除由人工自行处理。** 本规范**不代替人工判定某值是否敏感**：
> 生成配置时按需写入各环境 `.env.*` 并保持同步，**由人工判断是否需要删除/替换**；
> AI 不得自动扫描、删除或改写既有配置项，也不得凭猜测把配置判为「必须删除」。

### 机检门禁（⏸ 暂不实施 · 团队决策）

把 A/B/F 变成可执行检查（新增 `scripts/check-code-convention.mjs` 并入 `pnpm harness:check`）能给出拦截力而非靠自觉，**但需先定阈值**（如 `console.log` 基线数记为 N，只减不增），属需额外 MR 的改动，**当前按团队决策暂不实施**。

## 五、地图/空间数据约定

| 约定 | 说明 |
|------|------|
| 坐标系 | 协议层与服务层统一 **WGS84** `[longitude, latitude]`；进入渲染层前由底座转换（见 `utils/coordTransform.ts`、`baseComponent/amap/amapCoordinate.ts`） |
| 坐标顺序 | 协议 `lngLat` / `coordinates` 为 `[经度, 纬度]`；OpenLayers 内部为 `[经度, 纬度]`，投影在图层配置中声明 |
| 要素 ID | 业务图元需带业务前缀（`aoi_res_`、`zone_` 等现有约定见 `CallController`），新增沿用可辨识前缀 |
| Auto-Fit | `view.fitBounds` 应保留 padding 留边，不贴边（现有代码部分传 `padding`，调用时按需补齐） |
| 高频数据 | 车辆 GPS / 轨迹等高频流走 Web Worker（参考 `baseComponent/amap/routeMetrics.worker.ts`、`hooks/useRouteMetricsWorker.ts`） |
| 图层管理 | 图层源配置集中在 `src/config/layers.ts`；运行时三层（组/分类/资源）结构在 `src/config/mapConfig.ts`，勿在组件里另造图层清单 |

## 六、消息与协议约定

| 约定 | 说明 |
|------|------|
| 事件键唯一 | 事件键集中在 `src/const/const.message.type.ts` 的 `MESSAGE_EVENT_KEY`；**新增必须同步 `docs/source/07-协议事件清单.md`** |
| DTO 同步 | 新增/修改跨系统 DTO 必须同步 `docs/source/协议层DTO Schema.tsd` |
| 协议版本 | `MESSAGE_PROTOCOL_VERSION = '1.0.0'`；破坏性变更需升版本并评估兼容 |
| 收发解耦 | 发消息统一 `@/controller/publish` 的 `publishXxx`（**按 `MESSAGE_SYSTEM` 分类到 map/host/three 等文件，system+channel 在文件内固定**，详见 [消息协议速查](消息协议速查.md)「publish 发送规范」）；收消息统一 `useMessageStore().subscribe(KEY, handler)`，返回取消订阅函数，组件在 `onUnmounted` 取消。**controller/map、controller/three 已废弃，不得复活** |
| 拦截器归一 | 消息体归一只在 `interceptor/unwrap.ts`；业务拦截器只做数据归一，不重复解包 |
| 分发模式 | `subscribe.dispatch === 'multi'`（SEAT 泛订阅）时 transform 返回 `results[]` 二次分发；`single` 返回单条 |
| 优先级 | 拦截器按 `priority` 升序执行（seat 150 / alarm 等 200），`stop: true` 可中断链路 |

## 七、HTTP 与错误处理约定

| 约定 | 说明 |
|------|------|
| 统一实例 | 所有请求经 `alovaInstance` / `http` / `src/service/methods/**`，不裸 `fetch` / `XMLHttpRequest` |
| 错误类型 | 统一 `AppError` / `ERROR_CODES` / `toAppError`（`src/service/error.ts`），不自定义错误体系 |
| 静默错误 | 需要静默的请求在 config 里设 `meta: { silent: true }` 或 `showError: false` |
| 业务方法 | 新接口在 `src/service/methods/**` 加 `xxxMethod`，参数/响应类型进 `methods/types.ts` |
| Token | token 由 `beforeRequest` 统一注入，业务代码不手动加 Authorization |

## 八、状态管理约定

| 约定 | 说明 |
|------|------|
| Store 写法 | `defineStore` setup 风格（现有 store 均为 setup 写法），保持一致 |
| 持久化 | 用 `piniaPersist.ts` 的封装配置 `persist`，不散写 localStorage（地图配置 `mapConfig.ts` 的 localStorage 是既有例外） |
