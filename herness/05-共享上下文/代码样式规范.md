# 代码样式规范（CSS / Less）

> **适用范围**：本项目所有样式代码（`src/**/*.vue` 的 `<style>` 段、`src/**/*.less`）。
> **核心目标**：**默认适配系统主题**，新增样式不需要再写一遍夜间覆盖。

---

## 一、三层结构（不可越层）

```
tokens.less      设计常量（与主题无关）：颜色、间距、圆角、阴影
   ↓ 引用
palettes.less    调色盘：每个主题/预设盘是一组 CSS 变量
   ↓ 派生
组件样式          只消费 var(--token)，不出现裸色值
```

| 层 | 文件 | 允许出现 |
|----|------|---------|
| 设计常量 | `src/styles/tokens.less` | 裸色值、间距、圆角、阴影 |
| 调色盘 | `src/styles/palettes.less` | 只允许引用 tokens 的常量 + 少量预设盘覆盖值 |
| 组件样式 | `src/**/*.vue` / `src/**/*.less` | **只允许 `var(--token)`** |

**反例**（组件里写死颜色，夜间必然不匹配）：

```less
.locate-btn {
  background: rgba(255, 122, 0, 0.15);
  border: 1px solid #ff7a00;
  color: #ff7a00;
}
```

**正例**：

```less
.locate-btn {
  background: var(--ma-orange-soft);
  border: 1px solid var(--ma-orange);
  color: var(--ma-orange);
}
```

## 二、主题与调色盘

### 2.1 两个正交的切换维度

| 维度 | 属性 | 取值 | 用途 |
|------|------|------|------|
| **主题** | `document.documentElement[data-theme]` | `DAY` / `NIGHT` | 整体明暗 |
| **调色盘** | `document.documentElement[data-palette]` | `DAY` / `NIGHT` / `OCEAN` / `EMBER` / `CUSTOM` | 主色与色调 |

两者都只改根元素属性，**业务代码零改动**即自动生效。

### 2.2 优先级

```
:root[data-palette='CUSTOM']  ← 最高（inline style 覆盖）
  ↓
:root[data-palette='OCEAN'|'EMBER'|'DAY'|'NIGHT']  ← 预设盘覆盖
  ↓
:root[data-theme='NIGHT'|'DAY']  ← 主题默认盘
```

### 2.3 底图瓦片滤镜

地图底图色感由 `context.filter` 控制，参数已参数化并挂在 CSS 变量上：

| 变量 | 含义 | 默认（NIGHT） |
|------|------|-------------|
| `--filter-hue-rotate` | 色相旋转 | `180deg` |
| `--filter-invert` | 反相 | `100%` |
| `--filter-saturate` | 饱和度 | `1600%` |
| `--filter-brightness` | 亮度 | `80%` |
| `--filter-contrast` | 对比度 | `90%` |

取值统一走 `src/utils/themeColor.ts`：

```ts
import { buildFilterString, getBasemapFilter } from '@/utils/themeColor.ts'

context.filter = buildFilterString(getBasemapFilter())
```

**禁止**在业务代码里再手写 `context.filter = 'grayscale(...) invert(...)'` 字符串。

## 三、Less 优先（本项目默认样式语言）

> **本项目样式一律用 Less，不用原生 CSS、不用 SCSS/Sass、不用 Tailwind 原子类。**
> 理由：Less 与 Vite 深度集成、支持 `additionalData` 全局注入、能编译期做 mixin/函数/变量计算。

### 3.0.1 何时用 Less，何时用 CSS 变量（关键区分）

| 需求 | 用什么 | 例子 |
|------|--------|------|
| **与主题无关**的设计常量（圆角、间距、阴影） | Less 变量 `@panel-radius` + 同时导出 CSS 变量 `--radius-md` | 见 3.0.4 |
| **随主题/调色盘变化**的颜色 | **CSS 变量** `var(--accent-cyan)` | 组件里 90% 的场景 |
| 颜色运算（加深、变透明、混合） | `color-mix(in srgb, var(--x) N%, transparent)` | 不要手写 rgba |
| 一次定义、多处复用且带条件分支 | Less **mixin** | 见 3.0.3 |
| 单个文件内的计算值 | Less **函数**（带参） | 见 3.0.3 |

**铁律：Less 变量不能被 `var()` 消费。**
写成 `@radius-md: 8px` 的东西，`var(--radius-md)` **取不到值**，
浏览器会回退成 invalid —— 表现为 `border-radius` 消失、颜色变透明。
Less 编译期、构建、lint **都不报错**，只能靠核验产物发现。

### 3.0.2 变量命名与作用域

```less
// ✅ Less 变量：语义化命名，避免与 CSS 变量同名
@panel-radius: 12px;
@toolbar-gap: 5px;

// ❌ 禁止：与 CSS 变量同名同拼写（极易误以为可被 var() 消费）
@radius-md: 8px;   // 与 --radius-md 撞名
```

- Less 变量用 `@` 前缀，CSS 变量用 `--` 前缀，**不要重名**。
- 跨文件共享的 Less 变量放 `src/styles/tokens.less`（设计常量层）。
- 组件内私有变量写在组件 `<style>` 块顶部，**只在本文件有效**。

### 3.0.3 mixin 与函数：用于消灭重复，不是用于炫技

```less
// ✅ 参数化 mixin：同类结构多处复用时提取
.flex-center() {
  display: flex;
  align-items: center;
  justify-content: center;
}

// ✅ 默认参数 + 可覆盖
.card(@radius: var(--radius-lg)) {
  border-radius: @radius;
  background: var(--panel-bg);
}

// ✅ 用法
.toolbar { .flex-center(); .card(); }
.legend  { .card(var(--radius-sm)); }
```

| 规则 | 说明 |
|------|------|
| mixin 名用小写短横线 | 与 CSS 类名区分 |
| 允许默认参数 | 调用方不必全部覆盖 |
| **禁止**超过 3 个参数 | 参数过多说明抽象错了 |
| **禁止**在 mixin 里写业务语义 | mixin 只管样式形状 |
| 参数默认值**优先用 `var(--token)`** | 这样 mixin 产物自动适配主题 |

### 3.0.4 「Less 变量 + CSS 变量」双写模式（推荐）

`src/styles/tokens.less` 里的常量，**同时**在 `palettes.less` 的 `:root` 块导出 CSS 变量：

```less
/* tokens.less —— 设计常量层 */
@radius-md: 8px;
@space-md: 12px;
```

```less
/* palettes.less —— 调色盘层 */
:root {
  --radius-md: 8px;   /* 与 @radius-md 保持同值 */
  --space-md: 12px;
}
```

组件里**只写 `var(--radius-md)`**，不写 `@radius-md`。
这样：

- 组件样式自动跟随主题/调色盘；
- Less 侧仍可在编译期做运算（`@radius-md * 2`）；
- `check-css-vars.mjs` 能扫到变量缺失。

> ⚠️ **两处值必须完全一致**。双写漂移不报任何错（编译通过、运行正常、只是实际值与设计值差一点点），
> 实测出现过 `@weather-panel-width: 288px` 与 `--weather-panel-width: 300px` 漂移 12px 的事故。
> `check-css-vars.mjs` 已内置**双写一致性检查**（比对 `tokens.less` 的 `@name` ↔ `palettes.less`
> 顶层 `:root` 的 `--name`），漂移即阻断。详见 §4.7。

**自检**：`node scripts/check-css-vars.mjs`（已挂 `pnpm harness:check`）。

### 3.0.5 引用与导入

| 场景 | 写法 | 说明 |
|------|------|------|
| 组件内引用设计常量 | `@import (reference) '@/styles/tokens.less';` | `reference` 只取变量不输出样式 |
| 全局样式入口 | `src/styles/index.less` 统一 `@import` | 顺序即层叠顺序 |
| Vite 全局注入 | `vite.config.ts` 的 `additionalData` | 已注入 `variables.module.less` |

> `@import` 在 Less 4 已标记为过时，**但本项目统一用 `@import`**：
> `@use` 有命名空间隔离，与本项目「全局变量直接可用」的既有写法冲突，
> 迁移需单独立项，不要在业务需求里顺手改。

### 3.0.6 嵌套深度与选择器

| 规则 | 上限 | 说明 |
|------|------|------|
| 嵌套深度 | **3 层** | 超过就提取成独立类或 mixin |
| `&` 使用 | 允许 | `&:hover` / `&.active` |
| 选择器拼接 | 少用 | 生成的 CSS 体积大、命中路径长 |

```less
// ✅ 3 层以内
.tile {
  &:hover { background: var(--toolbar-tile-hover-bg); }
  &.checked { border-color: var(--toolbar-tile-active-border); }
}
```

### 3.0.7 BEM 命名

本项目组件内类名**保持既有风格**（各模块自有约定，如 `.weather_panel__city_text`、`.md-tool--primary`），
新建公共样式建议 BEM：

```less
.block { }              // 块
.block__element { }     // 元素
.block--modifier { }    // 修饰
```

## 四、组件样式写法

### 4.1 硬规则

| # | 规则 | 反例 | 正确做法 |
|---|------|------|---------|
| 1 | **禁止裸色值** | `color: #e6ebf5` | `color: var(--text-primary)` |
| 2 | **禁止 `html[data-theme='NIGHT']` 覆盖块** | 同一属性写两遍 | 用变量一份搞定 |
| 3 | 圆角走变量 | `border-radius: 8px` | `border-radius: var(--radius-md)` |
| 4 | 阴影走变量 | `box-shadow: 0 8px 28px rgba(0,0,0,.45)` | `box-shadow: var(--panel-shadow)` |
| 5 | 间距走变量 | `padding: 12px` | `padding: var(--space-md)` |
| 6 | 毛玻璃强度走变量 | `backdrop-filter: blur(8px)` | `backdrop-filter: blur(var(--glass-blur))` |
| 7 | 需要半透明派生时用 `color-mix` | `rgba(0,0,0,.12)` | `color-mix(in srgb, #000 12%, transparent)` |
| 8 | Element Plus 组件只调 `--el-*` | 覆盖 `.el-button` 的 background | 改 `--el-color-primary` 等变量 |

### 4.2 变量必须真的定义（高频踩坑）

**Less 变量 ≠ CSS 变量。** 写成 `@radius-md: 8px` 的东西，`var(--radius-md)` **取不到**，
浏览器会回退成无效值 —— 表现为 `border-radius` 消失、颜色变透明。

| 场景 | 定义位置 | 写法 |
|------|---------|------|
| 与主题无关（圆角 / 间距） | `src/styles/palettes.less` 的 `:root` 块 | `--radius-md: 8px;` |
| 随主题变化（颜色等） | `:root[data-theme='NIGHT']` / `[data-theme='DAY']` 块 | `--accent-cyan: @cyan-500;` |

**自检**：`node scripts/check-css-vars.mjs`（已挂进 `pnpm harness:check`）——
扫描全项目 `var(--x)` 引用，报告未定义的变量。

### 4.3 毛玻璃（Lightning CSS 前缀去重坑 · 已实测）

毛玻璃是本项目地图面板的默认质感，**必须保留**：

```less
.my-panel {
  background: var(--glass-bg);
  border: 1px solid var(--panel-border);
  border-radius: var(--radius-md);
  box-shadow: var(--panel-shadow);
  backdrop-filter: blur(var(--glass-blur));
}
```

> **只写 plain 的 `backdrop-filter`，不要写 `-webkit-backdrop-filter`。**

**为什么（2026-10-20 实测结论）**：

1. Vite 8 的 CSS 压缩走 Lightning CSS。当同一条规则里同时写
   `backdrop-filter` 与 `-webkit-backdrop-filter`（**且 plain 在后**）时，
   Lightning CSS 判定二者等价，**只保留 `-webkit-` 那一份**。
2. Chrome 实测：只有 `-webkit-backdrop-filter` 时，
   `getComputedStyle(el).backdropFilter` 返回 **`"none"`** —— 毛玻璃彻底失效。
3. 只有 plain 版本时，计算值正常返回 `blur(8px)`，毛玻璃生效。

**症状 → 原因对照**：

| 症状 | 原因 |
|------|------|
| 毛玻璃在 dev 正常、prod 构建后失效 | 产物只剩 `-webkit-` 版本 |
| 圆角 / 边框消失 | `var(--radius-md)` 引用了不存在的变量（Less 变量 ≠ CSS 变量） |
| 编译、lint、运行时均无报错 | 两类问题都是**产物期**才暴露 |

**自检**：`node scripts/check-backdrop-filter.mjs`（已挂 `pnpm harness:check`）
—— 扫描全项目 `-webkit-backdrop-filter` 残留。

> 补充：Lightning CSS 会**自动**为 plain 版本补 `-webkit-` 前缀（按目标浏览器），
> 所以源码里不需要手写前缀；手写反而会触发去重逻辑把自己坑掉。

### 4.4 透明度派生

需要从主题色派生半透明时，**用 `color-mix`**，不要手写 rgba：

```less
/* ✅ 跟随主题色 */
background: color-mix(in srgb, var(--accent-cyan) 15%, transparent);

/* ❌ 写死，跟主题走 */
background: rgba(34, 211, 238, 0.15);
```

### 4.5 OpenLayers 控件样式唯一真源（2026-10-21 立规）

**真源文件**：`src/styles/ol-controls.less`（全局，由 `src/styles/index.less` 引入）。

| 位置 | 允许写什么 | 禁止写什么 |
|------|-----------|-----------|
| `src/styles/ol-controls.less` | 控件**外观**（底色/描边/圆角/投影/字号）+ 通用尺寸 + 通用位置 + 移动端 | —— |
| 页面组件（`*.vue` / `map.less`） | 仅**位置**（`left` / `bottom` / `top` / `right` / `z-index`） | 底色、描边、圆角、投影、字号等**外观**属性 |

历史事故（本条规则的由来）：

- OL 样式一度散落在 **4 个文件 5 处副本**（`map.less` / `dispatchMap.vue` / `markDraw/index.vue` / `style.css`），
  同一控件在不同页面各长各的（实测 `.ol-control` 底色四种：`rgb(13,25,41)` / `rgba(255,255,255,.8)` / `rgba(10,22,40,.82)`）。
- `.ol-overviewmap` 容器加了 `overflow: hidden` → **鹰眼缩略图整块消失**（容器是 0 尺寸定位盒，
  缩略图被 `position:absolute` 抽出不撑开父级，裁剪盒把 180×120 缩略图裁没，只剩 2×2 边框残影）。
- `style.css` 移动端 media query 里 `.ol-control { background-color: ... !important }` 压过主题变量，
  夜间主题下控件发白。

**写 OL 控件样式前必查**：

1. 先翻 `src/styles/ol-controls.less`，能复用的直接复用，不要在页面里重写。
2. 只有**位置**确实因页面而异时，才在页面里加**带 id 限定**的覆盖（推荐 `#dispatch-map .ol-scale-line`），
   避免无 id 的全局选择器污染其它页面。
3. `ol-controls.less` 是全局文件，**不要写 `:global()`**（那是 scoped 块专用）；页面里写 `:global(...)` 才是。
4. 移动端用 `.is-mobile` 前缀（该类挂在**地图容器**上，不是 `body`）。

**0 尺寸定位盒的坑**：OL 有几个控件容器本身没有宽高（`.ol-overviewmap` 容器、折叠态 `.ol-attribution`），
   它们靠子元素绝对定位撑出视觉。**这类容器禁止加 `overflow` / `border` / `background` / `box-shadow`**，
   否则子元素被裁没或留下边框残影。视觉样式要落在真正的子元素上（如 `.ol-overviewmap-map`）。

### 4.6 同一视觉簇的位置必须常量推导（2026-10-21 立规）

**同一屏内互相挨着的元素（按钮簇、工具条、面板组），位置不能各写各的 `right`/`top` 魔法数字。**

历史事故：地图页右上角的**天气面板 + 主题开关 + 功能配置 + 调色盘**四件套，
分别散落在 4 个文件里各写各的 `right`（`340px` / `300px` / `266px` / `0.5em`），
间距 40px 与 34px 不等、`top` 有 10px 与 15px 两套。
结果：天气面板宽度一改就横向压住入口按钮（`z-index:60` 盖 `z-index:5`），
用户看到「config 入口按钮丢失」。

**规则**：

| 要求 | 做法 |
|------|------|
| 位置常量集中定义 | 放 `src/styles/tokens.less`，并在 `src/styles/palettes.less` 的 `:root` 导出同名 CSS 变量 |
| 组件只消费变量 | `right: calc(var(--top-actions-right) + var(--weather-panel-width) + var(--top-actions-gap))` |
| 宽度要有基准 | 同一簇里宽度不定长的元素（面板）用**固定宽度 + 省略号截断**，保证簇的位置恒定 |
| 纵向对齐到中心线 | 高度不同的元素统一对齐到 `--top-actions-center`，各自用 `calc(中心线 - 自身高度/2)` 居中 |
| z-index 拉齐 | 同一簇的入口按钮 z-index 必须同级，否则会被 z-index 高的兄弟节点压住 |

> 这条与 §4.5「OL 控件样式唯一真源」是**同一条原则的两个实例**：
> 凡是「多处各写一份」的定位/外观，都会因某次单点改动而互相冲突。

### 4.7 Less 变量与 CSS 变量「双写一致性」

项目约定：同一常量在 src/styles/tokens.less 写 Less 变量（供 Less 内部 calc() 引用），
在 src/styles/palettes.less 的**顶层 :root** 写同名 CSS 变量（供组件 ar() 消费）。
**两处值必须完全一致。**

**为什么这是铁律**：双写一旦漂移，编译不报错、运行也正常，只是实际生效值与设计值不一致。
真实事故：@weather-panel-width: 288px（tokens）与 --weather-panel-width: 300px（palettes）
漂移 12px，天气面板左边缘比设计位置右移，与右上角按钮簇的对齐关系被悄悄破坏 ——
肉眼看「好像有点歪」，但没有任何报错能指向它。

**门禁**：
ode scripts/check-css-vars.mjs 会自动比对两处值，不一致即报告并阻断。

| 事项 | 要求 |
|------|------|
| 比对范围 | 	okens.less 的 @name ↔ palettes.less **首个顶层 :root 块**的 --name |
| 主题覆盖值 | :root[data-theme='NIGHT'] 等块内的值**不算漂移**（随主题变化是设计意图） |
| 断点覆盖值 | @media 内的 :root 值**不算漂移**（响应式是设计意图） |
| 新增常量 | 两处必须同时写；只写一处会被 css-vars 门禁拦下 |

> 写完常量后跑一次 pnpm lint:css-vars 确认没有漂移。

### 4.8 模块 token（模型研判）

`--ma-*` 系列（`--ma-bg` `--ma-border` `--ma-orange` `--ma-text` …）定义在 `palettes.less`，仅模型研判模块使用。

## 六、新增组件的样式自检

```bash
# 1. 检查新文件是否有裸色值
rg -n "#[0-9a-fA-F]{3,8}|rgba?\(" src/新文件.vue

# 2. 检查是否写了夜间覆盖块（应改为变量）
rg -n "data-theme" src/新文件.vue

# 3. 检查 CSS 变量引用是否有定义（Less 变量 ≠ CSS 变量）
node scripts/check-css-vars.mjs

# 4. 检查 backdrop-filter 是否误写了 -webkit- 前缀
node scripts/check-backdrop-filter.mjs
```

| 检查项 | 通过标准 |
|--------|---------|
| 裸色值 | 0 处（纯 3D 场景材质、图标、渐变色标除外，需注释说明） |
| `data-theme` 覆盖块 | 0 处 |
| 圆角 / 阴影 / 间距 | 全部走变量 |
| 毛玻璃面板 | 只写 `backdrop-filter`（**不要**加 `-webkit-` 前缀） |
| 深浅两态 | 只改变量即可正确切换，不需改组件结构 |

## 八、与注释规范的关系

样式注释同样受 `代码注释规范.md` 约束：**解释「为什么」，不解释「做了什么」**。

```less
/* ✅ 说明这个覆盖为什么存在 */
.route-op-bar {
  /* 浮层压在 3D 画布上，需要半透明底才能看清路径 */
  background: var(--panel-bg);
}

/* ❌ 复述代码 */
.route-op-bar {
  /* 路由操作栏 */
  background: var(--panel-bg);
}
```
