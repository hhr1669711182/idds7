# 05-共享上下文

> AI 接手任务时的"第一口"上下文。本目录回答三个问题：**这是什么项目 / 代码在哪 / 怎么写才对**。

## 文件列表

| 文件 | 回答什么问题 | AI 何时读 |
|------|------------|----------|
| [项目结构速查.md](项目结构速查.md) | 代码在哪一层、改哪个目录 | **任何编码任务必读** |
| [技术栈速查.md](技术栈速查.md) | 用的什么技术、怎么跑起来 | 首次了解 / 涉及构建 |
| [核心概念术语.md](核心概念术语.md) | 业务在说什么 | 理解需求与业务逻辑 |
| [设计规范速查.md](设计规范速查.md) | 怎么写才符合规范 | **编码前硬门禁** |
| [消息协议速查.md](消息协议速查.md) | 跨系统消息怎么收发 | 涉及 WS / postMessage / 控制器 |
| [当前状态摘要.md](当前状态摘要.md) | 项目现在到哪了 | 每次接手任务 |

## AI 工作流

```
接到任务
  ↓
1. 读 00-SOP.md                     【强制】
2. 读 项目结构速查.md               定位改动落点
3. 读 设计规范速查.md               确认写法合规
4. 读 当前状态摘要.md               了解项目状态
5. 按任务类型追加：术语 / 协议 / 技术栈
  ↓
开始工作
  ↓
任务完成 → 回写 00-SOP.md 工作日志；新增文档更新对应 _index.md
```

## 维护责任

- **项目结构速查**：新增/删除顶层目录、控制器、store 时更新
- **技术栈速查**：`package.json` 依赖或 `vite.config.ts` 变更时更新
- **核心概念术语**：产品新增业务概念时更新
- **设计规范速查**：规范演进时更新（由技术负责人）
- **消息协议速查**：`const.message.type.ts` 或 `controller/core/protocol/**` 变更时更新
- **当前状态摘要**：迭代负责人每周更新
