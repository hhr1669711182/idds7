## 二、应用入口与装配

| 路径 | 职责 |
|------|------|
| `src/main.ts` | 应用入口，仅调用 `mountApp()` |
| `src/lib/index.ts` | **库模式装配函数** `mountApp()`：创建 app、装 Pinia（带持久化）、装 Router、注册 `drag` 指令、可选注入 `hostEmitter`、挂载 DOM |
| `src/App.vue` | 根组件 |
| `src/layout/` | 布局（`MainLayout.vue` 等） |
| `src/types/auto-imports.d.ts` / `components.d.ts` | **自动生成**，勿手改 |

> 双形态说明：`pnpm dev` 走应用形态；`pnpm build:lib` 以 `src/lib/index.ts` 为入口产出库（`dist-lib/`），供宿主项目通过 `mountApp` 挂载，并 `export * from '@/plugins/mapPlugins'` / `plugins/crypto` 对外暴露能力。

## 五、命名与文件约定

| 约定 | 说明 |
|------|------|
| 目录 | 业务域 kebab-case 或 camelCase（现存两种：`MarkDraw` / `AddressRobotDrawer` 为 PascalCase，其余多为 camelCase/kebab） |
| 组件 | `.vue` 文件多为小写短语（`map.vue`、`home.vue`）或 PascalCase（`MainLayout.vue`、`WeatherPanel.vue`）——**按同目录既有风格走** |
| Store | `useXxxStore.ts`，id 与文件名对应（`'messageStore'` 等） |
| 常量 | `const.xxx.ts` 或 `const/xxx.ts`，`as const` 结尾 |
| 类型 | `types.ts` 或 `xxx.d.ts`；跨层 DTO 放 `controller/core/protocol/` |
| 方法文件 | `xxx.ts`，导出 `xxxMethod` 或语义化函数名 |

## 六、易踩的坑

| 坑 | 正确做法 |
|----|---------|
| 手改 `types/auto-imports.d.ts`、`types/components.d.ts` | ❌ 自动生成，勿改；由 `vite.config.ts` 的 AutoImport/Components 插件产出 |
| 以为有 ESLint | ❌ `pnpm lint` 实际是 `vue-tsc --noEmit`（**类型**检查，非 lint 风格） |
| 以为有 `pnpm test` | ❌ 无测试脚本与框架；`tests/**` 是遗留脚本，需自备 runner |
| 在业务控制器里 `import 'ol/...'` | ❌ 越层；业务控制器只调 `this.genericController.*` |
| 裸 `new WebSocket()` 或裸监听 `message` 事件 | ❌ 必须走 `useMessageStore().publish/subscribe` |
| 在通用控制器里写业务判断 | ❌ `core/generic/**` 保持零业务 |
| 跨层传 `any` | ❌ 用 `protocol/**` 里的 interface |
| 改了消息事件键就交付 | ❌ 同步 `docs/source/07-协议事件清单.md` 与 `协议层DTO Schema.tsd` |
| 修改后想"应该没问题" | ❌ 先 `pnpm lint` |
