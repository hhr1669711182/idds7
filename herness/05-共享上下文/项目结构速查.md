## 二、应用入口与装配

| 路径 | 职责 |
|------|------|
| `src/main.ts` | 应用入口，仅调用 `mountApp()` |
| `src/lib/index.ts` | **应用/库共用装配** mountApp：Pinia → initUserStore → BusinessMessageRuntime.start → Router/导航 → F10～F13 bridges → initMessage → 挂载；失败/卸载释放资源 |
| `src/App.vue` | 根组件 |
| `src/layout/` | 布局（`MainLayout.vue` 等） |
| `src/types/auto-imports.d.ts` / `components.d.ts` | **自动生成**，勿手改 |

> 双形态说明：`pnpm dev` 走应用形态；`pnpm build:lib` 以 `src/lib/index.ts` 为入口产出库（`dist-lib/`），供宿主项目通过 `mountApp` 挂载，并 `export * from '@/plugins/mapPlugins'` / `plugins/crypto` 对外暴露能力。

## 五、命名与文件约定

| 约定 | 说明 |
|------|------|
| 目录 | 业务域 kebab-case 或 camelCase（现存两种：`MarkDraw` / `AddressRobotDrawer` 为 PascalCase，其余多为 camelCase/kebab） |
| 组件 | `.vue` 文件多为小写短语（`map.vue`、`home.vue`）或 PascalCase（`MainLayout.vue`、`WeatherPanel.vue`）——**按同目录既有风格走** |
| Store | `useXxxStore.ts`，id 与文件名对应（`'messageStore'` 等） |
| 常量 | `const.xxx.ts` 或 `const/xxx.ts`，`as const` 结尾 |
| 类型 | `types.ts` 或 `xxx.d.ts`；跨层 DTO 放 `controller/core/protocol/` |
| 方法文件 | `xxx.ts`，导出 `xxxMethod` 或语义化函数名 |

## 六、易踩的坑

| 坑 | 正确做法 |
|----|---------|
| 手改 `types/auto-imports.d.ts`、`types/components.d.ts` | ❌ 自动生成，勿改；由 `vite.config.ts` 的 AutoImport/Components 插件产出 |
| 以为有 ESLint | ❌ `pnpm lint` 实际是 `vue-tsc --noEmit`（**类型**检查，非 lint 风格） |
| 以为无测试 runner | ❌ 当前有 pnpm test（Vitest）与 pnpm e2e（Playwright），回放/组件/生命周期用例见 tests |
| 在业务控制器里 `import 'ol/...'` | ❌ 越层；构造参数使用 protocol BusinessMapPort，引擎逻辑放底座 adapter/renderer |
| 裸 `new WebSocket()` 或裸监听 `message` 事件 | ❌ 必须走 `useMessageStore().publish/subscribe` |
| 在通用控制器里写业务判断 | ❌ `core/generic/**` 保持零业务 |
| 跨层传 `any` | ❌ 用 `protocol/**` 里的 interface |
| 改了消息事件键就交付 | ❌ 同步 `docs/source/07-协议事件清单.md` 与 `协议层DTO Schema.tsd` |
| 修改后想"应该没问题" | ❌ 先 `pnpm lint` |

## 七、迁移职责边界（按当前源码）

- Runtime 为 App 级：start 注册唯一业务接收，attachMap/attachTracking 绑定地图或跟踪消费者并返回解绑函数，dispose 释放资源。换图时未完成 mock job 交还 pending，已完成不重放；attachTracking 同步恢复 accepted GPS，DispatchT1 控制器须先就绪。
- lib/index.ts 装配 register/businessMapLifecycle.ts::bindBusinessMapLifecycle：beforeEach 捕获 runtime.prepareDispatchLeave 闭包，afterEach 仅在成功导航时清对应 generation/contextRevision，防止旧离页清新 flood。
- GPS 跨层类型在 LegacyMessageProtocol/BusinessProtocol，实际为 `{ datas: CarLocationPoint[] }`；TrackingController 委托 port.trackingVehicleGpsUpdate，不能给 undefined layer 调通用更新。
- IncidentLocationController 接收完整 Envelope；store 按身份、版本、阶段、会话、HTTP 水位接受，meta.snapshotKind 区分 full 替换与 delta 合并。消息 inbox 不能直接当 accepted 状态恢复。
- SharedState 类型在 protocol；useUserStore 保存原始 phase 为 MapMode，getSharedMapStage 投影有效阶段。inquiry + 有效 incidentId 为 dispatch，不要求外部写 phase='dispatch'。
- F10 composable 解析/去重/LOCAL_STORAGE ingest 与发导航意图，Runtime 队列执行；F11 relay 与 F13 HTTP 本轮有快照/并发行为修正，不属冻结。仅 F12 选点/ACK V1.0 及其既有可靠性缺陷冻结等价迁位，通用 BC 工具不含业务。
- AddressRobotRenderer 暴露 new(genericController)、addressRobotGisSearch(data, options?)、addressRobotClear(options?)、dispose；底座负责 Feature/样式/面板及自身 timer/动画清理。VehicleRenderer、SwipeControl 同属底座。
- Control/**、useMessageStore916.ts 和旧 AddressRobotUtils 保留对照；messageStageGate.ts 仍存在。P1 已接入并完成自动化回归；完整人工验收后，还需用户另行确认清理。
