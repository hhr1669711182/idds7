## 一、消息中枢总览（useMessageStore）

```
外部消息（WebSocket / postMessage）
    ↓ ingest()
拦截器链 interceptorRegistry.run()   ← 模板匹配 + 数据归一
    ↓ 命中
dispatch(eventKey, data)              ← 生成 MessageEnvelope
    ↓
订阅分发 triggerSubscriptions()        ← notify 订阅者
    ↓
组件 handler（经 useMessageStore().subscribe 订阅）
```

**三条接收路径优先级**（`ingest` 内）：
1. 已是标准 Envelope（`v` / `eventKey` / `system` / `channel` 齐全）→ 直接补全后分发
2. 拦截器链命中 → 按拦截器输出（单条或多条 `results[]`）分发
3. 都未命中 → 兼容 Legacy（`raw.eventKey` 或 `raw.type` → 映射 MESSAGE_EVENT_KEY）分发

**核心 API**（setup store 返回）：
| 方法 | 说明 |
|------|------|
| `publish(eventKey, data, { system, channel, targetSystem?, meta?, targetOrigin?, iframe? })` | 发送，生成 Envelope 并记录 outbox |
| `subscribe(eventKey, callback, system?)` | 订阅，**返回取消函数**；组件须在卸载时调用 |
| `connectWebSocket({ system?, url, socketOptions? })` | 绑定 WS（自动重连），返回解绑函数 |
| `bindParent({ system?, acceptOrigins })` | 绑定 postMessage（按 origin 白名单过滤），返回解绑函数 |
| `bindBroadcastChannel({ system?, name, channelOptions? })` | 绑定 BroadcastChannel（同源多标签页互通），返回解绑函数 |
| 状态 | `wsStatus`、`wsError`、`lastBySystem`、`inbox`、`outbox`（各保留最近 100 条） |

**跨标签页广播（BroadcastChannel）**：`src/hooks/useBroadcastChannel.ts` 的 `BroadcastChannelClient` 与 `useWebSocket` 的
`WebSocketClient` 同构（构造即连接、`send` / `sendEvent` / `disconnect`、onOpen/onMessage/onError/onClose 回调），
但**不需要重连与心跳**，且**浏览器不会把消息回发给发送方自身**（故 store 只在接收侧 `ingest`，发送侧仍照常记入 `outbox`）。
由 `VITE_USE_BROADCAST_CHANNEL` 开关控制，在 `register/initMessage.ts` 中与 `bindParent` 同样的注册方式挂载。

**Envelope 结构**（`src/types/message.ts`）：`{ v, id, timestamp, system, channel, eventKey, data, targetSystem?, meta? }`

## 三、拦截器链（src/interceptor）

### 类型
| 类型 | 说明 |
|------|------|
| `SubscribeRule` | 与 `MESSAGE_SUBSCRIBE_TOPIC` 同构；`dispatch: 'single' \| 'multi'` |
| `InterceptorContext` | `{ channel, system, raw, eventKey?, meta? }` |
| `InterceptorOutput` | `{ matched, data?, eventKey?, meta?, results?, stop? }` |
| `MessageInterceptor` | `{ id, priority, enabled?, describe?, subscribe, transform }` |

### 执行规则（registry.run）
1. 按 `priority` 升序（seat 150 → alarm/alarmCall/carLocation 200）
2. `subscribe.type` 为 `CUSTOM`/`SEAT` 时先做模板匹配（`matcher.ts`），不匹配跳过
3. `transform(ctx)` 出 `{ matched: true, ... }` 才产出结果
4. `results[]` 非空 → 多条分发；否则单条 `eventKey + data`
5. `stop: true` → 中断后续拦截器
6. transform 抛异常 → 记录并跳过，不影响其他拦截器

### 消息体归一（unwrap.ts）
- `content` / `customContent` 是 JSON 字符串时自动 parse
- `topics` / `notifyType` / `notifySubType` 大小写归一
- **业务判断（topics 命中 / eventName 推导）由各 transform 自行处理**

### 现有业务拦截器
| 文件 | 订阅 | 模式 | 说明 |
|------|------|------|------|
| `transforms/seat.ts` | SEAT（`seatNumber`） | `multi` | 主系统泛订阅，二次分发到多个内部 eventKey |
| `transforms/alarm.ts` | CUSTOM `ALARM_INCIDENT` / `STATE_CHANGED` | single | 警情状态变更 |
| `transforms/alarmCall.ts` | CUSTOM `ALARM_CALL` / `ANSWER_STATUS_CHANGED` | single | 来电接听状态 |
| `transforms/carLocation.ts` | CUSTOM `GPS_MSG` / `car-location-broadcast-all` | single | 车辆 GPS |
| `transforms/dispatchers/` | — | — | 二次分发器：`addressRobot` / `locateCall` |

**装配时机**：`installDefaultInterceptors()` 由 `useMessageStore` 首次 `ingest` 时惰性安装（`ensureInterceptors`）。SEAT 订阅依赖 `seatNumber`，**必须在 Pinia 激活后**。

## 四、对外消息出口（publish / subscribe）

> `controller/map` 与 `controller/three` 已废弃删除，`src/subscribe/` 已下线。
> 现行唯一出口：**发送**走 `@/controller/publish`，**接收**走 `useMessageStore().subscribe`。

### 发送：`src/controller/publish/**`

**目录结构（按 `MESSAGE_SYSTEM` 分类）**

```
src/controller/publish/
├── index.ts       # barrel，只做再导出；新增分类文件必须在此加一行
├── types.ts       # 共享类型：PublishResult / FixedPublishOptions
├── map.ts         # system=map      （route / map / aoi / layer 等键）
├── host.ts        # system=host     （与宿主页面的 postMessage 通道）
├── three.ts       # system=three
├── dispatch.ts    # system=dispatch（预留，当前无实现）
└── common.ts      # 跨 system 通用（预留：hello / heartbeat / error）
```

| 文件 | 固定 system | 固定 channel | 现有函数 |
|------|-------------|---------------|---------|
| `map.ts` | `MESSAGE_SYSTEM.MAP` | `MESSAGE_CHANNEL.WS` | `publishRoutePlanMultiple` / `publishRoutePlanCancel` / `publishMapPoiPick` |
| `host.ts` | `MESSAGE_SYSTEM.HOST` | `MESSAGE_CHANNEL.POST_MESSAGE` | `publishAddrPoiPick` |
| `three.ts` | `MESSAGE_SYSTEM.THREE` | `MESSAGE_CHANNEL.WS` | `publishThreeBuildFormSend` |
| `dispatch.ts` / `common.ts` | — | — | 预留，当前无实现 |

**发送事件一览**

| 函数 | 事件键（`MESSAGE_EVENT_KEY`） | 实际键值 | system | channel |
|------|-----------|---------|--------|---------|
| `publishRoutePlanMultiple(data)` | `ROUTE_PLAN_MULTIPLE` | `route.plan.multiple` | map | ws |
| `publishRoutePlanCancel(routeId)` | `ROUTE_PLAN_CANCEL` | `route.plan.cancel` | map | ws |
| `publishMapPoiPick(data)` | `MAP_POI_PICK` | `map.poi.pick` | map | ws |
| `publishAddrPoiPick(data)` | `ADDR_POI_PICK` | `addr.poi.pick` | host | postMessage |
| `publishThreeBuildFormSend(data)` | `THREE_BUILD_FORM_SEND` | `three.build_form.send` | three | ws |

> ⚠️ 当前 5 个函数**尚无业务调用方**（仅测试引用），属预留契约。调用方按需 import，不注册到任何控制器。

**使用写法**

```ts
// ✅ 正确：按 system 从 barrel 导入，调用方不传 system / channel
import { publishMapPoiPick, publishRoutePlanCancel } from '@/controller/publish'

const ok = publishMapPoiPick({ lng, lat, address })
publishRoutePlanCancel(routeId)

// ❌ 错误：裸 store.publish
import { useMessageStore } from '@/store/useMessageStore'
useMessageStore().publish('map.poi.pick', data, { system: 'map', channel: 'ws' })

// ❌ 错误：字符串字面量事件键
useMessageStore().publish('map.poi.pick', data, OPTS)
```

**新增发送函数的落位流程**

```
1. 在 src/const/const.message.type.ts 的 MESSAGE_EVENT_KEY 加键（保持小写点分层级）
2. 确定该键的 system → 归到对应分类文件（map / host / three / dispatch / common）
3. 新建分类文件时，同步在 index.ts 加一行 export *，并在本表登记
4. 函数签名：export const publish<业务动作><目标> = <T>(data: T): boolean => ...
   - system / channel 用该文件的 OPTS 常量，不作为参数暴露
   - 载荷有 protocol DTO 时用它替代 <T>；<T> 泛型仅作过渡
5. 补 tests/unit/publish.spec.ts 契约用例（eventKey / system / channel 三项）
6. 同步 docs/source/07-协议事件清单.md 与 协议层DTO Schema.tsd
7. 回写本节表格与 05-共享上下文/公共工具速查.md
```

**publish 与 OutputController 的边界（不要合并）**

| | `src/controller/publish/**` | `src/controller/core/io/OutputController.ts` |
|-|------------------------------|------------------------------------------|
| 语义 | 业务**主动向外发送**（跨系统通信） | 渲染层**状态上报**（地图引擎内部事件） |
| 方向 | 业务代码 → 宿主 / 其他系统 | 地图引擎 → 订阅者 |
| 使用者 | 业务组件 / composables | `core/generic` 内部调用 |
| 分层 | 业务层出口 | 控制层内部 |

> 两者都经 `useMessageStore().publish`，但**语义与分层不同，不应合并**。
> `OutputController` 的 `emitXxx` 属既有控制层设计，本轮不动；业务侧新增对外发送一律走 `publish/`。

**禁止项**

| ❌ 禁止 | 原因 |
|---------|------|
| 裸 `useMessageStore().publish`（业务代码） | 绕过 system/channel 契约，事件键易写错 |
| 字符串字面量事件键 | 与 `MESSAGE_EVENT_KEY` 脱钩，改常量不生效 |
| 在 publish 层写业务判断 / 持有状态 | 薄封装原则，publish 只做转发 |
| 把 `system` / `channel` 暴露为函数参数 | 分类文件已固定，暴露会让调用方传错 |
| 从 publish 层 `import 'ol/'` 或 `three` | 分层铁律：业务出口不碰引擎 |
| 新增分类文件但忘记在 `index.ts` export | 调用方 import 不到，等于没加 |

### 接收：`useMessageStore().subscribe`
```ts
const unsubscribe = useMessageStore().subscribe(MESSAGE_EVENT_KEY.XXX, (envelope) => {
  const data = envelope.data
})
// 组件内务必在 onUnmounted 调用 unsubscribe，避免泄漏
```

## 五、修改协议的标准流程

1. 在 `src/const/const.message.type.ts` 新增/修改 `MESSAGE_EVENT_KEY`（保持命名规范：小写点分层级）
2. 在 `src/controller/core/protocol/` 对应文件新增/修改 DTO interface（Generic / Business / IO）
3. 若为服务端下行消息：在 `src/interceptor/transforms/` 加 transform（或改现有），并按需在 `install.ts` 注册
4. 若为跨系统消息：发送封装加到 `src/controller/publish/index.ts`（`publishXxx`）；接收方直接 `useMessageStore().subscribe`
5. **同步** `docs/source/07-协议事件清单.md`
6. **同步** `docs/source/协议层DTO Schema.tsd`
7. 破坏性变更：`MESSAGE_PROTOCOL_VERSION` 升版本并评估兼容策略

## 六、易错点

| 易错 | 说明 |
|------|------|
| 裸 WebSocket / 裸 message 监听 | 违反唯一出口规则 |
| 忘记取消订阅 | 组件卸载后仍回调 → 内存泄漏 |
| 在 transform 里重复 JSON.parse | 归一已在 `unwrap.ts` 完成 |
| 改事件键拼写"修正" | `map.base.poiLoation` 等历史拼写是对外契约，勿改 |
| SEAT 订阅在 Pinia 前初始化 | `seatNumber` 取不到 |
| 拦截器 priority 排错 | seat(150) 必须先于 alarm(200)，否则泛订阅不分发 |
