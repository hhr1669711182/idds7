## 一、消息中枢总览（useMessageStore）

```
外部消息（WS / postMessage / BC / LOCAL_STORAGE 桥 / HTTP 补水）
    ↓ ingest()
拦截器链 interceptorRegistry.run()   ← 模板匹配 + 数据归一
    ↓ 命中
dispatch(eventKey, data)              ← 生成 MessageEnvelope
    ↓
订阅分发 triggerSubscriptions()        ← notify 订阅者
    ↓
App 级 BusinessMessageRuntime → InputController + messageStagePolicy
    ↓
BusinessController / IncidentLocationController → store / BusinessMapPort
    ↓
当前地图 attachment（baseComponent/OpenlayersMap）
```

**三条接收路径优先级**（`ingest` 内）：
1. 已是标准 Envelope（`v` / `eventKey` / `system` / `channel` 齐全）→ 直接补全后分发
2. 拦截器链命中 → 按拦截器输出（单条或多条 `results[]`）分发
3. 都未命中 → 兼容 Legacy（`raw.eventKey` 或 `raw.type` → 映射 MESSAGE_EVENT_KEY）分发

上述为公共 ingest；WS onMessage 共用 receive 但关闭最后 Legacy 回退。仅带根 eventKey/type 的原始 WS 消息不能据公共 API 推断为已支持。

**核心 API**（setup store 返回）：
| 方法 | 说明 |
|------|------|
| `ingest(raw, channel, system, meta?)` | 接收/归一；LOCAL_STORAGE、HTTP bridge 也走此入口 |
| `publish(eventKey, data, { system, channel, targetSystem?, meta?, targetOrigin?, iframe? })` | 发送，生成 Envelope 并记录 outbox |
| `subscribe(eventKey, callback, system?)` | 订阅，**返回取消函数**；组件须在卸载时调用 |
| `connectWebSocket({ system?, url, socketOptions? })` | 绑定 WS（自动重连），返回解绑函数 |
| `bindParent({ system?, acceptOrigins })` | 绑定 postMessage（按 origin 白名单过滤），返回解绑函数 |
| `bindBroadcastChannel({ system?, name, channelOptions? })` | 绑定 BroadcastChannel（同源多标签页互通），返回解绑函数 |
| `getLastByEventKey` / `clearLastByEventKey` | 原始接收索引；不等于经过业务准入的恢复状态 |
| 状态 | `wsStatus`、`wsError`、`lastBySystem`、`lastByEventKey`、`inbox`、`outbox`（收发列表各保留最近 100 条） |

**跨标签页广播（BroadcastChannel）**：`src/hooks/useBroadcastChannel.ts` 的 `BroadcastChannelClient` 与 `useWebSocket` 的
`WebSocketClient` 同构（构造即连接、`send` / `sendEvent` / `disconnect`、onOpen/onMessage/onError/onClose 回调），
但**不需要重连与心跳**，且**浏览器不会把消息回发给发送方自身**（故 store 只在接收侧 `ingest`，发送侧仍照常记入 `outbox`）。
由 `VITE_USE_BROADCAST_CHANNEL` 开关控制，在 `register/initMessage.ts` 中与 `bindParent` 同样的注册方式挂载。

**Envelope 结构**（`src/types/message.ts`）：`{ id, timestamp, system, channel, eventKey, data, targetSystem?, meta?, v?, isRemoveSameElement? }`。类型中 v 可选；标准信封快路要求 v='1.0.0'；store 创建时会写入。实际载荷字段是 data，不是历史概念模型的 payload。接收 channel/system 以 ingest 参数为准，metadata 保留并合并。

`MessageMetadata.snapshotKind?: 'full' | 'delta'` 是画像全量/增量标记；WS transform、F11 relay、F13 HTTP 入口均须传递。meta 还可带 recordId/eventId/source、共享态 revision、session/context/generation 等源信息。

## 二、常量体系（const.message.type.ts）

### 通道 MESSAGE_CHANNEL
`ws` / `postMessage` / `broadcastChannel` / `localStorage` / `http`。后两者用于桥接入站；LOCAL_STORAGE 不自动扫描所有键；HTTP 仅表示补水来源，`publish` 对 HTTP 返回 false。

### 系统 MESSAGE_SYSTEM
`host`（主系统）/ `map`（地图）/ `three` / `dispatch` / `ids-seat-web`

### 订阅主题 MESSAGE_SUBSCRIBE_TOPIC（服务端订阅声明）
| 主题 | 结构 |
|------|------|
| `SEAT` | 运行时函数，key 取 `useUserStore().seatNumber` |
| `ALARM_CALL` | CUSTOM `ALARM_CALL` / key `ANSWER_STATUS_CHANGED` |
| `ALARM_INCIDENT` | CUSTOM `ALARM_INCIDENT` / key `STATE_CHANGED` |
| `GPS_MSG` | CUSTOM `GPS_MSG` / key `car-location-broadcast-all` |
| `DISASTER_PROFILE` | CUSTOM `DISASTER_PROFILE` / key `UPDATED` |

模板是**拦截器匹配规则**，不是线上 subscribe 线格式；线上报文统一为字符串 topic，两者分开放。`register/initMessage.ts` 建立 connect 鉴权后订阅 `user/<userId>/screen/map`、`ALARM_INCIDENT/STATE_CHANGED`、`ALARM_CALL/ANSWER_STATUS_CHANGED`、`GPS_MSG/car-location-broadcast-all`、`DISASTER_PROFILE/UPDATED`，有席位再加 `seat/<seatKey>`；用户级收件箱 `user/<userId>` 由服务端自动订阅，前端不重复声明。声明在 `interceptor/subscriptions.ts`（`buildScreenSubscription`/`buildPositionSubscription`/`buildPositionUnsubscribe` 与四个常量），`register/messageSubscriptions.ts` 兼容导出。

连接身份只取 `userId + sessionState`，与席位解耦：换席走同连接 `unsubscribe`/`subscribe`，不重建连接；换用户或换会话才释放旧连接。`initMessage()` 返回可调用句柄，附带 `subscriptionStatus()` 返回各 topic 的 `pending`/`ok`/`denied` 回执状态，登出或换会话时清空。`hooks/useWebSocket.ts` 的重连计数在 `markReady`（鉴权通过）才清零，CONNECT 被拒可正常累计 `reconnectAttempts`。挤下线由外部主控负责，本项目不实现登出跳转；`clientId` 固定 `ids-seat-web`。

## 三、拦截器链（src/interceptor）

### 类型
| 类型 | 说明 |
|------|------|
| `SubscribeRule` | 与 `MESSAGE_SUBSCRIBE_TOPIC` 同构；`dispatch: 'single' \| 'multi'` |
| `InterceptorContext` | `{ channel, system, raw, eventKey?, meta? }` |
| `InterceptorOutput` | `{ matched, data?, eventKey?, meta?, results?, stop? }` |
| `MessageInterceptor` | `{ id, priority, enabled?, fallback?, describe?, subscribe, transform }` |

### 执行规则（registry.run）
1. 按 `priority` 升序：SEAT 50 → 地址机器人 100 → 位置 110 → GPS 120 → 接听 130 → 警情 140 → 画像地址 150 → T1 900
2. `subscribe.type` 为 `CUSTOM`/`SEAT` 时先做模板匹配（`matcher.ts`），不匹配跳过
3. `transform(ctx)` 出 `{ matched: true, ... }` 才产出结果
4. `results[]` 非空 → 多条分发；否则单条 `eventKey + data`
5. `stop: true` → 中断后续拦截器
6. transform 抛异常 → 记录并跳过，不影响其他拦截器
7. `fallback: true` 仅在此前尚无结果时执行；T1 必须在专属业务归一之后

### 消息体归一（unwrap.ts）
- `unwrapMessageFrames` 支持数组、JSON 多层字符串、request/data/body/message/payload/userMsgBodyList 包装，继承外层路由与 metadata
- `content` / `customContent` 自动 parse，topics 对象/字符串 topic 兼容；type/customType/notify 大小写归一
- `matchesMessageRoute` 排除明确的 topic/notify/eventName/source 冲突，再做兼容匹配；不能任意含 data 就匹配所有业务

### 现有业务拦截器
| 文件 | 订阅 | 模式 | 说明 |
|------|------|------|------|
| `transforms/seat.ts` | SEAT（`seatNumber`） | `multi` | 先走统一 business 归一；未命中才走扩展 dispatcher |
| `transforms/addressRobot.ts` | RAW | 多结果 | 地址机器人，复用 addressRobot dispatcher |
| `transforms/position.ts` | RAW | 多结果 | 来电定位 |
| `transforms/alarm.ts` | CUSTOM `ALARM_INCIDENT` / `STATE_CHANGED` | 归一输出 | 警情状态变更 |
| `transforms/alarmCall.ts` | CUSTOM `ALARM_CALL` / `ANSWER_STATUS_CHANGED` | 归一输出 | 来电接听状态 |
| `transforms/carLocation.ts` | CUSTOM `GPS_MSG` / `car-location-broadcast-all` | 多批次结果 | 车辆 GPS |
| `transforms/incidentLocation.ts` | CUSTOM `DISASTER_PROFILE` / `UPDATED` | 归一输出 | 画像地址 + meta.snapshotKind |
| `transforms/t1.ts` | RAW | fallback | 最后的 T1 兼容兜底 |
| `transforms/dispatchers/` | — | — | addressRobot 供归一器使用；locateCall 保留兼容委托，SEAT 扩展列表默认为空 |

**装配时机**：`installDefaultInterceptors()` 由 `useMessageStore` 首次 `ingest` 时惰性安装（`ensureInterceptors`）。SEAT 订阅依赖 `seatNumber`，**必须在 Pinia 激活后**。

`transforms/business.ts` 先按 916 原生识别范围扫描地址机器人 → 位置 → GPS → 接听 → 警情 → 画像地址；整轮无结果才按相同顺序做包装增强，避免增强抢走原生匹配。install.ts 的各业务 interceptor 与 SEAT 共用统一归一裁决。位置/GPS 可多结果且去重，answer/incident 仅取首匹配；SEAT multi 不等于所有业务全量扇出。

T1 只接受根 eventType 对象或根 payload 单对象的 eventType/eventKey，事件值/data 原样保留，不映射常量名、不展开 T1 列表/深层包装。位置/GPS 不钻入 T1 data 抢走载荷。通用 unwrap 的多层解包能力不自动扩大 T1 接收范围。

### 实际 DTO 与业务准入

| 数据 | 类型/接收责任 |
| --- | --- |
| GPS | `LegacyMessageProtocol.CarLocationBatch = { datas: CarLocationPoint[] }`；BusinessProtocol.TrackingVehicleGpsUpdateData 同形；点含 carId/longitude/latitude/plateNumber，可选 orgId/orgName/gpsTime，无 layerId/incidentId 要求 |
| 画像地址 | `IncidentLocationProtocol.AddressUpdatedData`：version、slots 字典、可空地址/经纬度/主管站及身份字段；full 替换、delta 合并，省略与显式清空不同 |
| 定位接受 | `IncidentLocationController.receive(envelope)` → useIncidentLocationStore，负责身份、版本、阶段、会话、HTTP 请求水位；marker/槽位快照/上下文持久化，派生资源重建 |
| 来电粗定位 | usePendingCallLocationStore 保存定位与 contextKey，地图 attach 时恢复，已接受正式坐标优先 |

上述 DTO 均在 `src/controller/core/protocol/`。共享态类型在 SharedStateProtocol.ts，原始事实在 useUserStore；MapMode 保存原始 phase。`utils/seatSharedState::getSharedMapStage` 校验 v=1/updatedAt/auth 后投影：inquiry + currentAlarm=null → inquiry，inquiry + 有效 incidentId → dispatch；裸 phase='dispatch' 不放行。

### Runtime、F10～F13 与地图绑定

`mountApp` 创建并启动 `core/io/BusinessMessageRuntime`，持有 InputController/BusinessController；messageStagePolicy 按接收时间与最新 shared receive time 等待 500ms 稳定窗口，校验 popup/inquiry/dispatch/dispatchTrack，换会话清待交付队列。业务模块不再随地图重建重复订阅这些事件。

`attachMap(port, { kind?, mock?, dispose? })` / `attachTracking(callback)` 返回解绑函数。attachTracking 会同步 hydrate 最新 accepted GPS；DispatchT1 须先创建控制器再 attach，解绑后不继续回调。业务 Controller 构造参数为无引擎 BusinessMapPort；底座 `OpenlayersMap/businessMapPort.ts` 返回 { port, dispose }，创建 AddressRobotRenderer。VehicleRenderer/AddressRobotUtils/SwipeControl 也位于该底座目录。

换图时 Runtime 将未完成 mock job 交还 pending，已完成任务不重放。`src/register/businessMapLifecycle.ts::bindBusinessMapLifecycle` 由 lib/index.ts 装配：beforeEach 捕获 runtime.prepareDispatchLeave 闭包，afterEach 仅在导航成功时清对应 generation/contextRevision，避免旧离页回调清除新 flood。

| 批次/路径 | 当前职责 |
| --- | --- |
| F10 `composables/useMockCallLocationBridge.ts` | mock blob 解析、独立字段差异、命令去重、LOCAL_STORAGE ingest 与导航意图；Runtime 排队，dispatch attachment 执行 MockMapPort，退出/会话/generation 作废旧任务 |
| F11 `composables/useMapRelayReader.ts` | relay hello/snapshot/event/bye，30 秒 hello；本轮修正快照语义/上下文接入，不是冻结项 |
| F12 `composables/useGisPointSelection.ts` | 仅 GIS 选点/ACK V1.0 等价迁位，既有取消/ACK/重试缺陷保持冻结；PICK_START 转已有 mock.incident.relocate |
| F13 `composables/useIncidentLocationProfileSync.ts` | HTTP 全量补水、首次拉取与在途上下文竞争修正；snapshotKind='full'，不属冻结项 |
| 通用 BC | composables/useBroadcastChannelBridge 的 send/listen/close/dispose；hooks/useBroadcastChannel 的 BroadcastChannelClient；均不承载业务分支 |

这些 composables 路径相对 `src/`。PICK_* / relay kind 是各自线协议，不作为新增 MESSAGE_EVENT_KEY。

**使用写法**

```ts
// ✅ 正确：按 system 从 barrel 导入，调用方不传 system / channel
import { publishMapPoiPick, publishRoutePlanCancel } from '@/controller/publish'

const ok = publishMapPoiPick({ lng, lat, address })
publishRoutePlanCancel(routeId)

// ❌ 错误：裸 store.publish
import { useMessageStore } from '@/store/useMessageStore'
useMessageStore().publish('map.poi.pick', data, { system: 'map', channel: 'ws' })

// ❌ 错误：字符串字面量事件键

```

**新增发送函数的落位流程**

```
1. 在 src/const/const.message.type.ts 的 MESSAGE_EVENT_KEY 加键（保持小写点分层级）
2. 确定该键的 system → 归到对应分类文件（map / host / three / dispatch / common）
3. 新建分类文件时，同步在 index.ts 加一行 export *，并在本表登记
4. 函数签名：export const publish<业务动作><目标> = <T>(data: T): boolean => ...
   - system / channel 用该文件的 OPTS 常量，不作为参数暴露
   - 载荷有 protocol DTO 时用它替代 <T>；<T> 泛型仅作过渡
5. 补 tests/unit/publish.spec.ts 契约用例（eventKey / system / channel 三项）
6. 同步 docs/source/07-协议事件清单.md 与 协议层DTO Schema.tsd
7. 回写本节表格与 05-共享上下文/公共工具速查.md
```

**publish 与 OutputController 的边界（不要合并）**

| | `src/controller/publish/**` | `src/controller/core/io/OutputController.ts` |
|-|------------------------------|------------------------------------------|
| 语义 | 业务**主动向外发送**（跨系统通信） | 渲染层**状态上报**（地图引擎内部事件） |
| 方向 | 业务代码 → 宿主 / 其他系统 | 地图引擎 → 订阅者 |
| 使用者 | 业务组件 / composables | `core/generic` 内部调用 |
| 分层 | 业务层出口 | 控制层内部 |

> 两者都经 `useMessageStore().publish`，但**语义与分层不同，不应合并**。
> `OutputController` 的 `emitXxx` 属既有控制层设计，本轮不动；业务侧新增对外发送一律走 `publish/`。

**禁止项**

| ❌ 禁止 | 原因 |
|---------|------|
| 裸 `useMessageStore().publish`（业务代码） | 绕过 system/channel 契约，事件键易写错 |
| 字符串字面量事件键 | 与 `MESSAGE_EVENT_KEY` 脱钩，改常量不生效 |
| 在 publish 层写业务判断 / 持有状态 | 薄封装原则，publish 只做转发 |
| 把 `system` / `channel` 暴露为函数参数 | 分类文件已固定，暴露会让调用方传错 |
| 从 publish 层 `import 'ol/'` 或 `three` | 分层铁律：业务出口不碰引擎 |
| 新增分类文件但忘记在 `index.ts` export | 调用方 import 不到，等于没加 |

### 接收：`useMessageStore().subscribe`（底层 API）

Runtime 已承接的业务不得再在组件注册第二份同事件处理。独立订阅仍须取消；F12 组件选点消费者属于明确的冻结例外。

```ts
const unsubscribe = useMessageStore().subscribe(MESSAGE_EVENT_KEY.XXX, (envelope) => {
  const data = envelope.data
})
// 组件内务必在 onUnmounted 调用 unsubscribe，避免泄漏
```

## 五、修改协议的标准流程

1. 在 `src/const/const.message.type.ts` 新增/修改 `MESSAGE_EVENT_KEY`（保持命名规范：小写点分层级）
2. 在 `src/controller/core/protocol/` 对应领域文件新增/修改 DTO interface（含 LegacyMessage / SharedState / IncidentLocation / BusinessMapPort 等）
3. 若为服务端下行消息：在 `src/interceptor/transforms/` 加 transform（或改现有），并按需在 `install.ts` 注册
4. 若为跨系统消息：发送封装加到 `src/controller/publish/` 对应分类并从 index 导出；接收业务在 Runtime/InputController 的唯一入口登记，使用 protocol DTO 与阶段策略
5. **同步** `docs/source/07-协议事件清单.md`
6. **同步** `docs/source/协议层DTO Schema.tsd`
7. 破坏性变更：`MESSAGE_PROTOCOL_VERSION` 升版本并评估兼容策略

## 六、易错点

| 易错 | 说明 |
|------|------|
| 裸 WebSocket / 裸 message 监听 | 违反唯一出口规则 |
| 忘记取消订阅 | 组件卸载后仍回调 → 内存泄漏 |
| 在 transform 里重复 JSON.parse | 归一已在 `unwrap.ts` 完成 |
| 改事件键拼写"修正" | `map.base.poiLoation` 等历史拼写是对外契约，勿改 |

| 拦截器 priority 排错 | 按 install.ts 的 50→100→110→120→130→140→150→900 顺序，T1 最后 fallback |
| 把 inbox 当 accepted 快照 | 阶段拒绝消息也可能在收件索引中；只从业务已接受状态恢复 |
| 把历史概念信封当 transport | 当前为 id/timestamp/eventKey/data/v；docs/source 中历史概念示例已单独标记 |
| 提前清理 Control/916 | 保留对照闭包；messageStageGate.ts 仍在。完整人工验收后，用户须另行确认清理 |
