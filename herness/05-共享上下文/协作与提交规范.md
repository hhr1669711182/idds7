## 二、`.gitignore` 陷阱（🔴 P0 · 已修复）

| 规则 | 风险 | 正确写法 |
|------|------|---------|
| ~~`scripts`~~ | 裸目录名会忽略**整个** scripts 目录 | 用 `/scripts-temp/` 或精确到文件 |
| ~~`src` 的 md 规则~~ | 会屏蔽工程文档 | 精确路径白名单 |
| `skills*` | 屏蔽 skill 目录 | 若需入库则加 `!skills/` 例外 |
| `tests/__artifacts__/` | ✅ 正确：只忽略测试产物 | 保留 |

**新增 `.gitignore` 规则后的自检**：

```bash
git check-ignore -v <新文件>     # 有输出 = 被忽略了，需要修正规则
git status --short                # 新资产必须出现在列表里
```

## 三、分支模型（🟡 P1 · 团队约定）

| 分支 | 用途 | 规则 |
|------|------|------|
| `main` | 生产分支 | 只接受合并，**不直接提交** |
| `dev` | 集成分支 | 功能合并后跑一次全量验证 |
| `dev-<姓名>` | 个人开发分支 | 从 `dev` 切出；**命名统一 `dev-xx`，禁止 `dev-yf-2024` 等日期后缀** |

**提交前先同步**：

```bash
git fetch origin
git rebase origin/dev      # 或 merge，看团队约定
```

> 历史问题：个人分支曾落后 dev 121~250 个 commit，导致合并冲突集中爆发。养成「每天开工先 fetch」的习惯。

## 四、质量门禁（当前只提示，不阻塞）

`.husky/pre-commit` 已接入两个检查，**均为提示模式，不阻塞提交**：

| 脚本 | 检查什么 | 严格模式 |
|------|---------|---------|
| `scripts/check-lint-baseline.mjs` | `vue-tsc` 报错是否**新增** | `LINT_BASELINE_STRICT=1` |
| `scripts/check-herness-size.mjs` | 文档体量是否失控 / 日志是否写回 SOP | `HARNESS_STRICT=1` |

**判定标准是「没有引入新增报错」，不是「零报错」**（基线约 190 项 `TS6133`）。判定命令：

```bash
pnpm lint:baseline       # 期望输出「无新增报错」
pnpm harness:check       # 期望输出「文档体量正常」
```

> 后续若接入 GitLab CI，在 CI job 里设 `LINT_BASELINE_STRICT=1` / `HARNESS_STRICT=1` 即可卡住；**当前按团队决策暂不实施**。

## 五、环境变量与敏感信息（🟡 P1 · 已实施）

| 文件 | 处理 |
|------|------|
| `.env.development` / `.env.production` / `.env.test` | **可以入库**，只放**非敏感**配置（如 `VITE_MAP_CENTER`） |
| `.env.local` | **不入库**，本地私有覆盖 |
| `.env.local.example` | ✅ 已入库，作为模板参考 |

**禁止入库**：真实 token、密码、内网私有地址、`accessToken` 等凭据。

## 六、文档同步（多人一致性的核心）

多人维护时，「文档与代码脱节」是最隐蔽的坑。本仓库的三层信息架构：

| 内容 | 位置 | 变更频率 | 谁读 |
|------|------|---------|------|
| **工作规则** | `herness/00-SOP.md` | 低 | 每次任务 |
| **现行规范** | `herness/05-共享上下文/*.md` | 低 | 按任务类型 |
| **当期状态** | `herness/05-共享上下文/当前状态摘要.md` | 中（修复即删） | 每次任务 |
| **流水账** | `herness/09-工作日志/YYYY-MM/YYYY-MM-DD.md` | 高 | 需要追溯时 |
| **历史方案** | `herness/02-技术设计/前端/_archive/` | 不变 | 只读参考 |

**落位口诀**：*流水账进日志，规矩进规范，仍有效的结论进摘要，落地完的方案进归档。*

`pnpm harness:check` 会机械校验这条规则（防止日志回流 SOP、已修复条目长期滞留）。
