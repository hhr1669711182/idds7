## 二、缺陷清单（按优先级）

### P0 · 首屏阻塞

#### P0-1　全量 Element Plus CSS 进首屏（476 KB raw）

- **现象**：`src/lib/index.ts` 顶层 `import 'element-plus/dist/index.css'`；产物 `index-*.css` 含 990 个 `.el-*` 唯一选择器 / 5456 处引用。
- **根因**：项目同时存在「Element Plus resolver 按需引入」（`unplugin-vue-components` + `AutoImport` 的 `ElementPlusResolver`）与「手动全量 CSS」，resolver 的按需优化被完全抵消。
- **风险**：首屏多传 ~400 KB CSS 原文（gzip 后仍 69 KB），且样式表解析阻塞渲染。
- **修法**：删除 `src/lib/index.ts` 的 `element-plus/dist/index.css`；确认按需 resolver 已产出组件样式；补一个最小自测页验证无样式丢失。
- **验证**：重建后 `index-*.css` 应显著下降（预期降到 ~60–90 KB raw）；首页按钮/弹窗/表格样式肉眼比对。

#### P0-2　`dist/index.html` 硬编码 Cesium 样式 + 未声明 preload 策略

- **现象**：`dist/index.html` 首行是 `<link rel="stylesheet" href="cesium/Widgets/widgets.css">`（不在 `index.html` 源文件里，疑由 `vite-plugin-cesium` 注入）。
- **影响**：即使首屏不加载 Cesium JS，样式仍阻塞首屏解析；反之该 6.77 MB `cesium/` 目录对 `/map` 首屏完全无用。
- **修法**：确认 `vite-plugin-cesium` 注入点；若首屏不需要 Cesium，考虑改用 `copy` 按需投放，或改由 Cesium 组件自身动态引入样式。
- **风险**：中，改动插件配置可能影响 `/CesiumDuty` 等页面样式。

#### P0-3　`src/store/index.ts` 桶导出把全部 store 拉进首屏

- **现象**：`store-DofWcWUU.js` 189.2 KB 进首屏 preload。
- **根因**：`src/store/index.ts` 用 `export *` 一次性导出 21 个 store（含 `useMessageStore916` 14.2 KB、`useIncidentLocationStore` 29.9 KB、`useDispatchT1Store` 10.4 KB、`useModelAssessStore` 8.4 KB、`useSearchPanelStore` 12.6 KB）。入口链路（`lib/index.ts` → `register/*`、`composables/*`）任一引用 `@/store` 都会拖进整桶。
- **次生问题**：`useMessageStore916.ts`（14.2 KB）与 `useMessageStore.ts`（12.7 KB）并存，历史遗留命名歧义。
- **修法**（**需同步评估，不建议本批做**）：
  1. 首屏链路改为**深路径引入**（`@/store/useMapStore`）而非 `@/store`；
  2. 或按域拆桶（`@/store/map`、`@/store/dispatch`、`@/store/message`），保留 `@/store` 仅作类型出口。
  - **风险**：高。store 间存在互相引用（如 `Control/*`、`controller/**` 大量 `from "@/store"`），逐一改造面大。**建议单独立项**，先做依赖图再动。
- **旁证**：`@/store` 在 `src/Control/**`、`src/controller/**` 里被广泛 `import`，桶的边界已经失效。

### P1 · 分包与缓存

#### P1-1　无 `manualChunks` / `advancedChunks`，分包完全靠 Rolldown 自动

- **现象**：`vite.config.ts` 的 `build.rolldownOptions` 只有 `external` 与 `output.codeSplitting`，**没有任何 vendor 分组策略**。
- **后果**：
  - 三方库与业务代码混在同一批 chunk，第三方升级即让业务 chunk 缓存失效；
  - `alova`、`fetch.esm` 等稳定依赖无法长期缓存；
  - 已拆出 `Map`/`store`/`geoserver` 属自动产物，命名不可控、不可维护。
- **修法**：引入 Rolldown 新 API `output.advancedChunks`（`groups`）把 `vue/pinia/element-plus/ol/three/cesium/alova` 固定分组并命名（`vendor-vue`、`vendor-ol`、`vendor-three`…）。**先在 dev 验证无循环依赖再上生产。**
- **风险**：中。分块不当会引入 chunk 循环依赖，`three`/`cesium` 与业务层互相引用时尤其敏感。

#### P1-2　4 MB 级单 chunk 未告警

- **现象**：`CesiumDuty-Bi182bak.js` **4025.7 KB raw / 1107.3 KB gzip**，无 `chunkSizeWarningLimit` 配置，构建默认 500 KB 告警阈值下应触发但**未见显式阈值治理**。
- **判定**：Cesium 已被路由懒加载隔离（`router/index.ts` `component: () => import('@/components/BIM/CesiumDuty.vue')`），**不进首屏**，属可接受的大包；但需显式设阈值避免其他包继续恶化。
- **修法**：设置 `chunkSizeWarningLimit`（建议 800–1200 KB）；把 `CesiumDuty` 的 cesium 依赖看作「已知大包」白名单说明，而非靠默认告警。

#### P1-3　`GLTFLoader` 602 KB 与 `dispatchMap` 423 KB 归属不清

- **现象**：`GLTFLoader-CZgKjByO.js` 602.3 KB、`dispatchMap-DoHy9GsJ.js` 423 KB（含 `html2canvas` 静态引用 → `html2canvas-BLAuETGM.js` 194.8 KB）。
- **判定**：`src` 内已无 `html2canvas` 直接引用（`rg` 命中 0），属**残留产物/间接引用**，是明确的治理项。
- **修法**：
  - 查 `dispatchMap.vue` 的 `html2canvas` 间接来源（可能是 `jspdf`/`js-clipper` 依赖树）；
  - 确认无引用则从依赖树剔除或改动态引入；
  - `html2canvas` 若确为截图必需，改 `await import('html2canvas')` 仅在截图时加载。

### P2 · 资源与部署

#### P2-1　27.5 MB 无引用 `.tif` 进产物

- **现象**：`src/assets/file/hanyang_build.tif` **28 188.9 KB（27.53 MB）** 进 `dist/assets/file/`。
- **次生**：`src/assets/file/no-overviews.tif` 25 225.2 KB（24.6 MB）**未进产物**（已被另一 agent 治理中），说明团队已识别该问题但未清完。
- **判定**：`rg` 确认代码无引用 → 可直接移出 `src/assets`，改为按需从 CDN/OSS 拉取，或放入 gitignore 的静态目录。
- **风险**：低（无代码引用）。需确认运行时是否由业务动态拼接 URL 访问。

#### P2-2　`fonts/` 17.27 MB 首屏无关但部署重

- **现象**：`public/fonts/` 7 个文件共 17.27 MB，最大 `YEFONTDianYingPangBaiTi_Regular.json` **16 093.2 KB（15.7 MB）**。
- **判定**：这类字体 json 用于 3D 标注（Billboard/label）渲染，属运行期按需拉取，非首屏。
- **修法**：迁出 `public/`，改 CDN 或运行时 `fetch`，避免每次部署搬运与备份成本。
- **风险**：低。

#### P2-3　`model3d/` 50 MB 与 `video/` 2.7 MB 同类问题

- **现象**：`public/model3d/` 23 文件 50 MB（`gltf` 18.37 MB + 其他 31.64 MB）；`public/video/` 2.7 MB。
- **修法**：同 P2-2，一律「构建产物与 3D/视频资源分离」，资源走 CDN/OSS，`public/` 只留首屏必需。

#### P2-4　`web.config` 只配 MIME，无压缩

- **现象**：`dist/web.config` 仅声明 `.geojson` 的 MIME，**无 `<httpCompression>` 启用的 IIS 压缩配置**。
- **影响**：IIS 部署时 JS/CSS 不压缩，316 KB gzip 首屏 JS 变回 955 KB raw 传输。
- **修法**：补 `<httpCompression>`（`dynamicCompressionEnabled="true"` + `staticCompressionEnabled="true"`）；或 CI 产出 `.br`/`.gz` 预压缩文件。
- **风险**：低，需与运维确认 IIS 版本支持。

#### P2-5　构建告警：Three.js 导入不存在导出

- **现象**：每次构建输出 `[IMPORT_IS_UNDEFINED] Import 'sRGBEncoding' will always be undefined because there is no matching export in 'three@0.169.0'` — `src/components/BIM/module/initThreeBuilding.js:35`。
- **影响**：当前未崩溃，但 `sRGBEncoding` 恒为 `undefined`，Three 0.169 已移除该导出（r152+ 已废弃），渲染色彩空间设置**静默失效**。属**功能缺陷**而非性能问题，但阻塞告警噪声需清理。
- **修法**：改用 `THREE.SRGBColorSpace`（与 `renderer.outputColorSpace` 配合），或按当前 Three 版本实际 API 修正。
- **风险**：中，需回归 3D 建筑渲染色彩。
