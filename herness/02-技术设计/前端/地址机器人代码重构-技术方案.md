## 5. 关键流程

### 5.1 调用链（改造后不变）

```
服务端 916 帧
  → interceptor: normalizeAddressRobotFrames (transforms/addressRobot.ts)
  → addressRobotDispatcher → 事件键 address_robot.gis_search
  → useMessageStore 分发
  → InputController 订阅 → business.addressRobot.addressRobotGisSearch(data)
  → AddressRobotController（业务层，只依赖 BusinessMapPort，无引擎）
  → businessMapPort → AddressRobotRenderer（底座）
      → createDisplayStyleFunction / createFlashStyleFunction（唯一实现在底座 .ts）
      → featureRenderOrder（唯一实现在底座 .ts）
      → EventBus.emit('gis_search', …)
  → AddressRobotDrawer 监听 'gis_search' → 展示
```

**唯一变化**：`AddressRobotUtils` 的实现位置从「底座 + controller 双份」收敛为「**底座单份 .ts**」。调用链、事件键、DTO 均不变。

> ⚠️ **重构时必须保住的一条链路（实测）**：
> `AddressRobotRenderer` 收到的是**顶层平铺**的 `AddressRobotGisSearchData`（含 `overall_confidence` / `highlight_entities`），
> 但它发给抽屉的事件体是 **`{ ...gis_search, confidence: overall_confidence }`** —— 即 `confidence` 来自**顶层** `overall_confidence`，
> 而抽屉模板读的 `gis.raw_text` / `gis.highlight_entities` 来自**嵌套的** `gis_search` 对象。
> **这意味着「顶层 confidence」与「嵌套 gis_search」是混用的**（tests/unit/f6F7EngineBoundary.spec.ts:168 断言的是 `{ raw_text: '道路', confidence: 0.9 }`）。
> 重构抽屉类型时**不得**把 `GisPayload` 直接等同于 `AddressRobotGisSearchData`，否则会静默改变面板显示（置信度变 undefined → 显示 0.0%）。
> 该口径归属 W07（契约冻结）范畴，本次**只加注释说明，不改行为**。
