# 主题调色盘体系 · 技术方案

> 状态：**已落地**（2026-10-20）
> 事实来源：`pnpm build` 实测产物 + `pnpm lint:baseline`
> 规范见 `herness/05-共享上下文/代码样式规范.md`

---

## 一、目标

1. **默认适配主题**：新增样式不需要再写一遍夜间覆盖；
2. **可调试调色盘**：改主色、改底图滤镜不改业务代码；
3. **毛玻璃统一**：面板质感在所有主题下一致。

---

## 二、体系结构

```
tokens.less     设计常量（与主题无关）
   ↓
palettes.less   调色盘（每主题/预设盘一组 CSS 变量）
   ↓
element-theme.less  Element Plus 的 --el-* 适配层
   ↓
组件样式         var(--token) 消费
```

| 文件 | 职责 |
|------|------|
| `src/styles/tokens.less` | 裸色值、间距、圆角、阴影等设计常量 |
| `src/styles/palettes.less` | `DAY` / `NIGHT` / `OCEAN` / `EMBER` 四套调色盘 + `--ma-*` 模块色 |
| `src/styles/day.less` / `night.less` | 保留为「主题专属补充」入口，变量已上移到调色盘 |
| `src/styles/element-theme.less` | Element Plus `--el-*` 变量，**白天与夜间都补齐** |
| `src/styles/themed-panel.less` | 组件级强化（透明底、激活态等变量表达不了的细节） |

### 切换维度（正交）

| 维度 | 属性 | 取值 |
|------|------|------|
| 主题 | `html[data-theme]` | `DAY` / `NIGHT` |
| 调色盘 | `html[data-palette]` | `DAY` / `NIGHT` / `OCEAN` / `EMBER` / `CUSTOM` |

优先级：`CUSTOM`（inline style） > 预设盘 > 主题默认盘。

## 三、调色盘面板

`src/components/map/component/paletteDrawer.vue`

- 入口图标与配置图标**并排**（配置图标 `right: 300px`，调色盘图标 `right: 266px`）；
- 用 **Element Plus 抽屉**（`el-drawer`，`direction="rtl"`，`size="360px"`，`append-to-body`）弹出；
- 四个分区：主题切换 / 调色盘预设 / 自定义变量 / 底图滤镜。

| 分区 | 能力 |
|------|------|
| 主题 | DAY / NIGHT 二选一，复用既有 `ThemeSwitch` 的 store 通道 |
| 调色盘预设 | NIGHT / DAY / OCEAN / EMBER，点击即换 `data-palette` |
| 自定义变量 | 5 个关键 token 改色，写入 inline style + localStorage 持久化 |
| 底图滤镜 | 5 个参数滑块，实时改 `--filter-*` 并触发瓦片重载 |

**日/夜切换不进 config.vue**：既有 `ThemeSwitch.vue` + `useCommonStore.setThemeColor` 已实现，抽屉里只是复用同一通道。

## 四、底图滤镜参数化

改造前：滤镜字符串在两处硬编码。

| 位置 | 改造前 |
|------|--------|
| `src/utils/mapTool.ts` | `grayscale(98%) invert(100%) sepia(20%) hue-rotate(180deg) saturate(1600%) brightness(80%) contrast(90%)` |
| `src/baseComponent/OpenlayersMap/baseSource.ts` | 同上（重复） |

改造后：统一走 `src/utils/themeColor.ts`。

```ts
export interface BasemapFilter {
  hueRotate: number; invert: number; saturate: number; brightness: number; contrast: number
}

export const getBasemapFilter = (): BasemapFilter => { /* 从 CSS 变量读 */ }
export const buildFilterString = (filter: BasemapFilter): string => { /* 拼 filter 串 */ }
```

调用方：

```ts
context.filter = buildFilterString(getBasemapFilter())
```

**收益**：改色只需改调色盘变量，两处调用自动跟随；预设盘可带不同滤镜（OCEAN `hue-rotate: 200deg`、EMBER `20deg`）。

### 即时重绘

调色盘/滤镜变更 → `map.getLayers().forEach(l => l.getSource?.()?.refresh())` → 当前底图瓦片重载，新滤镜立即可见。

原用 Less 变量 `@ma-bg` / `@ma-orange` / `@ma-text` 等 15 个，定义在各 less 文件头部。改为 CSS 变量 `var(--ma-*)`，定义上移到 `palettes.less` 的 DAY / NIGHT 盘 —— 模块整体获得主题切换能力。

> 注意：Less 变量参与 `fade()` / `lighten()` 等函数计算时不能直接换 CSS 变量。实测本模块无此类用法（已核查）。

### 10.3 踩坑记录（重要）

**坑 1：Lightning CSS 前缀去重**

源码同时写 `backdrop-filter` 与 `-webkit-backdrop-filter` 时，Lightning CSS 判定等价，
**只保留 `-webkit-` 那一份**；而 Chrome 对 `-webkit-backdrop-filter` 的计算值返回 `none`
→ 毛玻璃在 **prod 构建**后彻底失效（dev 不压缩，所以看不出）。

> 结论：源码只写 plain 的 `backdrop-filter`。Lightning CSS 会自动补 `-webkit-` 前缀，
> 手写反而触发去重把自己坑掉。

**坑 2：scoped 下 `:global()` 会吃掉后代选择器**

`html[data-theme='NIGHT'] .compass` 里的变量苣挂在 `.compass` 内时，
Vue 的 scoped 编译会把 `.compass` 后代选择器吃掉，只剩 `html[...]` 规则，
变量定义到了 `html` 上而 `.compass` 自身的定义又覆盖了它 → 主题切换不生效。

> 结论：主题级变量定义在 `:global(html[...])` 上，组件只 `var()` 消费。

**坑 3：Less 变量 ≠ CSS 变量**

`@radius-md: 8px` 不能被 `var(--radius-md)` 消费 → 浏览器回退 invalid →
`border-radius` 消失。Less 编译期/构建/lint **都不报错**。已有 `check-css-vars.mjs` 防复发。

## 十一、第三轮修复（2026-10-21 · OL 控件样式收敛）

### 11.1 起因

用户反馈「丢失了 ol-overviewmap 鹰眼功能」。排查确认是第二轮引入的**回归**：
`src/styles/ol-controls.less` 给 `.ol-overviewmap` 加了 `overflow: hidden`，
把 180×120 的鹰眼缩略图整块裁没，只在左下角留了 2×2 的边框残影。

**根因机理（浏览器实测，非推测）**：

1. 项目样式把 `.ol-overviewmap .ol-overviewmap-map` 设为 `position: absolute`（`map.less`），**不撑开父容器**；
2. OL 官方 `.ol-overviewmap` 本身无宽高，靠内容撑开 —— 内容被绝对定位抽走后容器塌成 **0×0**；
3. 此前容器只有 `border-radius`（无 `overflow`），子元素溢出照常渲染；
4. 加上 `overflow: hidden` → 0 尺寸容器成了裁剪盒 → 缩略图被裁没。

像素级 A/B 实测（缩略图区域统计非白像素）：

| 覆盖 | 非白像素 | 结论 |
|------|---------|------|
| 现状（bug） | 3485 | 缩略图被裁 |
| `overflow: visible` | **7604** | 缩略图完整出现 |
| `border-radius: 0` / `border: none` / `box-shadow: none` / `background: transparent` | 3485 | 全部无关 |

同时确认：鹰眼 canvas **一直在正常渲染**（`distinctColors: 8087`，瓦片有真实像素），
JS 逻辑、`AMAP_LAYER()`、`overviewLayer` 均正常 —— **不是数据或生命周期问题**。

### 11.2 更深的根因：OL 样式散落 4 个文件 5 处副本

修完回归后发现真正的问题是**样式管理失控**：

| 文件 | 原行号 | 内容 | 冲突现状 |
|------|--------|------|---------|
| `map.less` | 374-466 | 控件尺寸/位置/鹰眼/比例尺/缩放/打印 | 与 `ol-controls.less` 同名不同值 |
| `dispatchMap.vue` | 3031-3131 | **几乎逐行复制** `map.less` 的 OL 段 | `.ol-control` 硬编码白底 `rgba(255,255,255,.8)` 压过主题变量 |
| `ol-controls.less` | 27-83 | 主题配色 | `overflow:hidden` 裁掉鹰眼 ← 本次回归 |
| `markDraw/index.vue` | 68-87 | `:deep(.ol-control)` 局部覆盖 | 圆角 2px 与全局 4px 冲突 |
| `style.css` | 86-93 | 移动端 media query `!important` | `background-color: rgba(255,255,255,.9) !important` 压过主题变量，夜间控件发白 |

实测同一套控件在 4 个页面的 `.ol-control` 底色**四种不同**：
`rgb(13,25,41)`（map）/ `rgba(255,255,255,.8)`（dispatch）/ `rgba(255,255,255,.8)`（dispatch1）/ `rgba(10,22,40,.82)`（markDraw）。

**结论**：冲突不是偶发，是这套「多处副本 + 局部覆盖」结构的必然产物。
所以不只修鹰眼，而是把 OL 样式**收敛到唯一真源**。

```less
  overflow: hidden;
  box-shadow: var(--panel-shadow);
}
```

### 11.4 踩坑记录

**坑 1：0 尺寸定位盒不能加外观样式**

OL 有几个控件容器本身无宽高（`.ol-overviewmap` 容器、折叠态 `.ol-attribution`），
靠子元素绝对定位撑出视觉。这类容器加 `overflow` / `border` / `background` / `box-shadow` 会：
- `overflow` → 子元素被裁没（本轮鹰眼事故）
- `border` / `box-shadow` → 留下边框残影（2×2 小方块）

**坑 2：`.ol-control button` 的字号必须显式给**

OL 官方 `.ol-control button` 用 `1.375em`，迁移时若只写 `width/height` 不写 `font-size`，
字号会回落到继承的 14px，图标变小。

**坑 3：`.ol-overviewmap` 折叠按钮的底色要自己给**

容器透明后，折叠按钮需要自己的 `background` + `border` 才在地图上可见。

## 十二、第四轮修复（2026-10-21 · 右上角操作簇收敛）

### 12.1 起因

用户反馈三条症状：

1. 「把我的 config.vue 入口按钮搞丢失了」
2. 「三个按钮整体位置也不对」
3. 「天气面板位置有异动」

### 12.2 根因（均已实测，非推测）

Playwright 实测 1600×900 `#/map`：

| 元素 | rect (x,y,w,h) | 定位 | z-index |
|------|----------------|------|---------|
| `.theme-switch` | 1210, 10, 50, 40 | `fixed; top:10px; right:340px` | 1000 |
| `.cfg-toggle` | 1270, 15, 30, 30 | `fixed; top:15px; right:300px` | **5** |
| `.palette-toggle` | 1304, 15, 30, 30 | `fixed; top:15px; right:266px` | 1000 |
| `.weather_panel` | 1283, 7, 261, 46 | `absolute; top:0.5em; right:56px` | **60** |

**根因 1 —— 入口按钮被压住（症状 1）**

`.weather_panel`（z-index 60）横向覆盖 `.cfg-toggle`（z-index 5）。
`elementsFromPoint(1290, 25)` 顶层是 `weather_panel`，图标主体被盖 → 用户看到「按钮丢失」。

**根因 2 —— 天气面板的「让位」本身是错的（症状 3）**

上一轮为「让开右侧按钮簇（brp / trp / clear / compass 都在 `right:8~18px`）」把
`right` 从 `0.5em` 改成 `56px`。但实测：

- `.brp` → `bottom:8px; right:8px`
- `.compass` → `bottom:38px; right:18px`
- `.trp` → `top:65px; right:10px`
- `.clear` → `top:590px; right:10px`

**它们全都不在顶部右侧**（brp/compass 在右下角，trp/clear 在右侧中部）。
顶部右侧本就不需要让位 → 白缩 48px，面板左边缘从 1213 移到 1283，
正好压上 config 按钮（1270~1300）→ **「让位」是凭想象做的，反而制造了事故**。

**根因 3 —— 三个按钮位置互不相干（症状 2）**

`right` 各自硬编码且互不相关（340 / 300 / 266），间距 40px 与 34px 不等；
`top` 也不统一（10 vs 15）；theme-switch 宽 50px 而另两个 30px
→ 右对齐但左边缘参差（1210 / 1270 / 1304）。

### 12.3 更深的根因：与「OL 控件散落副本」同型

这四个元素是**同一个视觉簇**（右上角），却在 4 个文件里各写各的 `right` 魔法数字。
谁一改宽度就撞谁 —— 与第三轮「OL 控件散落 4 文件 5 处副本」是**同一种结构性缺陷**，
只是这次发生在布局定位层而非外观层。故按同款思路收敛为**单一常量源**。

### 12.5 踩坑记录

**坑 1：「让位」要先验证让给谁**

上轮为 brp/compass 让位，但它们在右下角 —— 顶部让位是凭想象做的。
**移动/重排任何元素前，先量目标元素的实际 rect**。

**坑 2：横向簇必须有一致宽度基准**

面板内容长度不定（城市名、风力、湿度都会变），
用 `min-width`/`max-width` 时按钮簇位置会随内容长度漂移。
解法：**固定宽度 + `text-overflow: ellipsis`**，面板宽度成为簇布局的常量基准。

**坑 3：z-index 不同级 = 随时会被兄弟节点压住**

入口按钮 z-index 5，而同屏的天气面板是 60 —— 只差一个量级的事故。
**同一簇的入口按钮 z-index 必须同级**。

**坑 4：多文件各自硬编码位置 = 事故的复发路径**

本轮与上一轮 OL 控件事故同源。凡「同一视觉簇跨多个文件」，位置必须集中到常量层。
