## 2. 方案概述

### 背景（现状盘点，均为实测真实符号）

当前三类「顺序 / 索引」各自散落、缺统一可配置真源：

| 类别 | 现状落点 | 问题 |
|------|---------|------|
| **图层**（渲染堆叠 z-order + 工具栏列表序） | `src/config/layers.ts`：`LAYER_SOURCE_CONFIGS` 的 `order` / `groupOrder` / `categoryOrder`（工具栏分组列表序）；`src/config/mapConfig.ts`：`buildLayerGroups` 按 `sortByOrder` 归一；`useLayersStore.checkedIds`（勾选集，`sessionStorage` 持久化）；引擎层 z 序隐式（`map.vue` 各 `mount*` 函数按代码执行顺序 `addLayer`，`useAmapTools.ts` 的 `FIRE_STATION_LAYER_Z_INDEX` 是**唯一**显式 z 常量） | 工具栏「列表序」有配置；但**渲染堆叠 z-order 没有配置**——完全靠 `mount` 调用先后决定谁压谁，调顺序即改代码 |
| **面板**（DOM 挂载序 + 视觉 z-index） | `src/components/map/index.vue` 模板里**硬编码**面板顺序（`tlp/trp/routePlan/topicLayerCard/baseSource/clear/card/bigPanel/paletteDrawer/layers/ssrkPanel/config/WeatherPanel/circleQueryPanel/dispatch-variant-ui`）；显隐由 `effectiveFeature.<showXxx>` 布尔门控；视觉 z 序散在 CSS（`.ol-scale-line{z-index:2}`、右上角 `--top-actions-*` 常量簇、`config.vue` 让位逻辑） | 面板顺序、叠放层级全是**模板书写顺序 + CSS 魔法数字**，不可配置；加一个面板要改模板 + 手排 z-index |
| **视口**（多图 / 3D 场景的优先级与聚焦） | `const.map.ts`：`EXTENT` / `ZOOM{MIN,MAX,INIT}` / `CENTER`（经 `appEnv.mapCenter`）；`map.vue` 的 `refreshMapViewport`（rAF 双帧 `map.updateSize()+renderSync()`）；3D 场景在 `views/modelAssess/model3d/`（Cesium/Three 独立实例）；鹰眼 `OverviewMap` | 「视口索引」当前**只有主图一个默认 View**，无多视口优先级表；鹰眼、3D 视口与主图的叠放/聚焦关系无配置，纯靠各自 DOM 位置 |

**核心诉求**：把「图层 / 面板 / 视口」三类顺序从「硬编码 + 散落魔法数字」收敛为**单一可配置真源**，做到「顺序可声明、可校验、可随模式/用户配置切换、可持久化」。

### 目标

1. 建立统一的「顺序 / 索引」配置模型（OrderConfig），三类各一套可声明的有序清单 + z-band。
2. 图层：渲染 z-order 从「隐式执行序」变为**显式 z-band 配置**，工具栏列表序沿用现有 `order` 体系不变（兼容）。
3. 面板：DOM 挂载序与视觉 z-index 由**有序配置**驱动（`v-for` 按序 + `order` 映射 z-band），模板不再手写顺序。
4. 视口：引入**视口优先级 / 叠放表**，支持「主图 / 鹰眼 / 3D」的可配置聚焦与叠放。
5. 可控：全部走 `MapConfigPayload` 扩展（localStorage 默认源，预留 HTTP 源）+ 模式 overlay（沿用 `LAYER_MODE_HIDDEN_*` 风格），并做**归一化 + 校验**（缺省补齐、重复去重、未知键丢弃、locked 保护）。

### 范围（含 / 不含）

- **含**：顺序配置 schema、归一/校验工具、图层 z-band 渲染接入、面板有序挂载、视口优先级表、配置面板（config.vue）里的顺序编辑入口、`MapConfigPayload` 扩展与持久化、单测。
- **不含（明确不做）**：不改图层**显隐**逻辑（仍走 `checkedIds` / `effectiveFeature`）；不改面板**功能**本身；不动 3D 场景内部渲染管线；不引入新依赖；不改消息事件键 / DTO（纯前端本地配置域）。

## 4. 设计：统一顺序 / 索引规范

### 4.1 三条顺序轴（统一模型）

```
orderConfig（单一真源）
├── layerOrder   轴① 图层：groupOrder → categoryOrder → resourceOrder（列表/工具栏序，沿用现有）
│                + layerZBands   渲染堆叠 z-band（新增：category→band，band→整数值）
├── panelOrder   轴② 面板：mountSlot[]（有序挂载）+ panelZBands（视觉层级 band）
└── viewportOrder 轴③ 视口：viewportPriority[]（主图/鹰眼/3D 聚焦与叠放顺序）
```

**z-band 约定**（避免魔法数字，统一整数区间，区间间留 gap 便于后续插入）：

| 带 | 整数区间 | 用途 |
|----|---------|------|
| `Z_BAND.BASE` | 0–99 | 底图（高德/谷歌/影像） |
| `Z_BAND.WMS` | 100–199 | WMS 专题（消防站/警情/建筑…，类内细排） |
| `Z_BAND.VECTOR` | 200–299 | 矢量（路径线/圈选结果/标绘） |
| `Z_BAND.MARKER` | 300–399 | 标记（车辆/来电/SSRK/火灾） |
| `Z_BAND.OVERLAY` | 400–499 | 覆盖特效（围栏/天气圈/高亮） |
| `Z_BAND.UI` | 500–599 | 水印/网格 |

面板 `panelZBands`（DOM 视觉层级，对齐现有 CSS 散点并收敛为配置）：
`TOOLBAR=10 / DRAWER=30 / PANEL=40 / MODAL=60 / TOAST=80 / POPOVER=90`。

### 4.2 配置 schema（`src/config/orderConfig.ts` 草案，伪类型）

```ts
export interface LayerZBands { [band: string]: number }          // band 名 → 基础 z
export interface PanelSlot { key: string; slot: string; band: number; locked?: boolean }
export interface ViewportPriority { key: string; name: string; focus: number; stack: number }

export interface OrderConfig {
  layerZBands: LayerZBands                                  // 轴① z-band（默认值见 4.1）
  layerResourceZ: Record<string, number>                     // 单个资源细排覆盖（可选）
  panelSlots: PanelSlot[]                                    // 轴② 有序面板清单
  viewportPriorities: ViewportPriority[]                     // 轴③ 视口优先级
}
export const DEFAULT_ORDER_CONFIG: OrderConfig = { /* 按 4.1 默认值 */ }
```

归一函数 `normalizeOrderConfig(raw): OrderConfig`：
- 缺省 band 补齐为 `DEFAULT_ORDER_CONFIG`；
- 面板/视口按 `key` 去重（后者覆盖，保序）；
- 未知 `key` / 未知 `band` 丢弃；
- `locked` 资源（消防站 `gis:view_res_org_dept`）的 z 不可被外部数据改写；
- 数值非有限 → 落默认。

### 4.3 可控点

| 可控维度 | 入口 | 机制 |
|---------|------|------|
| 默认顺序 | `DEFAULT_ORDER_CONFIG` | 代码内默认，改默认即改真源 |
| 用户自定义 | `config.vue` 顺序 tab（拖拽/上下移） | 写 `MapConfigPayload.order` → `saveMapConfig`（localStorage 默认源 / 预留 HTTP） |
| 模式强制 | `LAYER_MODE_*` 扩展 | 沿用 `effectiveFeature` 派生思路：`effectiveOrder = applyModeOverlay(order, viewMode)`，调派/特灾态可强制某类面板/视口顺序，切出自动恢复，**零持久化副作用** |
| 渲染堆叠 | 底座 `addLayer` 前 `setZIndex(band + 细排)` | 不再靠 mount 执行序；`FIRE_STATION_LAYER_Z_INDEX` 并入 `layerZBands`，消除孤立魔法数字 |

### 4.4 归一与校验（异常兜底）

- `normalizeOrderConfig` 对 localStorage 脏数据 / 旧版本数据做**向后兼容**：读不到 `order` 段 → 用默认；字段缺失 → 补齐；非法值 → 丢弃取默认（对齐 `normalizeMapConfig` 既有风格）。
- 面板清单若漏掉某组件 → 该组件按 `DEFAULT_ORDER_CONFIG` 兜底位置渲染，不消失。
- 视口表空 → 默认「主图唯一」，3D/鹰眼回落既有行为。

## 6. 关键流程

### 6.1 调用链（面板有序渲染）
```
loadConfig() → normalizeMapConfig（含 normalizeOrderConfig）
  → useMapConfigStore.effectiveOrder（模式 overlay 派生）
  → index.vue 按 panelSlots 序渲染（v-for）→ band 映射 CSS z-index
```

### 6.2 调用链（图层 z-band）
```
useLayersStore.checkedIds → map.vue addLayer(id)
  → 查 orderConfig.layerZBands[category] + layerResourceZ[id]（细排）
  → layer.setZIndex(band + offset) → 渲染堆叠确定，不再依赖 mount 执行序
```

### 6.3 消息流
- 本方案**不新增消息事件键 / 拦截器 / DTO**（纯前端本地配置域，无跨系统通信）。

## 8. 异常与兜底

| 场景 | 处理 |
|------|------|
| localStorage 无 `order` 段 / 旧数据 | `normalizeOrderConfig` 补齐默认，不报错 |
| 非法 z / 未知 key / 未知 band | 丢弃该字段取默认，保留其余有效项 |
| locked 资源（消防站）被外部改写 z | 归一时强制回落 `layerZBands` 默认 |
| 面板清单漏组件 | 按默认 slot 兜底渲染，不消失 |
| 视口表为空 | 回落「主图唯一」既有行为 |
| 调派/特灾态 | `effectiveOrder` 模式 overlay 强制顺序，切出恢复用户值（零副作用） |

## 10. 依赖与风险

- 依赖：无新 npm 包；仅既有 `MapConfigSource`（localStorage / 预留 HTTP）与 `effectiveFeature` 模式 overlay 范式。
- 风险：
  1. **面板从「模板硬编码」改「配置驱动」** 是行为变更——需保证缺省配置下渲染结果与现状**逐面板一致**（回归用例锁定默认序）。
  2. **图层 z 从执行序改显式 band** 可能改变某些「碰巧正确」的叠放 → 需对照现有 `FIRE_STATION_LAYER_Z_INDEX` 等逐一核对 band 归属，避免压盖反转。
  3. 视口优先级若涉及 3D（Cesium/Three）多实例叠放，本期**仅声明表 + 主图/鹰眼落地**，3D 叠放作预留（不改 3D 内部管线）。
- 回滚：`order` 段为**新增可选段**，删除 `orderConfig.ts` 引入点并还原模板/`addLayer` 即回退；localStorage 旧数据经归一自动忽略 `order`，无脏数据残留风险。
