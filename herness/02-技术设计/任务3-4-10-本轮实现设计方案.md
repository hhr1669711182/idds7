## 一、任务 3 ｜ 限制视图范围工具：唤醒 + 配置持久化规范化 + config.vue 门控（默认关）

### 目标与范围
- 唤醒休眠的 `useExtent`，把它接到地图底座，使「限制视图范围」真实生效（flex 模式：越界时把视图拉回）。
- 把「是否启用限制 / 限制范围 / 模式」纳入 `FeatureSettings` 走**既有** config 持久化链路（localStorage → `useMapConfigStore` → `mapConfig.ts`），不再走 env 硬编码。
- 在 `config.vue` 的「功能配置」tab 增加门控开关 `showViewLimit`（限制视图），**默认 `false`（关闭）**。
- **不做**：不引入 `maxExtent` View 约束（保持现有 flex「拉回」语义，避免行为漂移）；不改 `useExtent` 核心算法；不动 env.ts（无需新增 VITE_* 键）。

### 分层落点（为什么）
| 改动 | 落层 | 理由 |
|---|---|---|
| `FeatureSettings` 增 `showViewLimit / viewLimitMode / viewLimitExtent` + 默认值 + normalize | `config/mapConfig.ts`（store 契约层） | 门控开关与其它 `showXxx` 同源，随 config 持久化 |
| config.vue「功能配置」加开关 + 范围/模式字段 | `views/components`（UI 层） | 与现有 `featureFieldGroups` 一致，纯 UI |
| map.vue 唤醒 useExtent + watch 门控 | `baseComponent/OpenlayersMap/map.vue`（渲染底座） | 地图实例与工具生命周期都在底座，符合「工具挂底座」现状（类比任务7天气圈挂底座） |

### 涉及文件清单
1. `src/config/mapConfig.ts` — `FeatureSettings` 增 3 字段；`DEFAULT_FEATURE_SETTINGS` 增默认值（`showViewLimit:false, viewLimitMode:'flex', viewLimitExtent: 兜底值`）；`normalizeMapConfig` 补兜底/收窄；`FeatureBoolKey` 无需改（`showViewLimit` 是 boolean）。
2. `src/components/map/config.vue` — 「功能配置」tab 的 `featureFieldGroups`「地图参数」组（或新增「视图限制」组）加 3 个字段项：`showViewLimit`（switch，默认关）、`viewLimitMode`（radio：flex/fixed）、`viewLimitExtent`（number×4 或留空=用默认兜底）。
3. `src/baseComponent/OpenlayersMap/map.vue` — 取消 `:17` import 注释；`initMap` 里按 `mapConfigStore.config.feature.showViewLimit` 决定 `useExtent(map, extent, { mode, enabled })`；加 `watch` 门控变化时 `setEnabled`/`setExtent`；`cleanup` 调 `destroy()`。

### 关键调用链
```
config.vue 保存 → useMapConfigStore.saveConfig → mapConfig.normalizeMapConfig（兜底 showViewLimit）
map.vue watch(feature.showViewLimit / mode / extent)
  → enabled ? extentCtrl.setEnabled(true) : setEnabled(false)
  → mode/extent 变化 → extentCtrl.setExtent(extent)（useExtent 内部 transformExtent WGS84→3857 + constrainView）
  → map.on('moveend', constrainView)（flex）拉回越界
```
> `viewLimitExtent` 用户输入用 **WGS84 `[minLng,minLat,maxLng,maxLat]`**；`useExtent` 内部已做 `transformExtent` 投影，故 map.vue 直接传 WGS84 四元组即可，不重复投影。

### 异常与兜底
- `viewLimitExtent` 为空/非法 → normalize 回退默认兜底（用当前地图初始中心点周边 或 原 EXTENT 的 WGS84 等价值 `[~109.0,22.4,118.5,26.5]` 全国范围，需在设计评审确认具体兜底值）。
- 开关从 开→关：`setEnabled(false)` 解绑监听，视图可自由移动，不报错。
- `map.getView().getCenter()` 未就绪：`useExtent` 内已有 `!center` 守卫，沿用。

### 验证方式
- `pnpm lint` 0 报错。
- `pnpm test`（新增/更新 `tests/unit/mapConfig.spec.ts`：默认 `showViewLimit=false`；normalize 兜底；`tests/unit/*` 若有 useExtent 用例补「enabled=false 不绑定」）。
- 手工：config 打开限制视图开关 → 拖动地图到边界外 → 视图被拉回；关开关 → 可自由拖动。

### 风险 / 回滚 / 待确认
- ⚠️ **待确认**：兜底 `viewLimitExtent` 默认 WGS84 具体数值（全国 or 当前城市？）——需产品确认默认限制范围。
- ⚠️ **待确认**：门控开关放「地图参数」组还是单列「视图限制」组（UI 偏好）。

## 二、任务 4 ｜ 路径规划方案排序：tag 命中多者优先

### 目标与范围
- 「点击分析」生成的多方案列表，**命中档位（tag）越多的方案排越前**：3 个 tag（时间最短/距离最短/综合最优，含躲避拥堵=最多 4）> 2 个 > 1 个 > 0 个（备选）。
- 同 tag 数量内**保持原代理顺序**（稳定排序），不引入权重打分（原方案 `routeSortWeights` 过度设计，且用户口径明确为「tag 命中数优先」）。
- 排序后重编 `index`（展示序号 方案1/2/3）与 `id`，使 `showRouteOptions(prepared, 0)` 默认高亮「tag 最多的方案」。
- **不做**：不改 `routeAlternatives.ts`（那是调派/立案链路，口径不同）；不改 `resolveOptionTiers`/`resolveBalancedIndex` 的判定逻辑（tag 判定保持不变，只改展示顺序）。

### 分层落点
| 改动 | 落层 | 理由 |
|---|---|---|
| `buildRoutePlanOptions` 末尾加稳定排序 + 重编 index/id | `baseComponent/tools/routePlanOptions.ts`（纯函数工具层） | 多方案视图模型的唯一构建点，纯函数、零 store 依赖、可单测 |

### 涉及文件清单
1. `src/baseComponent/tools/routePlanOptions.ts` — `buildRoutePlanOptions` 里 `return parsed.map(...)` 改为「先构建带 `tierCount` 的数组 → 按 `tierCount` 降序稳定排序 → 重编 `index`/`id`」。
2. `tests/unit/routePlanOptions.spec.ts` — 新增用例：多 tag 方案排在少 tag 前；同 tag 数保持原顺序；空响应仍 `[]`。

### 关键调用链
```
routePlanPanel.vue runAnalysis → buildRoutePlanOptions(response, summarize) → 返回按 tierCount 排序的 RoutePlanOption[]
  → routeOptions.value = prepared; tool.showRouteOptions(prepared, 0)（0 = tag 最多的首选方案）
  → 模板 v-for routeOptions 按新顺序渲染「方案1/2/3」
```
> 排序键：`(b.tiers.length - a.tiers.length)`，用 `Array.prototype.sort`（ES 保证稳定）；`balanced` 已并入 tiers，故「综合最优」也计入命中数。

### 异常与兜底
- 单方案 / 空数组：直接返回，不排序。
- 所有方案 tag 数相同（常见 1 vs 1）：稳定排序 = 原代理顺序，行为与现状一致（不产生回归）。

### 验证方式
- `pnpm lint` 0 报错。
- `pnpm test` 覆盖排序规则；现有 `spec:163`（index 连续 `[0,1,2]`）仍通过（重编后恒为 0..n-1）。
- 手工：分析 3 方案，命中 2 tag 的方案显示为「方案1」并默认上图。

### 风险 / 回滚 / 待确认
- ⚠️ **待确认**：同 tag 数时是否要次级排序（如按时长升序）？默认**仅按 tag 数 + 稳定原序**，如需次级口径请补充。
- 回滚：删排序行即还原；纯展示顺序，无数据契约变更。

## 三、任务 10 ｜ 资源检索输入模糊查询辅助（仅输入触发、失焦隐藏）

### 目标与范围
- 在 `circleQueryPanel.vue` 的资源检索 `input-panel`（`el-input`「输入关键词查询地址 / 消防资源」）加**模糊联想下拉**：
  - **仅当用户输入了内容**时才出现候选；
  - **点击聚焦（无输入）不出现**（对齐 `trigger-on-focus=false`）；
  - **失焦自动隐藏**；
  - 选中候选 → 回填关键词并直接执行查询（`runKeywordSearch`）。
- 用 Element Plus 的 `el-autocomplete`（项目已安装 `element-plus@^2.13.6`，且 `NavPanel.vue` 已用同款组件，风格统一）。
- **不做**：检索历史（用户明确砍掉）；高德地址联想（资源检索聚焦 GIS 资源，地址走既有「地址信息」tab 的查询结果，不混入联想源，避免双源混淆）。

### 组件选型结论（回答用户「是不是可以用 elementPlus」）
**可以，且推荐 `el-autocomplete`**：
- `:trigger-on-focus="false"` → 聚焦不触发；`:fetch-suggestions` 仅在输入变化时调用 → 仅输入触发；组件内建失焦收起 → 满足「失焦隐藏」。
- `NavPanel.vue` 已在用，样式/主题（`--el-*` 变量、夜间适配）零成本复用。
- 备选 `el-select remote`：需手写下拉显隐与键盘态，不如 autocomplete 贴合。

### 分层落点
| 改动 | 落层 | 理由 |
|---|---|---|
| `useSearchActions.ts` 增 `fetchSuggestions(keyword)`（小 count 调 `searchGisResources` + 截断 top-N） | `composables`（API 编排层） | 检索 API 编排放这层（store 不直连 apis 的铁律） |
| `circleQueryPanel.vue` 把 `el-input` 换成 `el-autocomplete`，接 `fetch-suggestions`/`@select` | `views/components`（UI 层） | 面板 UI 唯一改动点 |

### 涉及文件清单
1. `src/composables/useSearchActions.ts` — 新增 `fetchSuggestions(keyword, limit=5)`：`searchGisResources({keyword, maxFeatures}, layerNames, /*pageSize=*/limit, 0)` → 取 `items`（已含 `title/subtitle/layerName`）；空/异常返回 `[]`。
2. `src/components/map/component/circleQueryPanel.vue`：
   - `<el-input>` → `<el-autocomplete>`，`:fetch-suggestions` 接 `fetchSuggestions`，`:trigger-on-focus="false"`，`@select` 回填 `queryText` + 调 `onQuery`；
   - 保留既有「查询」按钮 + `view-dropdown`（视图下拉）不变，两者共存（autocomplete 管关键词联想，视图下拉管按图层精确查）；
   - 新增联想项渲染 `value = title（subtitle/图层名）`。

### 关键调用链
```
用户输入 → el-autocomplete.fetch-suggestions(q) → useSearchActions.fetchSuggestions
  → searchGisResources(keyword, 各图层 name LIKE) → items[] → 下拉展示
点击候选 @select → queryText = 候选.title → onQuery() → runKeywordSearch
失焦 → el-autocomplete 内建收起
```

### 异常与兜底
- 输入 < 1 字 / 纯空格：`fetchSuggestions` 直接 `cb([])`（不请求）。
- 建议加 **300ms debounce**（在 `useSearchActions.fetchSuggestions` 内或 autocomplete 的 `debounce` 属性，默认 300，符合原方案）。
- WFS 全部图层失败：`items=[]`，下拉不显示，不阻塞主查询。
- 坐标文本（用户直接输 `经度,纬度`）：`onQuery` 既有 `parseCoordinateText` 分支保留，autocomplete 选中不干预。

### 验证方式
- `pnpm lint` 0 报错。
- 手工：聚焦空输入无下拉；输入「消」出现资源候选；失焦收起；点候选直接出查询结果。

### 风险 / 回滚 / 待确认
- ⚠️ **待确认**：联想数据源是否也并入高德地址（双源）？默认**仅 GIS 资源**，避免与「地址信息」tab 重复。
- ⚠️ **待确认**：联想 top-N 取 5（原方案）是否合适。
- 回滚：autocomplete 还原 el-input；删 fetchSuggestions；纯 UI + 1 个 composable 方法，无契约变更。
