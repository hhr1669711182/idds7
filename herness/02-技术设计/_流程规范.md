# 技术设计（研发）流程

> 研发的完整工作流：**只读调查 → 输出方案 → 用户确认 → 编码 → 类型自检 → 文档同步 → MR**。

---

## 一、流程概览

```
接到需求
  │
  ├─→ 0. 【硬门禁】读 05-共享上下文/设计规范速查.md
  ├─→ 1. 只读调查 + 输出技术方案（禁止改实现文件）
  ├─→ 2. 【强制停止点】等待用户明确确认
  ├─→ 3. Coding        → 仅按已确认方案、按分层铁律落点
  ├─→ 4. 类型自检       → pnpm lint
  ├─→ 5. 方案同步      → 实现偏差回写方案 + 契约文档
  └─→ 6. MR            → 06-PR审查/_流程规范.md
```

---

## 二、规则 0（硬门禁）：编码前必读

> **开始任何编码前必须读 `05-共享上下文/设计规范速查.md`。**
> 该文件包含分层铁律、禁改文件、编码与协议约定。不读 = 违规。

---

## 三、规则 1：设计先行——编码前必须有已确认的技术方案

技术方案可在对话中输出，也可按 [前端/技术方案模板.md](前端/技术方案模板.md) 落盘。**无论哪种形式，都必须先输出并获得用户明确确认，才能进入编码。**

技术方案必须包含（可简版，但不可缺项）：

- **目标与范围**：要做什么、明确不做什么，避免范围蔓延
- **改动落点**：每个改动落在 `store / controller / plugin / view / service / const` 哪一层及理由
- **涉及文件清单**：新增 + 修改，标注修改点
- **关键流程**：主要调用链 / 消息流（跨系统消息须标出事件键）
- **契约影响**：是否改事件键 / DTO / 接口；若是，同步 `docs/source/07-协议事件清单.md` 与 `协议层DTO Schema.tsd`
- **异常与兜底**：异常路径、降级方案
- **验证方式**：类型门禁、手工路径、消息模拟方式
- **风险与待确认项**：影响范围、回滚方式、尚不明确的业务决策

### 强制停止点

方案输出后必须停止并询问用户是否确认。**用户确认前禁止：**

- 修改 `src/**`、`tests/**`、`package.json`、`vite.config.ts`、`tsconfig.json`、`scripts/**`、`server/**` 等实现或工程文件
- 新建实现代码、临时脚本、示例代码或测试文件

允许继续只读调查、补充方案和风险分析。

### 确认判定

- 同一方案上下文中，用户明确表达「确认 / 按方案实现 / 可以 / 开始 / 落地」即可进入编码。
- 单独的「继续」不视为确认；只有用户明确要求「跳过方案直接实现」时才可豁免。

### 方案变更必须重新确认

已确认后，若分层落点、文件范围、对外契约、数据结构、安全策略、风险等级或回滚方式发生实质变化，必须先说明变化并再次获得用户确认。纯实现细节的等价调整无需重新确认。

---

## 四、规则 2：编码后必须通过类型门禁

```bash
pnpm lint    # vue-tsc --noEmit
```

`tsconfig.json` 开启 `strict` + `noUnusedLocals` + `noUnusedParameters`，**类型错误与未用变量会直接报错**，必须清零或说明既有报错。

> ⚠️ **判定标准是「无新增」，不是「零报错」**。当前基线约 **193 个既有报错**（绝大多数 `TS6133` 未用变量）。请在改动前后各跑一次并对比，只对自己引入的新错误负责。

---

## 五、规则 3：方案与代码必须一致

实现过程中发现方案有偏差：

- 偏差小 → 直接回写方案
- 偏差大（改了分层、加了事件键、改了接口）→ **先更新方案与契约文档，再改代码**
- 禁止"方案写一套、代码做一套"

---

## 六、技术方案文档结构

见 [前端/技术方案模板.md](前端/技术方案模板.md)。核心章节：

1. 文档信息
2. 方案概述（背景 / 目标 / 范围）
3. 分层落点（每处改动落在哪层）
4. 涉及文件清单
5. 关键流程（调用链 / 消息流）
6. 接口与契约影响
7. 异常与兜底
8. 验证方式（如何证明可用）
9. 依赖与风险

## 七、研发门禁检查清单

### 编码前
- [ ] 已读 `05-共享上下文/设计规范速查.md`
- [ ] 已完成只读调查，确认不是凭想象设计
- [ ] 技术方案已产出（目标范围、分层落点、文件清单、关键流程、契约影响、异常兜底、验证方式、风险）
- [ ] 用户已明确确认方案；确认前未修改任何实现文件
- [ ] 涉及消息/接口时，契约同步路径已明确

### 编码后
- [ ] `pnpm lint` **无新增**报错（基线约 193 个既有问题，见 `05-共享上下文/当前状态摘要.md`）
- [ ] 无越层（对照分层铁律逐条确认）
- [ ] 订阅消息处已在卸载时取消订阅
- [ ] 协议/接口变更已同步 `docs/source/**`
- [ ] 方案已回写，与代码一致
- [ ] MR 描述含变更概述、关联方案、关联迭代，并追加 AI 审查请求

### 迭代结束
- [ ] 方案与测试文档已归档到 `02-技术设计/前端/`
- [ ] `前端/_index.md` 已更新
- [ ] `04-迭代管理/` 已记录产物链接
