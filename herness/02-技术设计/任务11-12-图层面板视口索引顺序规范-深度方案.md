## 〇、现状盘点（代码实测，2026-11-19）

### 1. 图层渲染顺序（WMS/矢量层）
- 统一入口：`src/baseComponent/OpenlayersMap/useGisBaseMap.ts` 的 `addLayer(id)`，`zIndex` 来自 `config.zIndex`（`layers.ts` 的 `LayerConfig.zIndex?`，调用方按 id 决定）。
- 挂载顺序：`map.vue` 按代码书写顺序 `addLayer` / `syncLayers`，**无显式排序**；OL 默认按 `zIndex` 升序绘制，缺省 zIndex 时按添加顺序。
- 特例：`featureRenderOrder.ts`（AddressRobot 要素层）用 `OrderFunction` 做**要素级** renderOrder（面<线<点，点按 role），与图层级 zIndex 是两套机制。
- **结论**：图层顺序目前是「半隐式」——依赖 `layers.ts` 的 zIndex 字段 + 代码挂载顺序，无集中配置、无校验。

### 2. 面板 / 浮层 z-index（DOM 层）
- 散落硬编码，实测：
  - `config.vue`：`.cfg-toggle z-index:1000`、`.cfg-panel z-index:1100`
  - `circleQueryPanel.vue`：`z-index:7`、`z-index:20`
  - `bigPanel.vue`：`z-index:5`
  - 天气面板、地址机器人抽屉、ZoomLevelControl、ThemeSwitch、bottomNav 等各自再写一套（`tokens.less` 有 `--top-actions-*` 簇布局常量，但**没有统一的 z-index token**）
- **结论**：面板层级无单一真源，数值跨度大（5 → 1100），新增面板极易撞层；主题切换依赖各自 CSS 变量，但 z-index 与主题无关却混在各 `.less` 里。

### 3. 视口 overlay 锚点 offset
- `IncidentVideoOverlayController.ts`：`PANEL_HORIZONTAL_OFFSET_PIXELS = 96`、`PANEL_VERTICAL_OFFSET_PIXELS = 170`（硬编码常量）；视频/天气 overlay 的 `offset: [x, y]` 亦为字面量。
- `UnclosedWeatherRingController.ts`：`offset: [0,4]`、`[16,-8]` 等。
- **结论**：overlay 偏移全是裸像素，分辨率/DPI 变化时无适配，与「稳定堆叠体验」目标冲突。

## 一、设计目标与原则

1. **三层分离**：把「图层渲染顺序」「面板 DOM 层级」「视口 overlay 锚点」当作**三个独立的堆叠维度**，各自有自己的配置来源与 token，不混用。
2. **单一真源**：每个维度只有一个配置源；组件/控制器只消费，不各自发明数值。
3. **主题无关**：z-index / offset 是几何与层级常量，**与日夜主题无关**（类比 `featureRenderOrder` 的 role 色——层级不该随主题漂移）。
4. **可覆盖、有兜底**：默认值 = 现状硬编码（零行为变更）；允许 env / 配置覆盖；未配置走兜底。
5. **可校验**：落地后能机检「是否所有面板 z-index 都走了 token」，杜绝新增裸值。

## 二、三层索引模型（规范性定义）

### 维度 A：图层渲染顺序（OL 矢量/WMS 层）
- 真源：`src/config/layers.ts` 的 `LayerConfig.zIndex`（已存在）+ 新增 `LayerOrderConfig`（显式挂载顺序表）。
- 规则：
  - **zIndex 区间分段**（预留，避免撞车）：
    | 段 | 范围 | 用途 |
    |---|---|---|
    | 底图 | 0–9 | 栅格底图 |
    | 业务面 | 10–39 | 围栏/区划面/专题面 |
    | 业务线 | 40–69 | 轨迹/路线 |
    | 业务点 | 70–129 | 资源点/车辆/警情 |
    | 高亮/选中 | 130–199 | 圈选范围圈、选中描边、临时标注 |
    | 临时交互 | 200+ | 绘制中、拖拽中 |
  - 同段内**显式排序**：`map.vue` 挂载时按 `LayerOrderConfig` 升序（而非代码书写顺序），保证可复现。
  - 要素级 `renderOrder`（AddressRobot 等）继续走 `featureRenderOrder.ts`，**不参与**本段管理（维度内两套机制，互不干扰）。

### 维度 B：面板 / 浮层 z-index（DOM）
- 真源：`src/styles/tokens.less` 新增一组 `--z-*` token（与主题无关，放 tokens 层而非 palettes 层）。
- 规则（**基线层级表**，从低到高）：
  | token | 值 | 用途 |
  |---|---|---|
  | `--z-map` | 0 | 地图画布 |
  | `--z-map-controls` | 100 | OL 原生控件（比例尺/鹰眼/指北针） |
  | `--z-toolbar` | 500 | 底部工具栏 / 图层工具栏 |
  | `--z-panel` | 900 | 普通业务面板（天气/检索/圈选结果/路径规划） |
  | `--z-panel-sub` | 950 | 面板内浮层（tab 下拉、加载更多遮罩） |
  | `--z-panel-modal` | 1000 | 配置面板、调色盘等大面板 |
  | `--z-overlay-tip` | 1050 | 视口 overlay 内的提示/详情卡 |
  | `--z-tooltip` | 1100 | 全局 tooltip / ElMessage |
  | `--z-drawer` | 1200 | 地址机器人抽屉等侧栏 |
- **铁律**：任何 `.less/.vue` 的面板级 `z-index` 只允许写 `var(--z-*)`，禁止裸数字（机检项，对齐 `代码样式规范.md` 的「只写 var(--token)」思路）。
- 映射现状：`config.vue` 1000→`--z-panel-modal`、1100→`--z-tooltip`；`circleQueryPanel` 7/20→`--z-panel`/`--z-panel-sub`；`bigPanel` 5→`--z-panel`（统一抬到 900 基线，行为等价、消除 5/7/20 的小数值）。

### 维度 C：视口 overlay 锚点 offset
- 真源：`src/styles/tokens.less` 新增 `--overlay-offset-*`（px），控制器读 CSS 变量而非裸常量。
- 规则：
  | token | 默认 | 用途 |
  |---|---|---|
  | `--overlay-offset-x` | 96px | 视频/详情 overlay 水平偏移 |
  | `--overlay-offset-y` | 170px | 垂直偏移 |
  | `--overlay-offset-compact-x` | 18px | 紧凑 overlay（如天气环） |
  | `--overlay-offset-compact-y` | 8px | 紧凑垂直 |
- **分辨率适配**：偏移改为 `calc()` 表达（如 `--overlay-offset-x: calc(var(--space-md) * 6)`），随 `--space-*` 基线缩放；控制器里 `getComputedStyle` 读 px 后取整传入 OL `offset`。

## 四、落地步骤（对应原任务 11 梳理 + 任务 12 落地）

1. **梳理（不写码，产表）**：全量盘点 `map.vue` `addLayer`/`mountXxxLayer` 顺序 + 各 `config.zIndex`，输出「图层 → 当前 zIndex → 归属段 → 依赖」渲染顺序表；盘点全部面板 z-index 与 overlay offset，输出层级表（本文件 §〇 已起头，落地时补全到 100% 覆盖）。
2. **token 化**：`tokens.less` 加 `--z-*` / `--overlay-offset-*`；各 `.less`/控制器把裸值换成 `var(--z-*)`。
3. **控制器读变量**：`IncidentVideoOverlayController.ts` / `UnclosedWeatherRingController.ts` 的 offset 常量改为读 `--overlay-offset-*`。
4. **图层顺序配置化**：`layers.ts` 加 `LayerOrderConfig`，`map.vue` 挂载改按配置排序（默认 = 现状，零变更）。
5. **机检**：`scripts/check-code-convention.mjs` 增加「面板 z-index 必须是 `var(--z-*)`」检测（或 `check-css-vars.mjs` 扩项），并入 `pnpm harness:check`。

**默认行为不变**：所有默认值 = 现硬编码，env/config 未配时零行为变更。

## 五、风险 / 回滚 / 待确认

- ⚠️ **待确认**：`--z-*` 基线表的具体数值（尤其 900/1000 段）是否贴合现有视觉层叠？建议先出一版 token，跑一次主题切换 e2e（任务 13）验证无跳变再定稿。
- ⚠️ **待确认**：overlay offset 是否要做**响应式**（小屏缩小偏移）？默认按 calc 基线缩放，不做断点切换（避免过度设计）。
- ⚠️ **待确认**：图层顺序是否要**用户可配并持久化**（进 config），还是仅**开发者可配**（env 覆盖）？默认按「开发者可配、用户不可配」（顺序误配易出严重叠层问题，不宜暴露给用户）。
- 风险：z-index 全量迁移若遗漏某面板裸值 → 该面板层级回退；机检项兜底。
- 回滚：B/C 维度只改样式 token 与控制器读法，`tokens.less` 加回默认值即还原；A 维度 `LayerOrderConfig` 默认序 = 现状，删配置行即还原。
