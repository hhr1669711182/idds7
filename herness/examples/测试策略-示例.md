# ids-gis-web 测试策略

> 示例文档。演示项目级测试策略应包含哪些内容。

## 一、现状

本项目**无自动化测试框架**，测试以「类型门禁 + 手工用例 + 契约核对」为主。`tests/*.test.ts` 为遗留脚本。

## 二、测试层次

| 层次 | 手段 | 门禁 |
|------|------|------|
| 类型 | `pnpm lint`（vue-tsc strict） | 无**新增**报错（基线约 193 个既有问题） |
| 契约 | 事件键 / DTO / 接口 与 `docs/source/**` 比对 | 不一致即阻断 |
| 分层 | 对照设计规范速查逐条确认 | 越层即阻断 |
| 功能 | 手工用例（含异常路径） | 关键路径全通 |
| 回归 | 改动公共层后的受影响路径 | 无退化 |

## 三、优先级

| 优先级 | 对象 | 原因 |
|--------|------|------|
| P0 | `const.message.type.ts`、`controller/**`、`interceptor/**` | 影响跨系统通信与全部业务 |
| P1 | `service/**`、`store/**` | 影响数据与状态 |
| P2 | `views/**`、`components/**` | 影响交互 |

## 四、覆盖率目标（引入自动化后）

| 对象 | 目标 |
|------|------|
| 纯逻辑模块（coordTransform / mapConfig / unwrap / matcher / error） | ≥ 80% |
| 控制器 | ≥ 60% |
| 组件 | 关键路径覆盖 |
