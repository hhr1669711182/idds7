# Agent 入口说明（多工具兼容）

> 本仓库为多种 AI agent 工具准备了自动加载的入口文件，使 `herness/` 工作台在会话启动时即被感知。
> **主规范文件是 `AGENTS.md`，其余入口均为其同步副本或引用。**

---

## 入口文件一览

| 工具 | 入口文件 | 加载方式 |
|------|---------|---------|
| **Codex / OpenAI Codex CLI** | `AGENTS.md` | 自动注入（根目录） |
| **Claude Code** | `CLAUDE.md` | 自动加载，`@AGENTS.md` 导入 |
| **Cursor** | `.cursor/rules/herness.mdc` | `alwaysApply: true` |
| **Windsurf** | `.windsurfrules` | 自动加载 |
| **GitHub Copilot** | `.github/copilot-instructions.md` | 自动加载 |
| **Gemini CLI** | `.gemini/GEMINI.md` | 自动加载 |
| **Trae** | `.trae/rules/project_rules.md` | 自动加载 |
| **Grok CLI / Grok Build** | `AGENTS.md` | 原生支持 `AGENTS.md`，根目录自动加载（需目录信任） |
| **Hermes / 其他** | `AGENTS.md` | 按 AGENTS.md 约定 |

---

## 维护规则（重要）

1. **改动规范只改 `AGENTS.md`**。其余入口是它的同步副本。
2. 同步副本改了之后，用下方清单逐一核对，避免遗漏：
   - `CLAUDE.md`（**特殊：不写正文**，见下方「Grok 的特殊处理」）
   - `.cursor/rules/herness.mdc`
   - `.windsurfrules`
   - `.github/copilot-instructions.md`
   - `.gemini/GEMINI.md`
   - `.trae/rules/project_rules.md`
3. **入口文件只放"路由 + 红线"，不放细节**。细节一律放 `herness/**`，靠文档引用按需加载，避免上下文膨胀。
4. 若新增支持某个工具，在此表登记其入口文件路径与加载方式.

---

## 为什么需要多个入口文件

不同 agent 工具约定俗成的规则文件名各不相同（`AGENTS.md`、`CLAUDE.md`、`.windsurfrules`、`.cursorrules` 等），没有任何一个通用文件名能被所有工具自动识别。因此本目录为每个主流工具各放一份，**共享同一份规范内容**，保证无论用哪个工具接手，都能自动读到 `herness/` 工作台的路由与红线。

> 注：目录名从 `hernes` 统一改为 `herness`（与来源模板 `herness-template` 对齐），命名本身不影响任何工具的自动加载。

## Grok 的特殊处理（已处理）

Grok CLI 原生支持 `AGENTS.md`，无需额外入口。但有两个特性需要注意：

### 1. 支持的文件名（Grok 官方）

`Agents.md`、`Claude.md`、`CLAUDE.md`、`CLAUDE.local.md`、`AGENT.md`、`AGENTS.md`

**同一目录下的每个匹配文件都会被加载**。因此本仓库的 `AGENTS.md` 与 `CLAUDE.md` 会被 Grok 同时加载。

### 2. 处理方式

`CLAUDE.md` **不复制任何规范正文**，只保留：
- 一段注释，说明规范唯一来源是 `AGENTS.md`
- 一行 `@AGENTS.md`（Claude Code 的导入语法，Grok 视为普通文本）

这样既保证 Claude Code 正常导入规范，又让 Grok 加载 `CLAUDE.md` 时几乎不消耗上下文、不产生重复注入。

> 注意：Grok **不支持** `@` 导入语法（那是 Claude Code 专属功能），因此不能靠 `@AGENTS.md` 消除重复加载，只能靠"不写正文"。

### 3. 启动加载需要目录信任

Grok 首次打开仓库需要授权信任该文件夹（`--trust` 或交互式授权），之后才会自动加载规则。可用 `grok inspect` 确认已加载哪些规则文件及其 token 量。

### 4. 可选增强：目录级规则

Grok 支持 `AGENTS.md` 按目录树逐层叠加，越深的优先级越高。如需对特定目录加强约束，可放置：

```
src/controller/AGENTS.md   # 改控制器时强调"通用层零业务"
```

> 其他工具不一定支持目录级叠加，按需使用。
