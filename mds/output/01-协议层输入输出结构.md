## 一、协议层架构总览

协议层是整个 GIS 系统的通信总线与接口契约，位于主前端业务系统与 GIS 核心之间，实现彻底的解耦。

```
主前端业务系统 ──(标准指令)──→ MessageStore(gisBridge) ──(路由分发)──→ Controller 层
                                                                    │
                              ◄─────────────────────────────────────┤
                          上行领域事件 (domain events)
```

### 1.1 核心职责

| 职责 | 说明 |
|------|------|
| 通信中枢 | `MessageStore` 统一事件总线（Event Bus），封装 WebSocket + postMessage 双通道 |
| 契约定义 | 统一下发指令（Command）与上行领域事件（Domain Event）的 TypeScript 类型 |
| 数据适配 | 主前端业务模型（如 `AlarmAggregate`）向 GIS 渲染所需数据格式的映射转换 |
| 归一处理 | 兼容旧格式 `{ type: "dispatchUpdate", payload: {} }` 自动归一为 `{ eventKey, data }` |

### 1.2 消息信封标准

所有消息均封装为标准信封结构：

```typescript
interface MessageEnvelope<T = any> {
  /** 消息唯一标识，用于追踪、应答、排错 */
  id: string;
  /** 消息时间戳（毫秒） */
  ts: number;
  /** 来源系统：host | map | dispatch | panel_25d | panel_3d */
  system: MessageSystem;
  /** 事件键（固定值，决定消息语义） */
  eventKey: string;
  /** 业务数据（根据 eventKey 不同，类型不同） */
  data: T;
  /** 目标系统（留空表示广播给所有订阅者） */
  targetSystem?: MessageSystem;
  /** 附加元数据（链路追踪、用户标识等） */
  meta?: Record<string, any>;
  /** 消息协议版本，当前固定为 '1.0.0' */
  v?: '1.0.0';
  /** 通道类型：ws | postMessage */
  channel?: MessageChannel;
  /** 是否移除相同元素，默认 false */
  isRemoveSameElement?: boolean;
}
```

### 1.3 系统标识枚举

```typescript
const MESSAGE_SYSTEM = {
  HOST: 'host',           // 宿主系统（上游/父窗口）
  MAP: 'map',             // 地图主应用
  DISPATCH: 'dispatch',   // 调度/告警/推送等业务系统
  PANEL_25D: 'panel_25d', // 2.5D iframe 面板系统
  PANEL_3D: 'panel_3d',   // 3D iframe 面板系统
} as const;
```

### 1.4 通道标识枚举

```typescript
const MESSAGE_CHANNEL = {
  WS: 'ws',                   // WebSocket 通道
  POST_MESSAGE: 'postMessage', // postMessage 通道
} as const;
```

## 二、输入协议（外部 → 地图）

### 2.1 通用控制协议（map.base.*）

通用控制层暴露一组无状态的、高内聚的基础接口，供业务层随时拼装调用。

#### 2.1.1 视图控制

| 协议 | 接口名 | 输入结构 | 说明 |
|------|--------|---------|------|
| 视口平移缩放 | `map.base.locate` | `{ lngLat: [number, number], zoom?: number, duration?: number }` | 中心点+缩放级别，可选动画时长 |
| 图层显隐 | `map.base.layer_toggle` | `{ layerId: string, visible: boolean }` | 控制单个图层可见性 |
| 面边界定位 | `map.base.fit_bounds` | `{ geometry: GeoJSON.Polygon, padding?: number[], duration?: number }` | 自适应视口，padding=[top,right,bottom,left] |
| POI 定位 | `map.base.poiLocation` | `{ longitude: number, latitude: number, zoom?: number }` | 结合空间检索的定位 |
| 2.5D 白膜渲染 | `map.base.3d_overlay` | `{ center: [number, number], highlightFloor: number, totalFloors: number }` | 建筑白模楼层高亮 |

#### 2.1.2 几何标绘

| 协议 | 接口名 | 输入结构 | 说明 |
|------|--------|---------|------|
| 单点标绘 | `map.base.marker_add` | `{ id: string, lngLat: [number, number], iconType?: string, animate?: 'breathe'\|'pulse'\|'none', vehicleType?: string, isMainStation?: boolean }` | 点标记，支持多种图标和动画 |
| 多边形面高亮 | `map.base.polygon_draw` | `{ id: string, geometry: GeoJSON.Polygon, style?: 'primary'\|'secondary', fillColor?: string, strokeColor?: string }` | 面要素绘制，支持主次样式 |
| 要素批量移除 | `map.base.feature_remove` | `{ featureIds: string[], layerIds?: string[] }` | 按 ID 批量移除，可选按图层 |

#### 2.1.3 空间分析

| 协议 | 接口名 | 输入结构 | 说明 |
|------|--------|---------|------|
| 空间检索 | `map.base.es_query` | `{ geometry: { type: 'Circle'\|'Polygon', center?: [number, number], radius?: number, coordinates?: number[][][] }, types: string[], limit: number }` | 多边形/圆形范围内检索资源 |
| 缓冲计算 | `map.base.buffer_calc` | `{ input: { center: [number, number], radius: number }, output: 'Polygon Geometry' }` | 生成缓冲区多边形 |
| 路径规划 | `map.base.route_calc` | `{ start: [number, number], end: [number, number], strategy?: 'fastest'\|'shortest' }` | 两点间路径计算 |

#### 2.1.4 轨迹动画

| 协议 | 接口名 | 输入结构 | 说明 |
|------|--------|---------|------|
| 平滑移动 | `map.base.smooth_move` | `{ featureId: string, targetLngLat: [number, number], duration: number }` | 车辆平滑移动，建议 500-1000ms |
| 轨迹追加 | `map.base.track_append` | `{ lineId: string, newLngLat: [number, number] }` | 在轨迹线上追加新点 |
| 轨迹回放 | `map.base.track_play` | `{ points: [number, number][], playSpeed: number }` | 历史轨迹播放 |

### 4.2 WebSocket 连接模型

```
前端建立单连接，通过频道订阅实现多路复用：

前端 → 后端:
{
  subscribe: {
    channels: [
      "vehicle.position",
      "vehicle.status_changed",
      "traffic.updated",
      "incident.*"
    ]
  }
}

后端 → 前端 (按订阅推送):
{ type: "vehicle.position", data: { vehicleId, lat, lng, heading, speed } }
```

## 五、消息信封完整定义

### 5.1 通用消息信封

```typescript
interface MessageEnvelope<T = any> {
  /** 消息唯一标识 */
  id: string;
  /** 消息事件键 */
  eventKey: MessageEventKey;
  /** 消息业务序列号（可选，用于消息关联） */
  sn?: string;
  /** 消息体（根据 eventKey 不同，类型不同） */
  body: any;
  /** 消息扩展信息 */
  extension?: Record<string, any>;
  /** 消息时间戳（毫秒） */
  timestamp: number;
}
```

### 5.2 消息事件键枚举

```typescript
type MessageEventKey =
  // 系统级
  | 'system:health'
  | 'system:heartbeat'
  | 'system:auth'
  | 'system:auth-result'
  | 'system:error'
  | 'system:push-switch'
  | 'system:config-update'
```
