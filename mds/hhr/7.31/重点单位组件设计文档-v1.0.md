## 一、组件定位

### 1.1 基础定位

- **模块**：GIS地图模块 → 独立业务组件
- **图层**：重点单位图层（点图层）
- **使用场景**：S1 值守、S3 接警问询、S4 图上调派、S5 跟踪到场
- **核心能力**：空间筛选（CIRCLE / AOI / VIEWPORT / BATCH）、模糊检索（拼音 / 英文）、多语言、按场景差异化渲染、写入审计、离线降级
- **字段合法性**：`key_unit_type` 必须在字典内；`status` 必须在合法枚举内；`incident_engagement` 状态变化必须由受控事件触发

### 1.2 协作服务

| 服务 | 职责 |
|------|------|
| `NearestResourceService` | 最近资源查询（跨组件） |
| `AddressResolutionService` | 警情地址 → `unit_id` / `aoi_id` 解析 |
| `AuditService` | 审计日志写入（由本组件调用） |
| `ConfigService` | 运行时可调参数管理 |
| `I18nService` | 多语言资源加载 |

### 1.3 "不负责"清单

- ❌ 不负责主数据维护（新增/修改/删除 → 走主数据管理子系统）
- ❌ 不负责建筑外框渲染 → 建筑组件
- ❌ 不负责消防栓搜索 → 消防栓组件
- ❌ 不负责路径规划 / 调度决策 → 调度引擎
- ❌ 不负责最终业务确认 → 消防监督机构业务
- ❌ 不负责微围栏管理 → 接警问询模块与 GIS 围栏服务
- ❌ 不负责审计日志的查询 / 报表 → 审计服务（组件只负责写入）

### 1.4 与其他组件的职责边界

| 组件 | 职责 | 与本组件的关系 |
|------|------|--------------|
| **重点单位（KeyUnit）** | 重点单位的点资源展示与查询 | — |
| **建筑组件** | 建筑外框 / 3D 楼栋 | 共享战场地图 |
| **消防栓组件** | 消防栓资源查询与渲染 | 共享事件总线；接口形态一致 |
| **微围栏服务** | 微围栏生命周期管理 | 本组件通过 `aoi_id` 反查 `geom` |
| **地址解析服务** | 警情地址 → `unit_id` / `aoi_id` | 本组件订阅 `IncidentAddressMatched` |
| **系统配置服务** | 运行时可调参数 | 本组件订阅 `ConfigChanged` |
| **审计服务** | 审计日志查询 / 报表 | 本组件只写入 |
| **I18n 服务** | 多语言资源管理 | 客户端通过 i18n_key 拉取翻译 |

## 三、外部控制接口

### 3.1 查询接口

四种空间选择方式 + 批量查询：

- **CIRCLE**：中心点 + 半径（半径由 `sys_config` 配置）
- **AOI**：微围栏 ID
- **VIEWPORT**：视口范围
- **BATCH**：按 ID 集合（最多 1000 个）

### 3.2 错误码

| 错误码 | 含义 |
|--------|------|
| 0 | 成功 |
| 1001 | PARAM_INVALID |
| 1002 | AOI_NOT_FOUND |
| 1003 | QUERY_TIMEOUT |
| 1004 | DATA_SOURCE_ERROR |
| 1005 | PERMISSION_DENIED |
| 1006 | PAGE_SIZE_OVERFLOW |
| 1007 | RADIUS_OVERFLOW |
| 1008 | FUZZY_QUERY_NOT_ALLOWED |
| 1009 | OFFLINE_MODE_FALLBACK |

### 3.3 内部仓储方法

供领域服务调用，不走 HTTP：

- **空间查询**：`findNearest` / `findByAoi` / `findByViewport` / `findByIds`
- **单点查询**：`findById` / `findByCreditCode`
- **模糊检索**：`fuzzySearch`（`pinyin` / `en` / `exact`）
- **状态变更**：`markIncidentEngagement00To01` / `01To02` / `resetExpiredEngagement`（仅响应受控事件）
- **审计**：`writeAuditLog` / `findAuditByUnitId` / `findAuditByTraceId`（仅审计服务调用）

## 五、用户故事场景集成

> 重点单位组件在 S1 值守、S3 接警问询、S4 图上调派、S5 跟踪到场 四个场景使用。

### 5.1 US-S1-01（值守阶段）

**触发**：S1 值守模式启动，两种：
1. ① 以接警员身份登录上线初始化页面
2. ② 由其他模式（来电弹屏 / 接警问询 / 调派 / 到场）返回值守模式

**动作**：监听地图缩放变化；缩放 ≥ 18 级时，调用视口查询；提供拼音/英文检索框（仅 S1 启用）；返回数据，前端渲染重点单位图标（按类型差异化着色）。

### 5.2 US-S3-01（接警问询阶段）

**触发**：警情接入，S3 阶段微围栏已确认。

**动作**：接警问询模块发出 `MicroFenceConfirmed` 事件（含 `aoi_id`）；组件响应事件，反查围栏 `geom`；地图自动缩放至 17 级；组件调用 AOI 查询（`selection_mode = AOI`）；返回数据，前端渲染。

### 5.3 US-S4-01（图上调派）

**触发**：警情已确认，进入 S4 调派阶段。

**动作**：组件接收 `ModeChanged → S4`；复用 `currentAoiId`，反查围栏 `geom`；组件调用 AOI 查询；自动过滤 `status = 01` + `incident_engagement ∈ {00, 02}`；CIRCLE 兜底：若 `aoi_id` 为空降级为 `selection_mode = CIRCLE`，半径取 `sys_config.key_unit.circle_radius_default_meters`；退出 S4 时清空画布。

### 5.4 US-S5-01（跟踪到场）

**触发**：救援到达现场，警情地址匹配到某重点单位。

**动作**：组件接收 `ModeChanged → S5`；复用 `currentAoiId`，反查围栏 `geom`；组件调用 AOI 查询；接收 `IncidentTargetMatched` 事件（含 `unit_id` + `incident_id`），组件调用 `KeyUnitRepository.markIncidentEngagement00To01()` 标记状态；该单位被标记为"现场目标"，视觉按 4.3 规则；救援撤离时接收 `IncidentTargetCleared` 事件，组件调用 `markIncidentEngagement01To02()` 重置状态；30 分钟后定时任务自动重置回 00。

## 六、事件订阅

### 6.1 外部事件

| 事件名 | 来源 | 触发时机 | 组件动作 |
|--------|------|---------|---------|
| `ModeChanged` | 工作台 / 问询模块 | 场景切换 | 清空画布 |
| `ZoomChanged` | 地图组件 | S1 缩放 | 视口查询 |
| `MicroFenceConfirmed` | 接警问询模块 | S3 微围栏生成 | 写入 `currentAoiId` |
| `IncidentAddressMatched` | 地址解析模块 | S5 地址匹配 | 触发 `IncidentTargetMatched` |
| `IncidentTargetMatched` | 调度模块 | S5 救援到场 | 标记 `incident_engagement` 00→01 |
| `IncidentTargetCleared` | 调度模块 | S5 救援离场 | 标记 `incident_engagement` 01→02 |
| `InquiryExited` | 接警问询模块 | 警情归档 | 清空状态 |
| `ConfigChanged` | 系统配置服务 | sys_config 变更 | 重新加载配置 |
| `DictionaryUpdated` | 数据管理子系统 | 字典表更新 | 失效字典缓存 |
| `AuditRecorded` | 审计服务 | 审计记录写入 | 旁路通知 |

### 6.2 内部状态生命周期

**`currentAoiId`**：`S3 MicroFenceConfirmed → 写入`；S4/S5 继承；`S1 保留`；`InquiryExited → 清空`。跨警情清理：每次 `InquiryExited` 强制清空。

**`incident_engagement`**：`IncidentTargetMatched → 00→01`；`IncidentTargetCleared → 01→02`；定时任务 30 分钟后 `02→00`。

## 九、非功能性要求

### 9.1 性能

| 指标 | 目标 |
|------|------|
| 单查询响应时间（P95） | < 500ms（含缓存命中） |
| 单查询响应时间（P99） | < 1s |
| 模糊检索响应时间（P95） | < 800ms |
| 并发查询能力 | ≥ 50 QPS |
| 数据量级 | ≤ 50,000 |

### 9.2 索引

- `key_unit.geom` GIST（必需）
- `key_unit.name_pinyin` / `name_en` GIN pg_trgm（必需）
- `key_unit.status` / `incident_engagement` / `key_unit_type` / `admin_region` B-tree（必需）
- `key_unit_audit` 4 个 B-tree 索引（必需）

### 9.3 分页与配置

| 参数 | 默认 | 最大 | 配置项 |
|------|------|------|--------|
| `page` | 1 | — | — |
| `page_size` | 100 | 1000 | `sys_config.key_unit.query_max_page_size` |
| `radius`（CIRCLE） | 1500 | 10000 | `sys_config.key_unit.circle_radius_max_meters` |

### 9.4 空结果

`code = 0`、`data.key_units = []`、`data.total = 0`。

### 9.5 坐标系

WGS84 强制；非 WGS84 须调用前转换。

### 9.6 审计

- 所有 API 调用记录日志
- `incident_engagement` 状态变更 + 主数据写入全部入 `key_unit_audit`
- 审计保留期 ≥ 5 年（公安部 61 号令）
- 审计写入走异步队列（不阻塞主请求）

### 9.7 缓存策略

两级缓存：L1 进程内（Caffeine，TTL 60s，容量 10000）+ L2 Redis（按对象 TTL）。

TTL：字典 / 配置 3600s / 300s（事件驱动失效）；视口查询 30s；AOI 查询 60s；微围栏 geom 300s。

一致性：字典 / 配置事件驱动失效（强一致）；视口查询 TTL 30s（最终一致）；写操作（INSERT / UPDATE / DELETE / `incident_engagement` 变更）失效受影响 `unit_id` 的所有缓存。

### 9.8 离线 / 弱网降级

触发：心跳 5s 超时 → 离线模式；抖动 3s+ → 网络不稳定提示。

离线行为：读操作走 L1/L2 缓存（L2 不可达返回错误码 `1009`）；写操作禁止（状态变更必须在线）；模糊检索禁用；右下角标识"🔌 离线模式"。

前端：Service Worker 缓存字典 + 最近 1000 条重点单位；IndexedDB 持久化（50MB 上限）；重新连接自动同步。

状态机：`ONLINE →(5s)→ DEGRADED →(10s)→ OFFLINE`（reconnect 回 ONLINE）。

### 9.9 多语言

支持：`zh-CN`（默认）/ `en-US` / `zh-TW`（待扩展）。

策略：API 返回 `type_name` + `type_name_en` + `i18n_key`；客户端按 `Accept-Language` 或用户手动切换。解析规则：i18n_key 翻译优先 → 回退 type_name_en → 默认 type_name。服务端不感知语言。

### 9.10 写入审计

范围：INSERT / UPDATE / DELETE 重点单位、`incident_engagement` 状态变更、status 变更（写操作全覆盖，读操作无审计）。

内容：who（operator_id / name）、when（operation_time）、why（reason）、before/after（jsonb）、changed_fields、trace_id、incident_id。

策略：异步队列（容量 10000），主请求完成后非阻塞写入；队列满 → 同步写入；失败 → 重试 3 次 → 失败入 `key_unit_audit_failed` 表。保留期 ≥ 5 年（公安部 61 号令）。

查询接口（仅审计服务调用）：`findAuditByUnitId` / `findAuditByTraceId`。
