# GIS 前端总体架构纲要设计 (核心总结)

**版本**：v1.0  
**定位**：面向技术总监、架构师及业务开发团队的高层设计蓝图，阐述系统演进方向、核心设计理念及业务价值。

---

## 一、 架构演进背景与核心挑战

在消防接处警等复杂业务场景下，GIS 前端不仅是“一张地图”，而是承载态势感知、指挥调派与实时追踪的“核心作战沙盘”。
当前系统面临三大挑战：
1. **多端孤岛化**：座席端、大屏端、调度端及移动端存在大量的地图初始化与工具逻辑重复，无法有效沉淀为资产。
2. **逻辑强耦合**：主前端业务逻辑与底层地图 API 深度绑定，导致引擎替换困难（如从商用引擎切换至信创引擎）。
3. **计算渲染瓶颈**：高频 GPS 轨迹、海量警情渲染以及空间相交计算，容易阻塞主线程，影响交互体验。

---

## 二、 核心设计理念

为了彻底解决上述痛点，本次架构重构遵循以下三大核心设计理念：

### 1. 面向 Monorepo 的积木式复用 (Componentization)
将大而全的 GIS 模块拆解为细粒度的功能包。从底层的引擎挂载，到上层的业务组件，均可像乐高积木一样按需引入，实现代码在不同平台（PC、大屏、App）的 100% 级复用。

### 2. 协议驱动与领域解耦 (Protocol-Driven & DDD)
坚持“业务真相在主前端，GIS 只做投影”的原则。主前端通过下发标准指令（Command）驱动地图，地图交互通过上报领域事件（Event）反馈主前端。双方通过一套标准化的“数据协议层”进行对话，实现系统级的彻底解耦。

### 3. 计算与渲染分离 (Compute & Render Separation)
引入独立的“（业务）计算层”和“取数层”，将高频的数据清洗、坐标转换及复杂的空间拓扑计算剥离至 Web Worker 中执行，确保渲染主线程的极致流畅。

---

## 三、 五大核心分类模型 (5-Pillars Model)

整个 GIS 生态被横向切分为五大核心域，对应 Monorepo 中的独立 Packages：

| 分类域 | 定位与核心能力 | 业务价值 |
| :--- | :--- | :--- |
| **基础类 (@gis/basic)** | **底座支撑**：封装 OpenLayers/ThreeJS 引擎适配，提供原生的渲染环境。 | 屏蔽底层引擎差异，支持未来信创无缝替换。 |
| **资源类 (@gis/resource)** | **数据管家**：管理多平台底图切换、GeoServer 图层及高德等第三方服务。 | 集中管理外部依赖，实现数据源的统一配置。 |
| **配置类 (@gis/config)** | **视觉中枢**：统管主题样式、默认缩放、场景图层策略及 UI 面板布局。 | 确保多端视觉与操作习惯的高度一致。 |
| **工具类 (@gis/tools)** | **操作面板**：独立可插拔的绘图、测量、圈选、缩放等通用控件。 | 提供开箱即用的地图交互能力，随取随用。 |
| **业务类 (@gis/business)** | **作战单元**：值守、来电、调派、跟踪等贴合消防流程的场景级组件。 | 实现业务能力的沉淀，新项目可直接引用整套作战流。 |

---

## 四、 六层逻辑架构 (6-Layers Architecture)

在纵向深度上，系统执行严格的层级调用规范，确保数据流向清晰：

1. **主前端层 (Main Frontend)**：维护 Pinia / Vuex 业务状态，下发操作指令。
2. **取数层 (Data Fetching)**：GIS 自主的数据泵，负责从后端或第三方拉取并清洗数据（演进方向）。
3. **数据协议层 (Protocol)**：统一定义 Command 与 Event，作为隔离业务与地图的网关。
4. **控制层 (Control)**：指挥中枢，管理场景状态机，编排具体的渲染与计算任务。
5. **计算层 (Compute)**：执行空间拓扑分析、ETA 推算及高频数据抽稀，脱离主线程运行。
6. **渲染与交互层 (Render & Interact)**：执行纯粹的几何图元绘制，并捕获原生交互事件。

---

## 五、 核心收益与业务愿景

1. **研发效能倍增**：新增接处警客户端或大屏项目时，无需从零开发地图模块，只需通过 `@gis/business` 引入对应场景包即可，开发周期缩短 60%。
2. **极致性能体验**：通过“计算与渲染分离”及高频数据的节流抽稀，保证在千级车辆并发跟踪场景下的平滑渲染（≥60fps）。
3. **技术资产沉淀**：剥离出的 `@gis/config` 和 `@gis/tools` 成为公司级的 GIS 技术底座资产，可跨行业、跨产品线平滑移植。
4. **国产化无忧**：底层适配器模式确保了在面对政府/公安系统对信创环境（如超图、天地图）的强要求时，能够实现“零业务代码修改”的底层切换。
