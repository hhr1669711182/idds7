### 一、GIS 端整体架构（适配多独立前端项目模式）
你们当前架构下，GIS 侧采用 **「统一 GIS 共享 npm 包 + 各项目私有 GIS 应用组件」** 的两级结构：
- 共享层：通用 GIS 能力封装为私有 npm 包（`@fire/gis-components`），所有前端项目构建时引入，能力复用、规范统一；
- 项目层：每个前端项目内部维护专属的 GIS 业务视图组件，耦合各自业务流程，独立实例化地图，运行时无耦合、无冲突，稳定性最高。

---

### 二、跨项目共享 GIS 组件包（`@fire/gis-components`）
所有前端项目通用，纯 GIS 能力沉淀，不耦合具体业务页面流程。内部再分两层，严格单向依赖。

#### 1. GIS 基础组件层（纯能力原子，无消防业务语义）
定位：封装底层地图引擎差异，提供标准化 GIS 原子能力，可复用到任何 GIS 项目。

| 组件名 | 核心职责 | 关键能力 |
|--------|----------|----------|
| GisMap | 核心地图容器 | 统一初始化 API，封装高德/超图/天地图/ArcGIS 引擎差异；内置缩放、鹰眼、比例尺等基础控件；暴露地图实例操作方法 |
| MapMarker | 通用地图标记 | 自定义图标、弹窗、点击事件；支持状态样式切换；统一坐标格式 |
| LayerManager | 图层统一管理器 | 图层显隐、层级控制、懒加载/卸载；支持热力图、围栏、瓦片、预案等多类型图层 |
| Geocoder | 地址解析器 | 正向/逆向地理编码统一封装；对接后端 GIS 服务，返回多候选结果 + 置信度 |
| RoutePlanner | 路径规划器 | 路线绘制 + ETA 预计时长；支持消防车限高/限宽/禁行约束；多路线对比 |
| SpatialQuery | 空间查询组件 | 周边查询、缓冲区分析、辖区内筛选；统一对接后端空间计算服务 |
| GeofenceDetector | 地理围栏检测器 | 自定义多边形/圆形围栏；进出围栏自动触发事件；支持批量围栏检测 |
| RealTimeTracker | 实时位置跟踪引擎 | 封装 WebSocket 订阅、断线重连、心跳；内置平滑移动动画（requestAnimationFrame） |
| InfoPopup | 地图通用信息弹窗 | 位置自动跟随、内容插槽、统一视觉样式；支持多实例管理 |
| MapToolbar | 通用地图工具栏 | 缩放、测距、全屏、清图、图层切换等通用操作按钮 |

#### 2. GIS 业务基础组件层（消防领域通用，跨项目复用）
定位：带有消防业务语义的 GIS 组合件，至少被 2 个及以上前端项目使用，统一业务视觉和交互规范。

| 组件名 | 核心职责 | 复用场景 |
|--------|----------|----------|
| VehicleMarker | 车辆专用标记 | 方向箭头、速度显示、状态色（待命/在途/到场）、轨迹尾迹；调度端、值守端、移动端通用 |
| IncidentMarker | 警情专用标记 | 紧急等级闪烁、灾害类型图标、警情编号标签；接警端、调度端、值守端通用 |
| ResourceMarker | 资源分类标记 | 消火栓、微站、重点单位、水源等分类图标与样式；全项目资源展示统一 |
| JurisdictionLayer | 辖区围栏图层 | 统一辖区边界样式、高亮交互、点击事件；值守、调度、接警全场景复用 |
| ResourceListMapPanel | 地图-列表联动面板 | 左侧资源列表 + 右侧地图标记双向联动高亮；调度、值守、移动端复用 |

### 四、多项目架构下 GIS 侧核心设计要点
1. **地图实例完全独立**
    共享包只提供组件类和能力方法，不持有全局单例；每个前端项目自行初始化自己的地图实例，项目间彻底隔离，不存在微前端的实例冲突、样式污染问题，排障简单、稳定性高。

2. **引擎差异统一收敛**
    所有地图引擎（商用/国产化）的适配工作只在共享包内完成，业务项目完全不感知底层引擎；后续信创替换地图引擎时，只需升级共享包版本，所有业务项目无需修改代码。

3. **后端 GIS 服务统一对接**
    地址解析、空间查询、路径规划等后端 GIS 微服务的接口调用，全部封装在共享包内部；各业务项目不用重复对接接口，后端接口变更时也只需要修改一处。

4. **性能优化统一落地**
    标记聚合、视口裁剪、帧节流、图层懒加载等通用性能优化，内置在共享包基础层；所有项目引入后自动生效，不用每个项目重复开发优化逻辑。

5. **版本语义化治理**
    GIS 共享包独立发版，遵循语义化版本规则；各业务项目按需锁定版本，升级不强制联动，既保证能力复用，又不影响各项目的独立迭代节奏。
