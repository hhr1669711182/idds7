# **场景2：来电弹屏**

## **用户故事**

作为一个 消防接处警中心的接警员

**我希望** 在值守阶段，\(文字\)主屏有来电弹屏时，地图GIS屏上按**已获取的基站定位为中心**，绘制半径500m的圈进行展示，并合理占用屏幕空间

**我希望** 在值守阶段，\(文字\)主屏有来电弹屏时，地图GIS屏上按**三字段固话装机位置定位为中心**，绘制半径500m的圈进行展示，并合理占用屏幕空间

**我希望** 直接在半径500m的圈里清晰展示定位类型：基站粗定位

以便于 我在接听电话的第一时间快速、直观地看到报警人大致位置范围和信息来源，减少视线移动和判断负担，提升接警效率和准确性。

## 状态来源

前端主页面同步状态过来or报警接入模块\-\>分机子状态\-\>振铃中

## 用例

1. 主屏弹出手机来电时，GIS屏自动以基站定位为中心绘制500米半径圈，并自动调整地图缩放层级以完整居中展示该范围。

2. 主屏弹出固话来电时，GIS屏自动以三字段装机地址为中心绘制500米半径圈，并自动调整地图缩放层级以完整居中展示该范围。

3. 在地图绘制的基站定位500米圈内，需直接且醒目地悬浮显示“基站粗定位”文本标识。

4. 在地图绘制的固话定位500米圈内，需直接且醒目地悬浮显示“固话装机定位”文本标识。

5. 地图定位圈及文本标识展示时，需确保信息层级分明且不遮挡地图关键路网或建筑信息，实现免拖拽即刻阅览。

# **场景4：图上调派阶段**

## **用户故事**

**作为一个** 消防接处警中心调度员

**我希望** 问询确定警情类型和救援对象（建筑or构建）后，图上完整展示主管队站围栏及最近三个队站围栏，颜色区分突出主管队站及车辆，将4个围栏完整显示，适当留边
**我希望** 展示灾害建筑所在微围栏（AOI3）及出入口、围栏内的消防栓
**我希望** 各个队站可用车辆上图展示车辆类型及ETA，突出主管队站车辆
**我希望** 加载预案调派车辆，突出颜色（研判/预案推荐的车辆）
**我希望** 本辖区不具备预案中的特殊车辆加载在角落画中画（后续再做）
**我希望** 能突出主路及相应支路路网
**我希望** 可以在图上，点击车辆调派和取消调派
**我希望** 可以在图上按一键调派按钮，下发选中车辆的调派单到相应队站

**以便于** 我摆脱传统繁琐的列表勾选，实现全局一眼盘清首战与后续增援力量的网格边界，更直观地“所见即所调”，快速做出调派决策，并优先确保主管队站的主力输出。

## 状态来源

前端主页面同步状态过来or接警问询模块->问询状态->问询已创建

## 用例

**一、模式进入与初始化**

**1、**问询确认警情地址/类型后启动图上调派，进入调派阶段，地图默认以警情定位为中心，缩放至18级。

**二、定位与边界展示（空间上下文）**

**2、**展示主管队站管辖围栏，采用高对比度的核心醒目色（如强对比色彩）。

**3、**展示最近3个支撑队站管辖围栏，采用次级弱对比色彩。

**三、资源展示**

**4、**展示灾害建筑所在微围栏（AOI3）及出入口、内部/周边可用消防栓。

**5、**展示各个队站可用车辆，严格区分车型（城市主战车、高喷车、泡沫车等），常态化悬浮展示动态预计到达时间（ETA），并在视觉尺寸或基础色调上显著异于支撑队站的车辆。

**6、**展示预案推荐的车辆编队（自动运行匹配预案后），采用特定的高亮霓虹色（如橙色/橙红色外环或光晕）包裹突出（待触发状态）。

**7、**展示核心主干道及相应支路路网，色彩需能体现当前实时路况（如红/黄/绿），与背景普通路网拉开明显的视觉层级。

**四、视图交互与配置（通用地图控制）**

**8、**地图自动执行 Fit Bounds 算法，动态计算4个围栏的几何中心及最大边界，确保所有围栏100%完整可视，地图边缘保留10%~15%的视距留边（Padding）避免视觉压迫。

**9、**点击图上任意可用车辆（或预案推荐车），该车即刻进入“选中/调派”状态（图标呈现虚线框变实线、打勾或色彩增强等视觉反馈）；再次点击平滑取消调派状态。

**10、**点击地图交互区“一键调派”主按钮，系统立即将当前地图上所有处于“选中”状态的车辆打包组合，并发异步下发调派单至相应中队完成指令闭环。


# **场景5：跟踪到场阶段**

## **用户故事**

**作为一个** 消防接处警中心调度员

**我希望** 在车辆出动后能全程实时跟踪其轨迹与ETA
**我希望** 在首车到场时地图能自动聚焦切入现场微观视图，展示微围栏、集结点、消防栓、出入口

**以便于** 我的工作重心能从“宏观途中调度”无缝平滑过渡到“现场战术支撑”。

## 状态来源

前端主页面同步状态过来or调派跟踪模块->车辆状态->车辆已出动/首车已到场

## 用例

**一、模式进入与初始化**

**1、**点击一键调派下发指令后，车辆出动，触发进入跟踪到场阶段。

**二、动态跟踪与状态展示（实时动态）**

**2、**车辆出动后，利用北斗/GPS实时数据，图上消防车图标实现平滑平移轨迹跟踪（非跳跃式闪烁），位置更新频率不低于2秒/次。

**3、**沿途计算的动态预计到达时间（ETA）随实时路况和距离缩短同步实时刷新。

**三、视图交互与配置（通用地图控制）**

**4、**接收到首辆消防车“已到场”状态（基于GPS地理围栏触发或车载终端反馈）时，地图自动执行Zoom-in，视角瞬间聚焦到灾害点的微围栏（AOI3）区域。

**四、元素可见性管理（通用控制）**

**5、**切换为微观作战视图后，自动净化/隐藏无关的远端中队围栏和未到场远端车辆。

**五、建筑与微围栏展示（细粒度图层）**

**6、**重点突出展示微围栏边界、集结点（现场指挥部/停放点预设位置）、消防栓位置以及进出通道，全面支撑到场后的协同指挥。

# 数据分类（紧急事件类 \+ 资源类）—— 完整版

**紧急事件类（警情事件 / Event Point Layer）静态组成（几乎不动）**：警情类型、报警时间、主管队站、基础AOI/POI。
**动态状态**：定位演进、问询记录、**警情地址描述、地址**（问询精确定位/修正）、警情状态高亮、微围栏切换。
**动频细分**：

- **几乎不动**：类型、时间、主管队站、基础AOI/POI（场景1加载，后续复用）。

- **偶尔动**：**警情地址描述、地址**（问询修正）、初/精定位、问询记录、相似警情高亮（场景2\-4）。

- **经常动**：当前状态高亮、微围栏切换、到场聚焦（场景3、5）。

**资源类 \& 救援对象类（Resource \+ Rescue Object Layer \+ 2\.5D建筑）静态组成（几乎不动）**：路网骨架、队站/辖区围栏基础、建筑白膜、2\.5D建筑、重点单位位置、消防栓/出入口基础。
**动态状态**：实时路况、车辆状态/轨迹/ETA、围栏高亮、预案推荐、微观要素显示、视图切换。
**动频细分**：

- **几乎不动**：路网骨架、队站围栏基础、建筑白膜、重点单位/消防栓位置（场景1加载）。

- **偶尔动**：围栏/高亮切换、车辆待命/预案推荐、微观要素控制（场景3\-4）。

- **经常动**：车辆轨迹平滑移动、动态ETA实时刷新、路况颜色、交互状态反馈、到场微观重塑（场景4\-5）。

# 业务状态机 \+ 图动逻辑（每步详细解释）

**业务状态流**：值守模式 → 来电接入 → 问询研判 → 调派决策 → 跟踪/到场作战。

上方状态机图已完整呈现。**动画逻辑**：每个箭头为一个关键帧，只刷新对应颜色组件（蓝常驻缓存、橙阶段事件驱动、红实时订阅）。地址更新主要在场景2→3的橙色“偶尔动”环节。

**每步详细解释**：

- **值守 → 来电**（偶尔动）：全城15级 → 粗定位18级 \+ 500m圈 \+ 定位类型 \+ **初始地址描述**。解释：快速看到报警人范围（对应故事2）。

- **来电 → 问询**（偶尔动，重点地址更新）：中心切换 \+ 高亮本/相似警情 \+ 管辖圈（颜色区分） \+ **地址描述精确定位/修正** \+ 建筑维度控制。解释：提前预判力量 \+ 聚焦灾情（对应故事3）。

- **问询 → 调派**（偶尔动）：围栏颜色区分 \+ 待命车辆/预案高亮 \+ 路网突出 \+ **已确认地址微围栏** \+ 出入口/消防栓 \+ ETA \+ 交互。解释：全局力量盘点 \+ 一键调派（对应故事4 \+ AC1\-4）。

- **调派 → 跟踪**（经常动）：选中状态反馈 \+ **平滑轨迹移动** \+ **动态ETA实时刷新**。解释：实时途中监控（对应故事4后半 \+ AC5）。

- **跟踪 → 到场**（经常动→偶尔动）：首车到场触发 **Zoom\-in微观视图** \+ 突出微围栏/集结点/消防栓/出入口 \+ 隐藏远端。解释：平滑切换到现场战术支撑（对应故事5）。
