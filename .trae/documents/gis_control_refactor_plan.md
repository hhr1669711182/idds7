# GIS 控制架构重构计划

## 1. 现状分析 (Current State Analysis)
当前已有的 `GIS控制.md` 与 `控制接口映射表.md` 是按照“业务阶段”（如初始化、值守、来电、接警、研判、调度、执行）来归纳总计 31 项 GIS 控制。
虽然具备了基本的分类和 JSON Schema 定义，但距离清晰的骨架模式还有差距：
- **分类维度**：尚未以“控制类型”（内部、外部、输出）作为主轴。
- **业务连贯性**：缺乏“控制 --> 用户故事 --> 应用场景 --> 业务阶段流程”这一标准的推导描述骨架。
- **配置与能力缺失**：内部配置开关不够详细，外部控制缺少对 POI、AOI 集合定位以及接警缩圈高亮等关键动作的具体定义。
- **映射关系单薄**：目前仅有简单的接口映射，缺乏控制与控制之间、控制与业务模块之间的关系映射矩阵。

## 2. 拟定变更 (Proposed Changes)
**目标文件**：覆写/更新 `d:\work\telewave\ids\ids-gis-web\mds\external\GIS控制.md`（将映射表精髓合并，形成一份终极版架构文档）。

**详细执行步骤**：

### 2.1 搭建 GIS 基本骨架模式
- 阐述重构后的架构理念，明确以“控制”为原子单元的驱动模式。
- 定义标准模板，后续所有控制均遵循：**[控制ID/名称] -> 用户故事 (User Story) -> 应用场景 (Scenario) -> 所属业务阶段 (Stage)**。

### 2.2 梳理并重组三大控制分类
将所有控制打散，重新按以下三大类组织：
1. **内部控制（包含配置开关与自发联动）**
   - **配置开关**：详细补充资源配置（基础图层）、工具栏配置、地图基础参数配置、搜索栏配置、地图控件显隐、地图清除（动态对象）状态配置、业务面板配置。
   - **内部联动**：如围栏自动缩圈、轨迹自动追加、状态自动流转等。
2. **外部控制（外源系统/用户驱动）**
   - 纳入现有的定位、上图、路线规划、调派等控制。
   - **重点补充**：
     - 基础 POI 定位（支持类型过滤、图标显隐）。
     - 围栏集合 AOI 定位。
     - 接警阶段：缩圈高亮资源控制（基于多边形围栏集合触发 ES 搜索并高亮）。
3. **输出控制（地图操作输出指令/数据）**
   - 包含地图视图变化、坐标拾取、车辆拾取、路线规划结果输出等。

### 2.3 补充图表与关系映射
- **图表 (Mermaid)**：
  - 绘制全新的 **全局业务流转流程图**（区分内外控制的边界）。
  - 绘制典型场景的 **时序图**（如接警缩圈联动时序、调派执行时序）。
- **关系映射矩阵**：
  - 建立【阶段 ↔ 控制】映射表。
  - 建立【外部控制 ↔ 触发 ↔ 内部/输出控制】的依赖连带关系。

## 3. 假设与决策 (Assumptions & Decisions)
- **合并文档决策**：为保证阅读和研发一致性，计划将原先分散的《控制接口映射表》的核心接口 Schema 和映射逻辑，直接内聚到《GIS控制.md》的对应控制说明下或作为附录。
- **语义统一**：所有的“外部控制”均对应系统接收到的 `eventKey`（如 websocket/eventbus 下发），所有的“输出控制”均对应地图抛出的事件。

- 确认所有的 Mermaid 流程图和时序图在标准 Markdown 解析器下渲染无误。
- 确认每一个核心控制都具有明确的用户故事和应用场景。
